### 함수란

- 일련의 과정을 문으로 구현하고 코드 블록으로 감싸서 하나의 실행 단위로 정의한 것이다.
- 함수 내부로 입력을 전달받는 변수를 매개변수, 입력을 인수, 출력을 반환값이라 한다.
- 함수는 함수 정의를 통해 생성하고, 함수 호출을 통해 실행한다.
  - 정의만으로는 실행되지 않으며 호출해야 실행된다.

### 함수를 사용하는 이유

- 코드의 재사용 : 같은 코드를 중복해서 작성하지 않고 필요할 때 여러 번 호출할 수 있다.
- 유지보수의 편의성과 코드의 신뢰성 : 중복을 억제하므로 수정할 곳이 한 군데로 줄어든다.
- 코드의 가독성 향상 : 함수 이름이 코드의 역할을 설명하므로 코드를 이해하기 쉬워진다.
  - 따라서 함수 이름은 함수의 역할을 명확히 표현해야 한다.

### 함수 리터럴

- 함수는 객체 타입의 값이므로 함수 리터럴로 생성할 수 있다.
  - function 키워드, 함수 이름, 매개변수 목록, 함수 몸체로 구성된다.
  - ```javascript
    var f = function add(x, y) {
      return x + y;
    };
    ```
- 함수 이름은 생략할 수 있다.
  - 이름이 있는 함수는 기명 함수, 없는 함수는 무명/익명 함수라 한다.
  - 함수 이름은 함수 몸체 내부에서만 참조할 수 있는 식별자다.
- 함수는 객체이지만 일반 객체와 달리 **호출할 수 있다**.
  - 또 일반 객체에는 없는 함수 고유의 프로퍼티를 갖는다.
- 함수가 객체 타입의 값이기에 리터럴로 생성할 수 있고, 값처럼 변수에 담거나 전달하고 반환할 수도 있다.
  - 이러한 성질을 갖는 객체를 일급 객체라 한다. (18장)
  - 즉 일급 객체여서 리터럴로 생성할 수 있는 것이 아니라, 객체 타입의 값이기에 일급 객체인 것이다.

### 함수 정의 방식

- 함수 선언문
  - ```javascript
    function add(x, y) {
      return x + y;
    }
    ```
- 함수 표현식
  - ```javascript
    var add = function (x, y) {
      return x + y;
    };
    ```
- Function 생성자 함수
  - ```javascript
    var add = new Function("x", "y", "return x + y");
    ```
  - 클로저를 생성하지 않는 등 다른 방식과 동작이 다르므로 권장하지 않는다.
- 화살표 함수(ES6)
  - ```javascript
    var add = (x, y) => x + y;
    ```
  - this, arguments, super, new.target 바인딩을 갖지 않으며 prototype 프로퍼티도 없다.

#### 함수 선언문

- 함수 선언문은 함수 리터럴과 형태가 동일하지만 함수 이름을 생략할 수 없다.
- 함수 선언문은 표현식이 아닌 문이다.
  - 따라서 변수에 할당할 수 없고, 값으로 평가될 수 없다.
  - 단 `var f = function add() {}` 처럼 할당되는 자리에 오면 함수 표현식으로 해석된다.
  - 즉 자바스크립트 엔진이 코드의 문맥에 따라 다르게 해석한다.
- 함수 선언문으로 정의한 함수는 함수 이름과 동일한 이름의 식별자를 암묵적으로 생성한다.
  - 함수 이름은 함수 몸체 내부에서만 유효하므로, 엔진이 함수 이름과 같은 식별자를 만들어 함수 객체를 할당한다.
  - 따라서 함수 이름으로 호출하는 것이 아니라 **엔진이 만든 식별자로 호출**하는 것이다.
  - 선언문은 식별자와 함수 이름의 철자가 같기에 이 구분이 드러나지 않는다.
- 함수 표현식에서 함수 이름과 식별자를 다르게 주면 둘이 구분되어 보인다.
  - ```javascript
    var sub = function minus(x, y) {
      return x - y;
    };

    sub(5, 2); // 3 (식별자로 호출)
    minus(5, 2); // ReferenceError (함수 이름으로는 외부에서 호출할 수 없다)
    ```

  - 함수 이름은 몸체 내부에서만 유효하므로 재귀 호출에 사용할 수 있다.
    - ```javascript
      var fact = function f(n) {
        return n <= 1 ? 1 : n * f(n - 1); // 내부에서는 f로 자신을 참조
      };

      fact(5); // 120
      ```

#### 함수 표현식

- 함수는 일급 객체이므로 값처럼 변수에 할당할 수 있다.
  - 이러한 정의 방식을 함수 표현식이라 한다.
- 함수 표현식의 함수 리터럴은 함수 이름을 생략하는 것이 일반적이다.
- 함수 선언문과 함수 표현식은 함수 생성 시점이 다르다.

### 함수 생성 시점과 함수 호이스팅

- 함수 선언문으로 정의한 함수는 선언문 이전에 호출할 수 있다.
  - 반면 함수 표현식으로 정의한 함수는 할당문 이전에 호출할 수 없다.
  - ```javascript
    console.log(add(2, 5)); // 7
    console.log(sub(2, 5)); // TypeError: sub is not a function

    function add(x, y) {
      return x + y;
    } // 함수 선언문

    var sub = function (x, y) {
      return x - y;
    }; // 함수 표현식
    ```

- 함수 선언문은 런타임 이전에 함수 객체가 먼저 생성된다.
  - 엔진이 함수 이름과 동일한 식별자를 암묵적으로 생성하고 함수 객체를 할당한다.
  - 이를 함수 호이스팅이라 한다.
- 함수 표현식은 변수 할당문의 값이 런타임에 평가되어 함수 객체가 된다.
  - 변수 호이스팅에 의해 undefined로 초기화되어 있으므로 `TypeError`가 발생한다.
- 즉 변수 호이스팅과 함수 호이스팅은 다르다.
  - 변수 호이스팅 : undefined로 초기화된다.
  - 함수 호이스팅 : 함수 객체로 초기화된다.
- 함수 호이스팅은 함수를 호출하기 전에 반드시 선언해야 한다는 규칙을 무시하므로
  - 함수 표현식을 사용할 것을 권장한다.

### 함수 호출

#### 매개변수와 인수

- 매개변수는 함수 몸체 내부에서만 참조할 수 있다.
  - 즉 매개변수의 스코프는 함수 내부다.
- 함수는 매개변수의 개수와 인수의 개수가 일치하는지 체크하지 않는다.
  - 인수가 부족하면 매개변수는 undefined가 된다.
  - 인수가 더 많으면 초과된 인수는 무시된다. 단 암묵적으로 arguments 객체에 보관된다.
  - ```javascript
    function add(x, y) {
      return x + y;
    }

    add(2); // NaN (y가 undefined이므로 2 + undefined)
    add(2, 5, 10); // 7 (10은 무시된다)
    ```

- 매개변수는 최대 3개 이상을 넘지 않는 것을 권장한다.
  - 그 이상이 필요하면 객체를 인수로 전달하는 것이 유리하다.
  - 단 객체를 전달하면 함수 내부에서 객체를 변경할 경우 매개변수에 주소가 복사돼서 같은 객체를 가리키게 되기 때문에 외부에 영향을 준다.

#### 인수 확인

- 자바스크립트는 동적 타입 언어이므로 매개변수의 타입을 사전에 지정할 수 없다.
  - 따라서 적절한 인수가 전달되었는지 함수 내부에서 확인할 필요가 있다.
  - ```javascript
    function add(x, y) {
      if (typeof x !== "number" || typeof y !== "number") {
        throw new TypeError("인수는 모두 숫자 값이어야 합니다.");
      }
      return x + y;
    }
    ```
- 인수가 전달되지 않은 경우 단축 평가나 기본값을 사용할 수 있다.
  - ```javascript
    function add(a = 0, b = 0) {
      return a + b;
    } // ES6 매개변수 기본값
    ```
  - 기본값은 인수를 전달하지 않은 경우와 undefined를 전달한 경우에만 유효하다.
- 이러한 타입 체크를 언어 차원에서 해결한 것이 타입스크립트다.
  - 매개변수에 타입을 선언하면 컴파일 시점에 타입을 검사한다.
  - ```typescript
    function add(x: number, y: number) {
      return x + y;
    }

    add("1", 2); // 컴파일 에러 (실행 전에 잡힌다)
    ```

  - 즉 런타임에 typeof로 확인하던 것을 컴파일 타임으로 옮긴 것이다.
  - 단 컴파일 후에는 타입 정보가 사라지므로, 외부에서 들어오는 값은 여전히 런타임 검증이 필요하다.
    - API 응답, 사용자 입력 등은 타입스크립트가 보장해주지 못한다.

#### 반환문

- 함수 호출은 표현식이며, 반환값으로 평가된다.
- return 키워드는 함수 실행을 중단하고 함수 몸체를 빠져나간다.
  - return 이후의 문은 실행되지 않는다.
- 반환문은 생략할 수 있으며, 이때 암묵적으로 undefined를 반환한다.
- 반환문은 함수 몸체 내부에서만 사용할 수 있다.
- return 키워드와 반환값 사이에 줄바꿈이 있으면 세미콜론 자동 삽입에 의해 undefined가 반환된다.

### 참조에 의한 전달과 외부 상태의 변경

- 원시 값은 값에 의한 전달, 객체는 참조에 의한 전달 방식으로 매개변수에 전달된다.
  - 따라서 함수 내부에서 객체를 변경하면 외부의 객체도 변경된다.
  - ```javascript
    function changeVal(primitive, obj) {
      primitive += 100;
      obj.name = "Kim";
    }

    var num = 100;
    var person = { name: "Lee" };

    changeVal(num, person);

    console.log(num); // 100 (원시 값은 변경되지 않는다)
    console.log(person); // { name: 'Kim' } (객체는 변경된다)
    ```

- 이러한 부수 효과(side effect)는 복잡한 코드에서 추적을 어렵게 만든다.
- 해결 방법은 객체를 불변 객체로 만들어 사용하는 것이다.
  - 객체의 복사본을 만들어 원본을 유지하는 방어적 복사를 수행한다.
  - 또는 Object.freeze를 사용해 객체를 동결한다.

<details>
<summary>as const 와 Object.freeze 의 차이</summary>

|                 | 막는 시점 | 프로퍼티 변경      |
| --------------- | --------- | ------------------ |
| `as const`      | 컴파일    | 막음 (타입 검사만) |
| `Object.freeze` | 런타임    | 막음               |

- `as const`는 타입스크립트의 타입 검사에서만 막는다.
  - 컴파일하면 타입 정보가 사라지므로 런타임에는 변경이 통과된다.
  - 따라서 `any`로 단언하거나 외부 함수에 전달되면 보호되지 않는다.
  - 불변성보다는 리터럴 타입을 좁히는 용도로 사용한다.
    - ```typescript
      const dirs = ["up", "down"] as const; // readonly ['up', 'down']
      type Dir = (typeof dirs)[number]; // 'up' | 'down'
      ```
- `Object.freeze`는 객체 자체를 동결하므로 런타임에도 변경을 막는다.
  - 단 한 단계만 동결하는 얕은 동결이므로 중첩 객체는 변경할 수 있다.
  - 완전한 불변 객체로 만들려면 재귀적으로 동결해야 한다.
- 즉 부수 효과를 막으려면 런타임 보호가 필요하므로 `Object.freeze`를 사용해야 한다.

- 외부 상태를 변경하지 않고 외부 상태에 의존하지도 않는 함수를 순수 함수라 한다.
- 순수 함수를 통해 부수 효과를 최대한 억제하는 것이 함수형 프로그래밍이다.

### 다양한 함수의 형태

#### 즉시 실행 함수

- 함수 정의와 동시에 즉시 호출되는 함수로 단 한 번만 호출되며 다시 호출할 수 없다.
  - 반드시 그룹 연산자로 감싸야 한다.
  - ```javascript
    (function () {
      var a = 3;
      return a;
    })();
    ```
- 그룹 연산자로 감싸는 이유는 함수 선언문으로 해석되지 않게 하기 위함이다.
  - 선언문은 값으로 평가되지 않으므로 호출할 대상이 없어 호출 연산자를 붙일 수 없다.
  - 그룹 연산자로 감싸면 함수 리터럴이 함수 객체로 평가되므로 호출할 수 있다.
  - ```javascript
    (function () {
      return 3;
    })();
    // └──── 평가 결과: 함수 객체 ────┘└┘ 호출
    ```

- 변수나 함수 이름의 충돌을 방지할 수 있다.

#### 재귀 함수

- 함수가 자기 자신을 호출하는 것을 재귀 호출이라 한다.
  - 반복되는 처리를 반복문 없이 구현할 수 있다.
  - ```javascript
    function factorial(n) {
      if (n <= 1) return 1; // 탈출 조건
      return n * factorial(n - 1);
    }
    ```
- 반드시 탈출 조건을 만들어야 한다.
  - 없으면 함수가 무한 호출되어 스택 오버플로가 발생한다.
- 대부분의 재귀 함수는 반복문으로 구현할 수 있으며, 재귀가 더 직관적인 경우에만 사용한다.

#### 중첩 함수

- 함수 내부에 정의된 함수를 중첩 함수 또는 내부 함수라 한다.
  - 중첩 함수를 포함하는 함수는 외부 함수라 한다.
- 중첩 함수는 외부 함수 내부에서만 호출할 수 있다.
  - 일반적으로 자신을 포함하는 외부 함수를 돕는 헬퍼 함수의 역할을 한다.

#### 콜백 함수와 고차 함수

- 함수의 매개변수를 통해 다른 함수의 내부로 전달되는 함수를 콜백 함수라 한다.
  - 매개변수를 통해 함수를 전달받은 함수를 고차 함수라 한다.
- 고차 함수는 콜백 함수를 자신의 일부분으로 합성한다.
  - 콜백 함수를 전달받은 고차 함수는 필요에 따라 콜백 함수를 호출할 수 있다.
  - ```javascript
    function repeat(n, f) {
      for (var i = 0; i < n; i++) f(i); // f는 콜백 함수
    }

    repeat(3, function (i) {
      console.log(i);
    }); // 0 1 2
    ```

- 콜백 함수는 함수형 프로그래밍 패러다임과 비동기 처리에 활용되는 중요한 패턴이다.
- 콜백 함수로 전달된 함수 리터럴은 고차 함수가 호출될 때마다 평가되어 함수 객체를 생성한다.
  - 따라서 콜백 함수를 전달하기 전에 다른 변수에 할당한 뒤 전달하면 함수 객체 생성을 줄일 수 있다.
  - ```javascript
    // 리터럴이 매 순회마다 평가되어 함수 객체가 100개 생성된다.
    for (var i = 0; i < 100; i++) {
      repeat(5, function (i) {
        console.log(i);
      });
    }

    // 리터럴 평가는 한 번뿐이고 이후에는 주소만 전달된다.
    var logAll = function (i) {
      console.log(i);
    };

    for (var i = 0; i < 100; i++) {
      repeat(5, logAll);
    }
    ```

  - 전달할 때는 주소만 복사되므로, 문제는 전달이 아니라 리터럴의 **평가 시점**이다.
    - 함수 리터럴은 평가될 때마다 새로운 함수 객체를 생성한다.
    - 즉 같은 리터럴을 두 번 평가하면 서로 다른 객체가 된다.

#### 순수 함수와 비순수 함수

- 순수 함수 : 외부 상태에 의존하지 않고 변경하지도 않는 함수
  - 동일한 인수가 전달되면 언제나 동일한 값을 반환한다.
  - 함수의 외부 상태를 변경하지 않으므로 부수 효과가 없다.
- 비순수 함수 : 외부 상태에 의존하거나 외부 상태를 변경하는 함수
  - 외부 상태에 따라 반환값이 달라질 수 있다.
- 함수 외부 상태의 변경을 지양하는 순수 함수를 사용하는 것이 좋다.
