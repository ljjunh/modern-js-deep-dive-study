### 스코프란

- 모든 식별자(변수 이름, 함수 이름, 클래스 이름 등)는 자신이 선언된 위치에 의해 유효 범위가 결정된다.
  - 이 유효 범위를 스코프라 한다.
  - 즉 스코프는 **식별자가 유효한 범위**다.
- 자바스크립트 엔진은 이름이 같은 식별자가 여러 개 있을 때 어느 것을 참조할지 스코프를 통해 결정한다.
  - 이를 식별자 결정(identifier resolution)이라 한다.
- 스코프는 식별자를 검색하는 규칙이라고 할 수도 있다.
- 식별자는 유일해야 하지만 스코프가 다르면 같은 이름의 식별자를 사용할 수 있다.
  - 즉 스코프는 이름의 충돌을 막아주는 **네임스페이스 역할**을 한다.

#### var 키워드의 문제

- var 키워드로 선언된 변수는 같은 스코프 내에서 중복 선언이 허용된다.
  - 의도치 않게 변수 값이 재할당되어 변경되는 부작용이 발생한다.
  - ```javascript
    var x = 1;
    var x = 2; // 에러 없이 재할당된다.
    ```
- let, const 키워드는 중복 선언을 허용하지 않는다.

### 스코프의 종류

- 전역 스코프 : 코드의 가장 바깥 영역으로, 전역 변수는 어디서든 참조할 수 있다.
- 지역 스코프 : 함수 몸체 내부로, 지역 변수는 자신의 지역 스코프와 하위 지역 스코프에서 유효하다.
- 변수는 자신이 선언된 위치에 의해 자신이 유효한 범위인 스코프가 결정된다.

### 스코프 체인

- 함수는 중첩될 수 있으므로 함수의 지역 스코프도 중첩될 수 있다.
  - 즉 스코프가 계층적으로 연결되며, 이를 스코프 체인이라 한다.
- 변수를 참조할 때 엔진은 스코프 체인을 통해 변수를 참조하는 코드의 스코프에서 시작해
  - 상위 스코프 방향으로 이동하며 선언된 변수를 검색한다.
  - 따라서 상위 스코프에서 유효한 변수는 하위 스코프에서 자유롭게 참조할 수 있다.
  - 하지만 하위 스코프에서 유효한 변수를 상위 스코프에서 참조할 수는 없다.
- 스코프 체인은 물리적인 실체로 존재한다.
  - 엔진은 렉시컬 환경(Lexical Environment)을 실제로 생성한다.
    - 환경 레코드(식별자 저장소)와 외부 렉시컬 환경에 대한 참조로 구성된다.
    - 이 외부 참조 포인터들이 연결된 것이 스코프 체인이다.
  - ```javascript
    var x = 1;

    function foo() {
      var y = 2;
      console.log(x);
    }
    ```

    ```mermaid
    flowchart TB
        subgraph FOO["foo의 렉시컬 환경"]
            direction TB
            FOO_REC["환경 레코드<br/>y → 0x02 (값 2)"]
            FOO_OUT["외부 참조 (포인터)"]
        end

        subgraph GLOBAL["전역 렉시컬 환경"]
            direction TB
            G_REC["환경 레코드<br/>x → 0x01 (값 1)<br/>foo → 0x03 (함수 객체)"]
            G_OUT["외부 참조 (포인터)"]
        end

        NULL["null (체인의 끝)"]

        FOO_REC -.->|x 없음, 외부 참조로| FOO_OUT
        FOO_OUT ==>|포인터가 가리킴| GLOBAL
        G_OUT ==> NULL
    ```

- 변수 선언이 실행되면 식별자가 이 자료구조에 키로 등록되고, 변수 할당이 일어나면 값이 할당된다.
  - 즉 키 등록(선언)과 값 할당은 분리되어 있다.

    ```mermaid
    flowchart LR
        subgraph S1["① 평가 단계 : 키 등록"]
            direction TB
            A["환경 레코드<br/>x → undefined"]
        end

        subgraph S2["② 실행 단계 : 값 할당"]
            direction TB
            B["환경 레코드<br/>x → 0x01 (값 1)"]
        end

        S1 ==>|"var x = 1 실행"| S2
    ```

  - 선언만 된 상태에서는 키는 존재하지만 값이 없으므로 undefined가 반환된다.
    - ```javascript
      console.log(x); // undefined (키는 있고 값은 아직 없다)
      var x = 1;
      console.log(x); // 1
      ```

#### 함수 레벨 스코프

- 대부분의 프로그래밍 언어는 모든 코드 블록이 지역 스코프를 만든다.
  - 이러한 특성을 블록 레벨 스코프라 한다.
- 하지만 var 키워드로 선언된 변수는 오로지 함수의 코드 블록만을 지역 스코프로 인정한다.
  - 이러한 특성을 함수 레벨 스코프라 한다.
  - ```javascript
    var x = 1;

    if (true) {
      var x = 10; // 함수 코드블록이 아니므로 전역 변수를 덮어쓴다.
    }

    console.log(x); // 10
    ```

- for 문의 변수 선언문에서 var로 선언한 변수도 전역 변수가 된다.
- let, const 키워드는 블록 레벨 스코프를 지원한다.

### 렉시컬 스코프

- 함수를 어디서 호출했는지가 아니라 **어디에 정의했는지**에 따라 상위 스코프를 결정한다.
  - 이를 렉시컬 스코프 또는 정적 스코프라 한다.
  - 자바스크립트를 포함한 대부분의 언어가 이 방식을 따른다.
- 반대로 함수를 어디서 호출했는지에 따라 상위 스코프를 결정하는 방식을 동적 스코프라 한다.
  - ```javascript
    var x = 1;

    function foo() {
      var x = 10;
      bar();
    }

    function bar() {
      console.log(x);
    }

    foo(); // 1
    bar(); // 1
    ```

  - bar 함수는 전역에서 정의되었으므로 상위 스코프는 항상 전역 스코프다.
  - 따라서 foo 내부에서 호출해도 전역 변수 x를 참조한다.

- 함수의 상위 스코프는 함수 정의가 실행될 때 정적으로 결정되고 변하지 않는다.
  - 함수 객체는 자신이 정의된 스코프를 기억한다.
  - 이 때문에 클로저가 가능하다.
