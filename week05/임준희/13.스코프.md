### 스코프

- 식별자(변수, 함수, 클래스 이름)가 유요한 범위. 식별자는 자신이 선언된 위치에 의해 다른 코드가 참조할 수 있는 범위가 정해진다.
- 같은 이름의 식별자가 여러 스코프에 있을 때 엔진이 어느 것을 쓸지 정하는 것이 식별자 결정이고, 스코프는 "엔진이 식별자를 검색할 때 쓰는 규칙"이다.
- 스코프는 네임스페이스다. 폴더가 있어서 같은 파일 이름을 여러 곳에 쓸 수 있듯, 스코프가 있어서 같은 변수 이름을 여러 곳에 쓸 수 있다. 한 스코프 안에서 이름은 유일해야 한다.
- var는 같은 스코프에서 중복 선언이 허용되어 의도치 않은 재할당이 생길 수 있다.

### 스코프의 종류

- 전역 스코프: 코드의 가장 바깥 영역. 전역 변수는 어디서든 참조할 수 있다.
- 지역 스코프: 함수 몸체 내부. 지역 변수는 자신의 스코프와 그 하위 스코프(중첩 함수)에서만 유효하다.
- 안쪽에 같은 이름이 있으면 안쪽이 바깥을 가린다.

### 스코프 체인

- 함수가 중첩되면 스코프도 중첩되어 계층 구조가 된다. 바깥 함수의 스코프가 안쪽 함수의 상위 스코프이고, 모든 스코프의 최상위는 전역 스코프다.
- 식별자를 찾을 때 엔진은 현재 스코프에서 시작해 상위로 올라가며 검색하고, 찾으면 멈춘다. 절대 하위로 내려가지 않는다. 그래서 상위 변수는 하위에서 보이지만 하위 변수는 상위에서 안 보인다.
- 스코프마다 `Lexical Environment`가 하나씩 있고, `Outer Environment Reference`로 바깥 `Lexical Environment`를 가리키며 이 체인을 만든다. 식별자 해석은 현재 `Environment Record`에 `HasBinding`으로 "이 이름 있니"를 묻고, 없으면 `Outer Environment Reference`를 따라 올라가기를 반복하는 알고리즘(ResolveBinding -> GetIdentifierReference)이다.
- 함수도 식별자에 할당된 값이라 변수와 똑같이 이 규칙으로 검색된다.

### 함수 레벨 스코프

- C, Java 등은 모든 코드 블록이 스코프를 만들지만(블록 레벨), JS에서 var는 함수 몸체만 스코프로 인정한다(함수 레벨). 함수 밖의 if, for 블록 안에서 var로 선언한 변수는 전역 변수가 되어 바깥 변수를 덮어쓴다.
- ES6 let/const는 블록 레벨 스코프를 지원한다.

### 렉시컬 스코프

- 함수의 상위 스코프를 호출한 위치로 정하면 동적 스코프, 정의한 위치로 정하면 렉시컬 스코프. JS는 렉시컬 스코프다.
- 함수 객체는 만들어질 때 자신의 상위 스코프를 기억한다. 그 시점의 `Lexical Environment`가 함수 객체의 내부 슬롯 `[[Environment]]`에 저장된다. 함수가 호출되면 새 `Lexical Environment`가 만들어지고, 그 `Outer Environment Reference`가 슬롯에 저장해 둔 `Lexical Environment`로 연결된다. 그래서 상위 스코프는 호출 위치가 아니라 정의 위치로 정해진다.

### 스코프는 정적인데 this는 왜 호출 위치에 따라 바뀌나

```javaScript
var x = 1;
function who() { return [x, this]; }
who();                       // x=1, this=globalThis
obj.who();                   // x=1, this=obj
who.call({ name: "outer" }); // x=1, this=outer
```

x는 어디서 불러도 1인데 this는 매번 다르다. this는 식별자가 아니라 호출할 때 결정되는 값이라 렉시컬 스코프 규칙을 따르지 않는다. 자바스크립트에서 "호출 위치에 따라 달라지는 것"은 변수가 아니라 this 뿐이고, 화살표 함수는 this마저 렉시컬로 묶는다.

### 함수가 상위 스코프를 기억한다는 것의 비용

함수 객체의 `[[Environment]]`가 바깥 `Lexical Environment`를 붙들고 있으면 그 환경은 함수가 살아 있는 한 GC되지 않는다. 바깥 함수가 끝나고 지역 변수가 남는 것이 클로저의 원리이자 메모리 누수의 원인이다. V8은 안쪽 함수가 실제로 참조하는 변수만 Context 객체로 올리고 나머지는 스택에 두어 비용을 줄인다.
