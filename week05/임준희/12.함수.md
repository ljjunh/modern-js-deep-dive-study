### 함수란

- 입력을 받아 일련의 과정을 실행하고 출력을 내보내는 하나의 실행 단위
- 함수는 정의로 만들고 호출로 실행한다. 호출하면 매개변수에 인수가 순서대로 할당되고 몸체의 문들이 실행되며, 반환값이 호출 표현식의 값이 된다.
- 쓰는 이유: 코드 재사용, 유지보수 편의성, 신뢰성, 가독성

### 함수 리터럴과 함수 객체

- 함수는 객체 타입의 값이다. 숫자를 숫자 리터럴로 만들듯 함수도 함수 리터럴로 만든다. 리터럴이 평가되면 함수 객체가 생긴다.
- 함수 이름은 식별자이고 생략 가능하다. 있으면 기명 함수, 없으면 익명 함수
- 일반 객체와 다른 점은 호출할 수 있다는 것이고, 호출 가능한 객체만의 프로퍼티를 갖는다. 사양에서는 [[Call]] 내부 메서드가 있는 객체가 함수다.

### 함수 정의 4가지

| 방식             | 예                                                |
| ---------------- | ------------------------------------------------- |
| 함수 선언문      | function add(x, y) { return x + y; }              |
| 함수 표현식      | var add = function (x, y) { return x + y; };      |
| Function 생성자  | var add = new Function('x', 'y', 'return x + y'); |
| 화살표 함수(ES6) | var add = (x, y) => x + y;                        |

### 함수 선언문

- 함수 이름을 생략할 수 없다. 생략하면 SyntaxError.
- 표현식이 아닌 문이다. 콘솔에서 실행하면 완료값 undefined.
- 같은 모양의 기명 함수 리터럴도 놓인 자리에 따라 다르게 해석된다. 단독으로 있으면 선언문, 값이 필요한 자리에 있으면 함수 리터럴 표현식
- 책은 "엔진이 함수 이름과 같은 이름의 식별자를 암묵적으로 생성하고 함수 객체를 할당한다"고 설명한다. 이건 선언문이 왜 바깥에서 호출 가능한지를 보여 주는 모델이다. 사양 기준으로 정확히 말하면 선언문의 이름은 그 스코프에 만들어지는 바인딩 자체이고, 기명 함수 표현식처럼 "몸체 안에서만 보이는 별도의 이름"은 따로 만들어지지 않는다. 그래서 바깥에서 add = 1로 재할당하면 몸체 안에서 보는 add도 1이 된다. 몸체 전용 이름이 따로 생기는 것은 기명 함수 표현식 뿐이다.

```javaScript
function add(x, y) { return add; }
const saved = add; // 함수 객체를 따로 보관
add = 1; // 바깥의 add를 덮어씀
saved(); // 1
```

### 함수 표현식

- 함수는 일급 객체라 변수에 할당할 수 있다. 이름은 보통 생략한다.
- 기명 함수 표현식 `var add = function foo() {}` 에서 foo는 몸체 안에서만 보이고, 재할당할 수 없는 바인딩이다. 바깥에서 `foo()`는 ReferenceError다. 사양이 함수 이름 전용 Environment Record를 하나 더 만들어 불변 바인딩으로 넣기 때문이다. 바깥 변수를 바꿔도 안의 `foo`는 그대로 함수다.
- 함수를 호출하는 것은 함수 이름이 아니라 함수 객체를 가리키는 식별자다. 선언문에서는 둘이 같은 이름이라 구분이 안 보일 뿐이다.

```javaScript
var add = function foo(x, y) { return typeof foo; };
foo(); // ReferenceError: foo is not defined
typeof foo; // "undefined"
add(); // "function" 함수 몸체 안에선 foo가 보임

var h1 = function foo() { foo = 1; return typeof foo; };
h1(); // "function" 비엄격: 할당이 조용히 무시됨

var h2 = function foo() { "use strict"; foo = 1; return typeof foo; };
h2(); // TypeError: Assignment to constant variable 엄격: 에러
```

### 함수 생성 시점과 호이스팅

- 선언문은 등록 단계에서 함수 객체까지 만들어져 바인딩에 들어간다. 그래서 선언문보다 앞에서 호출할 수 있다.
- 표현식은 변수 호이스팅만 일어난다. var면 undefined라 앞에서 호출하면 TypeError(not a function), const/let이면 TDZ라 ReferenceError다.

### Function 생성자

- `new Function('x', 'y', 'return x + y')` new 없이 호출해도 같다.
- 일반적이지 않고 권장되지 않는다. 책은 "클로저를 생성하지 않는다"고 하는데, 정확히는 만들어진 함수의 스코프가 항상 전역이다. 확인 결과 둘러싼 함수의 지역 변수는 못 보고 전역 객체의 프로퍼티는 본다.

```javaScript
globalThis.g = "전역";

function outer() {
    var local ="지역";
    var normal = function () { return typeof local + " / " + typeof g; };
    var dyn = new Function("return typeof local + ' / ' + typeof g;");
    return [normal(), dyn()];
}

outer();
// normal() -> "string / string" <- 지역 local, 전역 g 둘 다 보임
// dyn() -> "undefined / string" <- 지역 local은 못 보고 전역 g만 보임
```

### 화살표 함수

- 책은 "항상 익명 함수"라 하는데, 문법상 자기 이름을 가질 수 없다는 뜻이다. 변수에 할당하면 add.name은 "add"가 된다. 사양의 NamedEvaluation이 할당되는 이름을 name 프로퍼티로 넣어준다. 익명 함수 표현식도 같다.
- 표현만 간략한 게 아니라 내부 동작도 다르다. 생성자로 쓸 수 없고, this 바인딩이 다르고, prototype이 없고, arguments 객체가 없다

### 함수 호출

- 매개변수와 인수: 매개변수는 정의할 때 선언하고 함수 몸체 안에서만 참조 가능(스코프가 함수 내부). 인수는 호출할 때 넘기는 값으로 개수와 타입에 제한이 없다.
- 호출되면 매개변수가 몸체 안에서 변수처럼 만들어지고 인수가 순서대로 들어간다. 인수가 부족하면 undefined, 많으면 초과분은 무시되지만 arguments 객체에는 전부 보관된다.
- 자바스크립트는 매개변수와 인수의 개수, 타입을 확인하지 않는다.
- 매개변수 개수는 적을수록 좋고 3개 이하를 권장한다. 많아지면 객체 하나로 받아도 좋지만 객체를 받아 안에서 바꾸면 바깥 객체가 바뀐다.

### 반환문

- return 표현식은 함수 실행을 중단하고 함수를 빠져나가며, 표현식의 값을 반환한다. 반환문 뒤의 문은 실행되지 않는다.
- 표현식을 생략하거나 반환문 자체를 생략하면 undefined
- return 뒤에 줄바꿈이 오면 ASI가 세미콜론을 넣어 그 아래 표현식이 무시된다.
- 반환문은 함수 내부에서만 쓸 수 있다. 브라우저 스크립트의 전역에서는 SyntaxError, Node에서는 파일이 모듈 함수로 감싸져 있어 에러가 나지 않는다.

### 참조에 의한 전달과 외부 상태의 변경

- 원시 값은 값 자체가 복사되어 전달되므로 함수 안에서 바꿔도 바깥에 영향이 없다.
- 객체는 참조가 복사되어 전달되므로 함수 안에서 프로퍼티를 바꾸면 바깥 객체가 바뀐다.
- 외부 상태를 바꾸는 함수는 상태 변화를 추적하기 어렵게 만든다. 해결책은 불변 객체로 만들거나, 깊은 복사로 새 객체를 만들어 돌려주는 것. 외부 상태에 의존하지도 변경하지도 않는 함수가 순수 함수다.

### 즉시 실행 함수(IIFE)

- 정의와 동시에 한 번 호출

### 재귀 함수

- 자기 자신을 호출
- 탈출 조건이 없으면 무한 루프
- 대부분 반복문으로 바꿀 수 있고, 재귀가 더 직관적일 때만 쓴다.

### 중첩 함수

- 함수 안에 정의한 함수
- 외부 함수의 변수를 참조할 수 있고 외부 함수 안에서만 호출된다

### 콜백 함수와 고차 함수

- 매개변수로 다른 함수에 전달되는 함수가 콜백 함수
- 콜백을 받아 호출 시점을 결정하는 함수가 고차 함수
- 콜백을 익명 리터럴로 넘기면 고차 함수를 호출할 때마다 함수 객체가 새로 만들어진다

### 순수 함수와 비순수 함수

- 같은 인수에 항상 같은 값을 돌려주고 외부 상태를 바꾸지 않으면 순수 함수
- 외부 상태에 의존하거나 외부 상태를 바꾸면 비순수 함수
- 함수형 프로그래밍은 순수 함수와 보조 함수의 조합으로 부수 효과를 최소화해 불변성을 지향한다.
