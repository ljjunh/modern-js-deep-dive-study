### Object 생성자 함수

- new 연산자와 함께 Object 생성자 함수를 호출하면 빈 객체를 생성하여 반환한다.
  - 빈 객체를 생성한 이후 프로퍼티나 메서드를 추가하여 객체를 완성할 수 있다.
  - ```javascript
    const person = new Object();

    person.name = "Lee";
    person.sayHello = function () {
      console.log("Hi! My name is " + this.name);
    };

    console.log(person); // { name: 'Lee', sayHello: f }
    ```

- 생성자 함수란 new 연산자와 함께 호출하여 객체(인스턴스)를 생성하는 함수를 말한다.
  - 생성자 함수에 의해 생성된 객체를 인스턴스라 한다.
- 자바스크립트는 Object 외에도 String, Number, Boolean, Function, Array, Date, RegExp, Promise 등의 빌트인 생성자 함수를 제공한다.
  - ```javascript
    const strObj = new String("Lee"); // String {'Lee'}
    const numObj = new Number(123); // Number {123}
    const func = new Function("x", "return x * x"); // f anonymous(x)
    ```
- 다만 객체를 생성하는 방법으로 객체 리터럴이 더 간편하므로 Object 생성자 함수는 특별한 이유가 없다면 사용하지 않는다.

### 생성자 함수

#### 객체 리터럴에 의한 객체 생성 방식의 문제점

- 객체 리터럴은 직관적이고 간편하지만 **단 하나의 객체만 생성**한다.
  - 따라서 동일한 프로퍼티를 갖는 객체를 여러 개 생성해야 하는 경우 매번 같은 코드를 기술해야 한다.
  - ```javascript
    const circle1 = {
      radius: 5,
      getDiameter() {
        return 2 * this.radius;
      },
    };

    const circle2 = {
      radius: 10,
      getDiameter() {
        // 같은 메서드를 또 작성해야 한다
        return 2 * this.radius;
      },
    };
    ```

- 객체는 프로퍼티를 통해 **상태(state)** 를 표현하고 메서드를 통해 **동작(behavior)** 을 표현한다.
  - 프로퍼티 값은 객체마다 다를 수 있지만 메서드는 내용이 동일한 경우가 일반적이다.
  - 그런데도 객체 리터럴은 객체마다 메서드를 중복해서 갖게 되므로 비효율적이다.

#### 생성자 함수에 의한 객체 생성 방식의 장점

- 생성자 함수는 객체(인스턴스)를 생성하기 위한 **템플릿(클래스)처럼** 동작한다.
  - 즉 프로퍼티 구조가 동일한 객체 여러 개를 간편하게 생성할 수 있다.
  - ```javascript
    function Circle(radius) {
      // 생성자 함수 내부의 this는 생성할 인스턴스를 가리킨다
      this.radius = radius;
      this.getDiameter = function () {
        return 2 * this.radius;
      };
    }

    const circle1 = new Circle(5);
    const circle2 = new Circle(10);

    console.log(circle1.getDiameter()); // 10
    console.log(circle2.getDiameter()); // 20
    ```

- 생성자 함수는 일반 함수와 동일한 방법으로 정의하고 **new 연산자와 함께 호출하면** 생성자 함수로 동작한다.
  - 반대로 new 연산자 없이 호출하면 일반 함수로 동작한다.
  - ```javascript
    const circle3 = Circle(15); // new 없이 호출했다

    console.log(circle3); // undefined (일반 함수는 암묵적으로 undefined를 반환한다)
    console.log(radius); // 15 (this가 전역 객체를 가리켜 전역 변수가 되었다)
    ```

  - 즉 함수 자체에 특별한 형식이 있는 것이 아니라 **호출 방식이 역할을 결정한다**.

- 따라서 생성자 함수는 일반 함수와 구분하기 위해 **파스칼 케이스로 명명하는 것이 관례**다.

#### this

- this는 객체 자신의 프로퍼티나 메서드를 참조하기 위한 **자기 참조 변수(self-referencing variable)** 다.
  - this가 가리키는 값, 즉 **this 바인딩은 함수 호출 방식에 따라 동적으로 결정된다**.

| 함수 호출 방식       | this가 가리키는 값(this 바인딩)        |
| -------------------- | -------------------------------------- |
| 일반 함수로서 호출   | 전역 객체                              |
| 메서드로서 호출      | 메서드를 호출한 객체(마침표 앞의 객체) |
| 생성자 함수로서 호출 | 생성자 함수가 (미래에) 생성할 인스턴스 |

- ```javascript
  function foo() {
    console.log(this);
  }

  foo(); // window (일반 함수로서 호출)

  const obj = { foo };
  obj.foo(); // obj (메서드로서 호출)

  new foo(); // foo {} (생성자 함수로서 호출)
  ```

- 즉 **같은 함수라도 호출 방식에 따라 this가 달라진다**.
  - 생성자 함수를 new 없이 호출하면 this가 인스턴스가 아닌 전역 객체를 가리키게 되는 이유다.

#### 생성자 함수의 인스턴스 생성 과정

- 생성자 함수의 역할은 인스턴스를 생성하고 생성된 인스턴스를 초기화하는 것이다.
  - 인스턴스 생성은 필수이고 초기화는 옵션이다.
- new 연산자와 함께 생성자 함수를 호출하면 자바스크립트 엔진이 다음 과정을 **암묵적으로** 수행한다.
- 메모리 관점에서 보면 **힙에 객체 하나가 만들어지고 그 주소가 복사되며 전달된다**.
  - ```javascript
    function Circle(radius) {
      this.radius = radius;
    }

    const circle = new Circle(5);
    ```

  - 위 코드를 실행하면 다음 순서로 동작한다.
  - ```
    1. new가 힙에 빈 객체를 만든다

       힙(Heap)
       ┌──────────────┐
       │ 0x100: { }   │
       └──────────────┘

    2. 그 주소를 this에 연결하고 함수를 실행한다

       콜 스택(Call Stack)
       ┌─────────────────────────┐
       │ Circle 실행 컨텍스트       │
       │   this   → 0x100        │  주소를 가리킨다
       │   radius → 5            │  원시 값은 스택에 직접 저장된다
       └─────────────────────────┘

    3. this.radius = radius 가 실행된다

       힙
       ┌──────────────┐
       │ 0x100: {     │
       │   radius: 5  │  0x100 객체에 프로퍼티가 추가된다
       │ }            │
       └──────────────┘

    4. 함수가 끝나면 new가 0x100을 반환한다

       콜 스택에서 실행 컨텍스트가 제거되어 this는 사라지지만
       힙의 객체는 반환되어 살아남는다

    5. circle이 그 주소를 이어받는다

       ┌─────────────────────────┐
       │ 전역 컨텍스트              │
       │   circle → 0x100        │
       └─────────────────────────┘
    ```

- 즉 객체는 **단 한 번만 만들어지고 복사되는 것은 주소뿐**이다.
  - this와 circle은 같은 객체를 가리키는 서로 다른 이름이다.
  - ```javascript
    function Circle(radius) {
      this.radius = radius;
      this.self = this; // 자기 주소를 프로퍼티에 담아둔다
    }

    const circle = new Circle(5);

    circle.self === circle; // true (같은 객체다)
    ```

- 함수가 끝나면 this는 사라지지만 **힙의 객체는 반환되어 살아남는다**.
  - 반대로 반환값을 어디에도 할당하지 않으면 주소를 가리키는 곳이 없어 가비지 컬렉션의 대상이 된다.
  - ```javascript
    new Circle(5); // 할당하지 않으면 참조가 끊겨 수거된다
    ```
- 생성자 함수는 인스턴스 자체가 아니라 인스턴스를 찍어내는 **템플릿**이다.
  - 반환되는 인스턴스는 함수가 아니라 new가 만들어낸 별개의 객체다.
  - ```javascript
    const circle = new Circle(5);

    typeof Circle; // 'function' (함수다)
    typeof circle; // 'object' (new가 만들어낸 인스턴스다)
    circle === Circle; // false (서로 다른 값이다)
    ```

##### 1. 인스턴스 생성과 this 바인딩

- 암묵적으로 빈 객체가 생성되고 이 객체가 this에 바인딩된다.
  - 이 처리는 함수 몸체의 코드가 한 줄씩 실행되는 **런타임 이전에** 실행된다.
  - ```javascript
    function Circle(radius) {
      // 함수에 들어오기 전에 new가 이미 빈 객체를 만들어 this에 연결해두었다
      console.log(this); // Circle {} (아직 비어 있는 인스턴스)

      this.radius = radius;
    }

    new Circle(5);
    ```

  - 즉 `console.log(this)`는 빈 객체가 채워지기 **직전의 모습**을 보기 위한 코드다.
    - 함수 바깥에서는 이미 완성된 모습만 보이므로 이 순간을 확인할 수 없다.

- 여기서 바인딩이란 식별자와 값을 연결하는 과정을 말한다.
  - this 바인딩은 this가 가리킬 객체를 연결하는 것이다.
- 일반 변수는 개발자가 선언할 때 연결되지만 **this는 엔진이 호출할 때마다 연결한다**.
  - 따라서 같은 함수라도 호출 방식에 따라 this에 연결되는 값이 달라진다.
  - this는 재할당할 수 없으며 엔진만 연결할 수 있다.
  - ```javascript
    this = {}; // SyntaxError: Invalid left-hand side in assignment
    ```

##### 2. 인스턴스 초기화

- 생성자 함수에 기술되어 있는 코드가 한 줄씩 실행되어 this에 바인딩된 인스턴스를 초기화한다.
  - 즉 인스턴스에 프로퍼티나 메서드를 추가하고 인수로 전달받은 초기값을 할당한다.
  - ```javascript
    function Circle(radius) {
      // this에 연결된 인스턴스를 초기화한다
      this.radius = radius;
      this.getDiameter = function () {
        return 2 * this.radius;
      };
    }
    ```
- 이 과정은 개발자가 직접 기술한다.

##### 3. 인스턴스 반환

- 생성자 함수 내부의 모든 처리가 끝나면 **완성된 인스턴스가 바인딩된 this가 암묵적으로 반환된다**.
  - 이 반환도 함수가 아니라 new 연산자가 수행한다.
  - ```javascript
    function Circle(radius) {
      this.radius = radius;
    } // 함수가 끝나면 new가 this(인스턴스)를 대신 반환해준다

    console.log(new Circle(5)); // Circle { radius: 5 }
    ```

  - 반환되는 것은 함수 자신이 아니라 앞서 new가 만들어둔 **별개의 객체**다.
    - 출력의 `Circle {...}`에서 앞의 Circle은 어떤 생성자로 만들어졌는지 알려주는 이름표일 뿐이다.
  - 따라서 호출할 때마다 매번 새로운 인스턴스가 만들어진다.
  - ```javascript
    const c1 = new Circle(5);
    const c2 = new Circle(10);

    c1 === c2; // false (호출마다 별개의 객체가 생성된다)
    ```

- 만약 this가 아닌 **다른 객체를 명시적으로 반환하면 this 반환이 무시된다**.
  - ```javascript
    function Circle(radius) {
      this.radius = radius;
      return { name: "Lee" }; // 객체를 반환하면 this가 무시된다
    }

    console.log(new Circle(5)); // { name: 'Lee' }
    ```
- 이때 인스턴스가 덮어씌워지는 것이 아니라 **두 객체가 따로 만들어진다**.
  - 인스턴스는 정상적으로 완성되지만 아무도 그 주소를 받아가지 않아 버려진다.
  - ```
    힙(Heap)
    ┌──────────────────────┐
    │ 0x100: {             │  new가 만든 인스턴스
    │   radius: 5          │  정상적으로 완성되었다
    │ }                    │
    │                      │
    │ 0x500: {             │  return 문이 만든 별개의 객체
    │   name: "Lee"        │
    │ }                    │
    └──────────────────────┘

    this   → 0x100   (여전히 인스턴스를 가리킨다)
    circle → 0x500   ← return이 이긴다
    ```
  - 따라서 0x100은 참조가 끊겨 가비지 컬렉션의 대상이 된다.
- 이 경우 **프로토타입 연결도 함께 끊긴다**.
  - 반환된 객체는 객체 리터럴이므로 Circle.prototype이 아닌 Object.prototype을 가리킨다.
  - ```javascript
    Circle.prototype.getArea = function () {
      return Math.PI * this.radius ** 2;
    };

    const circle = new Circle(5);

    circle.getArea(); // TypeError: circle.getArea is not a function
    circle instanceof Circle; // false (상속이 끊겼다)
    ```
  - 즉 초기화한 값도, 상속받을 메서드도 모두 잃게 된다. ([19장](./19.프로로타입.md#프로토타입-객체))

- 하지만 **원시 값을 반환하면 원시 값 반환이 무시되고 this가 반환된다**.
  - ```javascript
    function Circle(radius) {
      this.radius = radius;
      return 100; // 원시 값은 무시된다
    }

    console.log(new Circle(5)); // Circle { radius: 5 }
    ```
  - new의 목적은 객체 생성이므로 **반환값이 객체일 때만 채택**하기 때문이다.
  - null은 typeof 연산자가 'object'를 반환하지만 객체가 아니므로 무시된다.
    - ```javascript
      function Circle(radius) {
        this.radius = radius;
        return null;
      }

      console.log(new Circle(5)); // Circle { radius: 5 }
      ```

- 즉 생성자 함수 내부에서 return 문을 반드시 생략해야 한다.
  - 명시적으로 객체를 반환하면 생성자 함수의 기본 동작을 훼손하기 때문이다.

| 반환 값 | 실제 반환되는 것 |
| ------- | ---------------- |
| 생략    | this (인스턴스)  |
| 객체    | **반환한 객체**  |
| 원시 값 | this (인스턴스)  |
| null    | this (인스턴스)  |

### 내부 메서드 `[[Call]]`과 `[[Construct]]`

- 함수는 객체이지만 일반 객체와는 다르다.
  - 일반 객체는 호출할 수 없지만 함수는 호출할 수 있다.
- 따라서 함수 객체는 일반 객체가 가지고 있는 내부 슬롯과 내부 메서드는 물론
  - 함수로서 동작하기 위해 함수 객체만을 위한 `[[Environment]]`, `[[FormalParameters]]` 등의 내부 슬롯과
  - `[[Call]]`, `[[Construct]]` 같은 내부 메서드를 추가로 갖는다.
- 함수가 **일반 함수로 호출되면 `[[Call]]`이 호출되고 new 연산자와 함께 호출되면 `[[Construct]]`가 호출된다**.
  - ```javascript
    function foo() {}

    foo(); // [[Call]] 호출
    new foo(); // [[Construct]] 호출
    ```

- 모든 함수 객체는 `[[Call]]`을 갖고 있으므로 호출할 수 있다.
  - 하지만 `[[Construct]]`는 모든 함수 객체가 갖는 것은 아니다.
- 내부 메서드 `[[Call]]`을 갖는 함수 객체를 callable이라 하고
  - 내부 메서드 `[[Construct]]`를 갖는 함수 객체를 constructor,
  - `[[Construct]]`를 갖지 않는 함수 객체를 non-constructor라 한다.
- 즉 **모든 함수 객체는 callable이지만 모든 함수 객체가 constructor인 것은 아니다**.

### constructor와 non-constructor의 구분

- 자바스크립트 엔진은 함수 정의를 평가하여 **함수 객체를 생성할 때 함수 정의 방식에 따라** 둘을 구분한다.
  - constructor : 함수 선언문, 함수 표현식, 클래스
  - non-constructor : 메서드(ES6 메서드 축약 표현), 화살표 함수
  - ```javascript
    // constructor
    function foo() {}
    const bar = function () {};

    // non-constructor
    const arrow = () => {};
    const obj = {
      baz() {}, // ES6 메서드 축약 표현
    };

    new foo(); // foo {}
    new bar(); // bar {}
    new arrow(); // TypeError: arrow is not a constructor
    new obj.baz(); // TypeError: obj.baz is not a constructor
    ```

- 주의할 점은 ECMAScript 사양에서 **메서드란 ES6의 메서드 축약 표현만을 의미한다**는 것이다.
  - 즉 프로퍼티에 할당한 일반 함수 표현식은 메서드가 아니라 constructor다.
  - ```javascript
    const obj = {
      x: function () {}, // 일반 함수 표현식이므로 constructor다
      y() {}, // ES6 메서드이므로 non-constructor다
    };

    new obj.x(); // x {}
    new obj.y(); // TypeError: obj.y is not a constructor
    ```

- non-constructor는 prototype 프로퍼티도 갖지 않는다. ([18장](../../week05/윤홍비/18.함수와_일급_객체.md#prototype-프로퍼티))
  - new로 호출할 수 없으므로 인스턴스의 프로토타입이 될 객체가 필요 없기 때문이다.

### new 연산자

- new 연산자와 함께 함수를 호출하면 해당 함수는 생성자 함수로 동작한다.
  - 이때 호출되는 함수는 non-constructor가 아닌 **constructor여야 한다**.
- 반대로 new 연산자 없이 생성자 함수를 호출하면 일반 함수로 호출된다.
  - 즉 `[[Call]]`이 호출되므로 this는 전역 객체를 가리키게 된다.
  - ```javascript
    function Circle(radius) {
      this.radius = radius;
      this.getDiameter = function () {
        return 2 * this.radius;
      };
    }

    const circle = Circle(5); // new 없이 호출

    console.log(circle); // undefined
    console.log(radius); // 5 (전역 변수가 되었다)
    console.log(getDiameter()); // 10 (전역 함수가 되었다)
    ```

- 메모리 관점에서 보면 **새로운 객체가 아예 만들어지지 않는다**.
  - this가 이미 존재하던 전역 객체를 가리키므로 프로퍼티가 전역 객체에 들러붙는다.
  - ```
    힙(Heap)
    ┌──────────────────────┐
    │ 0x001: window {      │  이미 존재하던 전역 객체
    │   radius: 5          │  여기에 추가된다
    │   getDiameter: f     │
    │ }                    │
    └──────────────────────┘

    this → 0x001 (전역 객체의 주소)
    ```

  - 즉 빈 객체 생성도, 반환도 없으므로 반환값은 undefined가 된다.
  - 전역 객체의 프로퍼티는 전역 변수처럼 이름만으로 접근할 수 있다.
    - 따라서 함수 바깥에서 radius를 참조하면 값이 출력된다.
    - ```javascript
      console.log(radius === window.radius); // true (같은 것이다)
      ```

- 에러 없이 조용히 전역이 오염되므로 발견하기 어렵다는 점이 위험하다.
  - 단 strict mode에서는 this가 undefined이므로 TypeError가 발생해 즉시 드러난다.
- 따라서 일반 함수와 생성자 함수에 특별한 형식적 차이는 없고
  - **파스칼 케이스 명명 규칙**으로 생성자 함수임을 알리는 것이 최선이다.

### new.target

- new.target은 **함수가 new 연산자와 함께 호출되었는지 확인**할 수 있는 ES6 문법이다.
  - new 연산자와 함께 호출되면 함수 자신을 가리키고, 그렇지 않으면 undefined다.
  - ```javascript
    function Circle(radius) {
      // new 없이 호출되었다면 new.target은 undefined다
      if (!new.target) {
        return new Circle(radius); // new와 함께 재귀 호출한다
      }

      this.radius = radius;
    }

    const circle = Circle(5); // new 없이 호출했다
    console.log(circle.radius); // 5 (정상 동작한다)
    ```

- 이러한 패턴을 **스코프 세이프 생성자 함수(scope-safe constructor)** 라 한다.
  - new 없이 호출해도 전역 스코프를 오염시키지 않으므로 scope-safe라 부른다.
  - 즉 재귀 호출 자체가 아니라 **방어 코드를 갖춘 생성자 함수**를 가리키는 이름이다.
- new.target을 지원하지 않는 환경에서는 `instanceof`로 같은 효과를 낼 수 있다.
  - ```javascript
    function Circle(radius) {
      if (!(this instanceof Circle)) {
        return new Circle(radius);
      }
      this.radius = radius;
    }
    ```
  - new 없이 호출하면 this가 전역 객체를 가리키므로 `instanceof` 검사가 false가 된다.
- 다만 ES6의 **클래스는 new 없이 호출하면 애초에 에러가 발생**하므로 이 패턴이 필요 없다.
  - ```javascript
    class Circle {
      constructor(radius) {
        this.radius = radius;
      }
    }

    Circle(5); // TypeError: Class constructor Circle cannot be invoked without 'new'
    ```
  - 조용히 전역을 오염시키는 대신 즉시 에러로 알려주므로 더 안전하다.
  - 따라서 스코프 세이프 생성자 함수는 주로 기존 코드에서 마주치게 되는 패턴이다.
- 참고로 대부분의 빌트인 생성자 함수는 new 연산자와 함께 호출되었는지 확인한 후 적절한 값을 반환한다.
  - Object와 Function 생성자 함수는 new 없이 호출해도 new와 동일하게 동작한다.
  - ```javascript
    const obj = Object(); // {} (new와 동일하게 동작한다)
    const f = Function("x", "return x"); // f anonymous(x)
    ```
- 하지만 String, Number, Boolean은 **new 여부에 따라 결과가 완전히 달라진다**.
  - new와 함께 호출하면 래퍼 객체를, 없이 호출하면 **원시 값을 반환**한다.
  - ```javascript
    const num = new Number(123); // Number {123} (객체)
    const n = Number("123"); // 123 (원시 값)

    typeof num; // 'object'
    typeof n; // 'number'
    ```

  - 즉 Number, String, Boolean은 new 없이 호출하여 **타입 변환 함수로 사용하는 것이 일반적**이다.

- 래퍼 객체는 원시 값과 비교 동작이 다르므로 혼동하지 않도록 주의해야 한다.
  - ```javascript
    new Number(0) == 0; // true (암묵적 타입 변환이 일어난다)
    new Number(0) === 0; // false (객체와 원시 값이므로 다르다)

    if (new Boolean(false)) {
      console.log("실행된다"); // 객체는 항상 truthy다
    }
    ```

  - 따라서 래퍼 객체를 직접 생성할 일은 거의 없다.
