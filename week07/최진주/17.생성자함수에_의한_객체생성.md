# 17장. 생성자 함수에 의한 객체 생성

- 같은 구조의 객체를 여러 개 만들 때 쓰는 함수 = 생성자 함수
- `new`와 함께 호출하면 객체 생성, `this` 연결, 반환을 엔진이 암묵적으로 처리
- 생성자 함수로 만든 객체 = 인스턴스
- 이후 프로토타입(19장), 클래스(25장)의 기반 개념

---

## 객체 리터럴 vs 생성자 함수

| 구분 | 객체 리터럴 `{}` | 생성자 함수 |
|---|---|---|
| 적합한 상황 | 객체 하나 생성 | 같은 구조 객체 여러 개 생성 |
| 구조 정의 | 객체마다 반복 작성 | 함수 하나로 재사용 |
| 초기값 전달 | 직접 작성 | 인수로 전달 |

```js
function Product(name, price) {
  this.name = name;
  this.price = price;
}

const p1 = new Product('키보드', 50000);
const p2 = new Product('마우스', 30000);

console.log(p1.name); // '키보드'
console.log(p2.price); // 30000
```

- 이름은 파스칼 케이스(대문자 시작)가 관례
- 문법상 강제 아님, `new`로 호출하라는 의도 표시용
- `Object`, `String`, `Number`, `Function`, `Array`, `Date`, `RegExp` 등 빌트인 생성자 함수도 존재

## this 바인딩

- `this`: 자신이 속한 객체 또는 자신이 생성할 인스턴스를 가리키는 식별자
- 함수 정의 시점이 아닌 호출 방식에 따라 동적으로 결정

| 호출 방식 | this |
|---|---|
| 일반 함수 호출 `foo()` | 전역 객체 (strict mode에서는 `undefined`) |
| 메서드 호출 `obj.foo()` | 메서드를 호출한 객체 |
| 생성자 함수 호출 `new Foo()` | 생성할 인스턴스 |

```js
function whoAmI() {
  return this;
}

const obj = { whoAmI };

console.log(obj.whoAmI() === obj); // true
console.log(new whoAmI() instanceof whoAmI); // true
```

## new 호출 시 내부 동작

```js
function Product(name) {
  // 1. 빈 객체 생성 후 this에 바인딩 (암묵적)
  // 2. this에 프로퍼티 추가 (개발자가 작성하는 부분)
  this.name = name;
  // 3. 바인딩된 this 반환 (암묵적)
}
```

1. 인스턴스 생성과 this 바인딩: 런타임 이전에 빈 객체 생성, `this`에 연결
2. 인스턴스 초기화: 함수 본문 실행, `this`에 프로퍼티와 메서드 추가
3. 인스턴스 반환: 모든 처리 후 `this` 자동 반환

### 명시적 return 처리

| return 대상 | 결과 |
|---|---|
| 없음 | `this` 반환 |
| 객체 | `this` 대신 해당 객체 반환 |
| 원시값 | 무시, `this` 반환 |

```js
function A() {
  this.x = 1;
  return { y: 2 };
}

function B() {
  this.x = 1;
  return 100;
}

console.log(new A()); // { y: 2 }
console.log(new B()); // B { x: 1 }
```

- 명시적 return은 생성자 함수의 기본 동작을 훼손하므로 생략이 원칙

## 내부 메서드 [[Call]], [[Construct]]

- 함수도 객체, 일반 객체의 내부 슬롯과 내부 메서드를 모두 보유
- 추가로 함수 전용 내부 슬롯(`[[Environment]]`, `[[FormalParameters]]` 등)과 내부 메서드 보유

| 내부 메서드 | 실행 시점 | 보유 여부 |
|---|---|---|
| `[[Call]]` | 일반 함수로 호출 | 모든 함수 (callable) |
| `[[Construct]]` | `new`로 호출 | constructor만 보유 |

- 모든 함수 객체는 callable
- 모든 함수 객체가 constructor는 아님

## constructor vs non-constructor

- 구분 기준: 함수 내용이 아닌 함수 정의 방식

| constructor (`new` 가능) | non-constructor (`new` 불가) |
|---|---|
| 함수 선언문 | 화살표 함수 |
| 함수 표현식 | 메서드 축약 표현 (ES6) |
| 클래스 | |

```js
const arrow = () => {};
const obj = {
  method() {},
  normal: function () {},
};

new obj.normal(); // 정상 동작 (함수 표현식)
new arrow(); // TypeError: arrow is not a constructor
new obj.method(); // TypeError: obj.method is not a constructor
```

- ES6 사양의 메서드는 메서드 축약 표현으로 정의한 함수만 의미
- 프로퍼티 값으로 할당된 일반 함수(`normal`)는 constructor
- 일반 함수로 정의해도 `new`로 호출하면 생성자 함수로 동작, 의도와 다른 동작 가능성 존재

## new 연산자 유무에 따른 차이

- `new` 있음: `[[Construct]]` 호출, 생성자 함수로 동작
- `new` 없음: `[[Call]]` 호출, 일반 함수로 동작

```js
function Product(name) {
  this.name = name;
}

const p = Product('키보드');
console.log(p); // undefined
```

- 일반 함수로 호출되어 `this`가 전역 객체를 가리킴
- 반환문이 없어 `undefined` 반환, 전역 객체에 `name` 프로퍼티가 추가되는 부작용 발생

## new.target

- ES6 도입, 함수 내부에서 사용하는 메타 프로퍼티
- `new`로 호출: 함수 자신을 가리킴
- `new` 없이 호출: `undefined`

```js
function Product(name) {
  if (!new.target) {
    return new Product(name);
  }
  this.name = name;
}

const p = Product('키보드');
console.log(p.name); // '키보드'
```

- `new` 누락을 방지하는 안전장치로 활용
- IE 미지원, 대안으로 스코프 세이프 생성자 패턴(`this instanceof Product` 검사) 사용
- 클래스는 `new` 없이 호출하면 항상 TypeError 발생하므로 별도 처리 불필요

### 빌트인 생성자 함수의 new 유무 차이

| 생성자 | `new` 있음 | `new` 없음 |
|---|---|---|
| `Object`, `Function` | 객체 반환 | 동일하게 객체 반환 |
| `String`, `Number`, `Boolean` | 래퍼 객체 반환 | 원시값 반환 (타입 변환) |

```js
console.log(typeof new String(123)); // 'object'
console.log(typeof String(123)); // 'string'
console.log(Number('42')); // 42
```

## 생성자 함수 방식의 한계

```js
function Product(name) {
  this.name = name;
  this.getName = function () {
    return this.name;
  };
}

const p1 = new Product('키보드');
const p2 = new Product('마우스');

console.log(p1.getName === p2.getName); // false
```

- 인스턴스마다 동일한 메서드가 중복 생성되어 메모리 낭비
