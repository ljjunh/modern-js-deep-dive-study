### Object 생성자 함수

`new Object()`로 빈 객체를 만들고 프로퍼티를 붙여 완성할 수 있다. 하지만 리터럴이 더 간편해서 특별한 이유가 없다면 그다지 유용해 보이지 않는다. 자바스크립트는 Object 외에도 String, Number, Boolean, Function, Array, Date, RegExp, Promise 같은 빌트인 생성자 함수를 제공한다.

### 생성자 함수

객체 리터럴의 문제점: 객체 하나만 만든다. 구조가 같은 객체를 여러 개 만들려면 같은 프로퍼티와 메서드를 매번 적어야 한다. 객체는 프로퍼티로 상태를, 메서드로 동작을 표현하는데, 상태 값은 객체마다 달라도 메서드는 보통 같다.

생성자 함수의 장점: 템플릿처럼 써서 구조가 같은 객체를 여러개 만들기 편하다. this는 생성자 함수가 만들 인스턴스를 가리킨다.

정의 형식: 자바 같은 클래스 기반 언어와 달리 생성자 함수의 형식이 따로 없다. 일반 함수와 똑같이 정의하고 new와 함께 호출하면 생성자로 동작한다. new 없이 부르면 일반 함수다.

### this 바인딩(함수 호출 방식에 따라 동적으로 결정)

| 호출 방식            | this                            |
| -------------------- | ------------------------------- |
| 일반 함수로서 호출   | 전역 객체(엄격 모드: undefined) |
| 메서드로서 호출      | 마침표 앞의 객체                |
| 생성자 함수로서 호출 | 생성자가 만들 인스턴스          |

### 인스턴스 생성 과정

생성자 함수의 역할은 인스턴스 생성(필수)과 초기화(옵션)다. 개발자는 초기화 코드만 쓰고, 생성과 반환은 엔진이 암묵적으로 한다.

1. 인스턴스 생성과 this 바인딩: 빈 객체가 만들어지고 this에 바인딩된다. 본문 코드가 실행되기 전에 일어난다.
2. 인스턴스 초기화: 본문이 실행되며 this에 프로퍼티와 메서드를 추가하고 인수로 초기값을 할당한다.
3. 인스턴스 반환: 완성된 this를 암묵적으로 반환한다. 다른 객체를 명시적으로 반환하면 그 객체가 반환되고, 원시 값을 반환하면 무시되고 this가 반환된다. 그래서 생성자 함수에서는 return을 쓰지 않는다.

### 내부 메서드 [[Call]]과 [[Construct]]

함수는 객체라 일반 객체의 내부 슬롯, 메서드를 다 갖고, 함수 전용으로 [[Environment]], [[FormalParameters]]같은 내부 슬롯과 [[Call]], [[Construct]] 내부 메서드를 추가로 갖는다.

- 일반 호출 foo() -> [[Call]] 실행
- new foo() -> [[Construct]] 실행
- [[Call]]을 갖는 객체 = callable(모든 함수)
- [[Construct]]를 갖는 함수 = constructor
- [[Construct]]가 없는 함수 = non-constructor
- 모든 함수는 callable이지만 모두 constructor인 건 아니다.

### constructor와 non-constructor의 구분

엔진은 함수 정의 방식으로 구분한다.

- constructor: 함수 선언문, 함수 표현식, 클래스
- non-constructor: 메서드 축약 표현, 화살표 함수
  사양에서 "메서드"는 ES6 메서드 축약 표현만이다. { x: function(){} } 처럼 프로퍼티 값으로 할당한 일반 함수는 메서드가 아니라 constructor다. 함수가 어디 할당됐는지가 아니라 어떻게 정의됐는지로 결정된다. non-constructor에 new를 붙이면 TypeError

### new 연산자

new를 붙이면 [[Construct]]가, 안 붙이면 [[Call]]이 호출된다. 생성자로 쓸 의도가 없는 일반 함수에 new를 붙여도 동작은 한다.(객체를 반환하지 않으면 빈 객체 반환, 객체를 반환하면 그 객체) 반대로 생성자 함수를 new 없이 부르면 this가 전역 객체라 프로퍼티가 전역에 새 나간다. 그래서 생성자 함수는 파스칼 케이스로 이름 지어 구별한다.

### new.target

파스칼 케이스는 관례일 뿐이라 실수를 못 막는다. ES6의 new.target은 constructor 함수 안에서 쓰는 메타 프로퍼티로, new로 호출되면 함수 자신, 아니면 undefined다. 이걸 검사해 new 없이 호출됐으면 return new Circle(radius)처럼 재귀 호출해 생성자로 동작시킬 수 있다. IE 미지원 시 대안은 스코프 세이프 생성자 패턴(this instanceof Circle 검사).

빌트인 생성자는 대부분 new 여부를 확인해 적절히 동작한다. Object, Function은 new 없이 불러도 같고, String, Number, Boolean은 new 없이 부르면 원시 값을 반환한다(타입 변환에 쓰임).

### 생성자 함수는 new 없이 부르면 일반 함수로 동작하는데, 클래스는 왜 에러가 나나?

함수 생성자는 new 없이 호출돼도 막는 장치가 없다. `[[Call]]`이 실행되고 this는 비엄격에서 전역객체라 프로퍼티가 전역으로 새 나간다. 엄격 모드면 this가 undefined라 타입에러가 나지만, 어느 쪽이든 생성자로 쓰려던 함수가 실행된 뒤에 알게 된다.
클래스는 이 경로를 사양이 막아 놓았다. 클래스로 만든 함수는 `[[IsClassConstructor]]`가 true라서, new 없이 호출되면 본문을 실행하기 전에 타입에러를 던진다. this 바인딩도 일어나지 않는다.

### 빌트인 생성자는 new를 안 붙이면 어떻게 되나?

사양에서 각 빌트인 생성자가 new없이 호출됐을 때 뭘 하기로 정했는지가 다르다.

1. new를 붙이든 안 붙이든 결과가 같다 - Object, Function, Array, RegExp, Error

```javaScript
typeof Object() // "object" new Object()와 같은 결과
Array(3).length // 3 new Array(3)과 같은 결과
```

2. new를 안 붙이면 원시 값, 붙이면 래퍼 객체 - String, Number, Boolean
   new가 없으면 타입 변환 함수로 동작한다.

```javaScript
typeof String(1) // "string" 원시 값으로 변환
typeof new String(1) // "object" String 래퍼 객체
```

Date는 조금 다르다. new 없이 부르면 Date 객체가 아니라 현재 시각을 담은 문자열을 돌려준다.

```javaScript
typeof Date() // "string"
typeof new Date() // "object"
```

3. new를 안 붙이면 TypeError - Promise, Map, Set, WeakMap, 모든 클래스

```javaScript
Promise(()=>{}) // TypeError
Map() // TypeError
```

Symbol은 반대로 new를 붙이면 TypeError다.

```javaScript
Symbol('a') // 정상
new Symbol('a') // TypeError: Symbol is not a constructor
```
