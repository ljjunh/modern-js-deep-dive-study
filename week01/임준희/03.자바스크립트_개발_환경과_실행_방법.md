## 자바스크립트 실행 환경

- 브라우저와 Node.js 모두 자바스크립트 엔진을 내장한다. 따라서 둘 다 ECMAScript는 실행할 수 있다.
- 하지만 용도가 다르다. 브라우저는 웹페이지 렌더링이 목적이고, Node.js는 브라우저 밖에서 자바스크립트를 실행하는 것이 목적이다.
- 그래서 ECMAScript 이외의 기능은 호환되지 않는다. 브라우저는 DOM API를 제공하지만 파일 시스템은 없고, Node.js는 파일 시스템을 제공하지만 DOM은 없다.
- 브라우저에 파일 시스템이 없는 이유는 보안이다. 다운로드되어 실행되는 코드가 로컬 파일을 건드릴 수 있으면 악성 코드에 노출되는 것과 같다.

1. "Node.js는 클라이언트 사이드 Web API를 지원하지 않는다"는 책이 쓰인 시점 기준이다.
   Node 18부터 fetch가 내장됐고, AbortController, URL, Web Streams처럼 네트워크와 데이터 처리 계열 API는 이제 Node에도 들어와 있다. 여전히 없는 건 DOM이나 localStorage처럼 화면과 사용자가 전제되는 API다. 결국 책이 말한 "용도가 다르다"는 논리는 그대로 유효하고, 그 경계선이 "Web API 전부"에서 "화면에 묶인 것만"으로 좁아진 것이다.

2. Next에서 window is not defined 에러가 나는 이유가 이 절의 내용이다.
   SSR에서는 브라우저가 요청을 보내면 서버가 먼저 컴포넌트를 실행해 완성된 HTML을 만들어 보내고, 브라우저는 그 HTML을 받은 뒤 같은 컴포넌트를 다시 실행해 이벤트를 연결한다(하이드레이션). 즉 같은 컴포넌트가 Node.js에서 한 번, 브라우저에서 한 번 실행된다. 컴포넌트에서 window나 localStorage를 참조하면 Node.js 전역에는 그 객체가 없으므로 서버 쪽 실행에서 ReferenceError가 발생한다. useEffect의 콜백은 서버 렌더링 중에는 실행되지 않고 브라우저에서 화면이 그려진 뒤에만 실행되므로, 브라우저 API 접근은 그 안에 두는 것이 표준 해법이다. 이 절이 말한 "ECMAScript는 공통, 그 외 API는 환경별"이라는 구분이 컴포넌트 한개 안에서 지켜야 하는 규칙이 되는 경우다.
