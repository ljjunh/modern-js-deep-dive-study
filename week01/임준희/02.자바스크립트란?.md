## 자바스크립트와 ECMAScript

- ECMAScript는 자바스크립트의 표준 사양(ECMA-262)이다. 값, 타입, 객체, 함수, 표준 빌트인 객체 등 언어의 핵심 문법을 규정하고, 브라우저 제조사는 이 사양대로 엔진을 구현한다.
- 자바스크립트는 ECMAScript + Web API를 아우르는 말이다.
- Web API는 ECMAScript와 별개의 기구가 별도 사양으로 관리한다.

## 자바스크립트의 특징

- 브라우저에서 동작하는 유일한 프로그래밍 언어다. C, Java에서 문법을, Self에서 프로토타입 기반 상속을, Scheme에서 일급 함수를 가져왔다.
- 개발자가 컴파일하지 않는 인터프리터 언어다. 모던 엔진은 인터프리터와 컴파일러를 결합해 속도 문제를 해결했지만, 런타임에 컴파일되고 실행 파일이 생기지 않으므로 컴파일러 언어라 할 수는 없다.
- 명령형, 함수형, 프로토타입 기반 객체지향을 모두 지원하는 멀티 패러다임 언어다.

1. 인터프리터 언어인가
   저자의 기준은 실행 방식이 아니라 배포 방식이다. "개발자가 별도 컴파일을 하지 않고, 실행 파일이 생기지 않는다"는 것. 이 기준이면 지금도 맞는 말이다. ReactNative의 Hermes 엔진은 빌드 시점에 JS를 바이트코드로 미리 컴파일해서 앱에 넣고, 기기에는 소스가 배포되지 않는다. 책의 기준으로 보면 RN 안의 JS는 인터프리터 언어라고 하기 애매해진다. 저자 말대로 "구분이 모호해지는 추세"가 일어나고 있다.

2. Self에서 가져온 프로토타입 기반 상속
   Self는 1980년대에 만들어진 언어로, 클래스가 없다. 클래스에서 인스턴스를 찍어내는 대신, 살아 있는 객체가 다른 객체를 가리키고 없는 것은 그쪽에 물어본다. JS가 이 구조를 그대로 가져왔다.

   ```js
   const animal = {
     speak() {
       return `${this.name}가 소리를 낸다`;
     },
   };

   const dog = Object.create(animal);
   dog.name = "짱구";
   dog.speak(); // '짱구가 소리를 낸다'
   ```

   dog에는 speak가 없지만 프로토타입인 animal까지 따라가서 찾는다. ES6의 class Dog extends Animal도 결국 Dog.prototype이 Animal.prototype을 가리키게 만드는 문법일 뿐, 내부는 여전히 이 구조다.

3. Scheme에서 가져온 일급 함수
   Scheme은 함수를 숫자나 문자열과 똑같은 '값'으로 다룬다. 일급(first-class)이란 값이 할 수 있는 세 가지를 함수도 할 수 있다는 뜻이다.

   ```js
   const double = (x) => x * 2; // 1. 변수에 담을 수 있다
   [1, 2, 3].map(double); // 2. 인자로 넘길 수 있다
   const add = (a) => (b) => a + b; // 3. 반환값이 될 수 있다
   add(1)(2);
   ```

4. 멀티 패러다임: 같은 문제를 세 방식으로
   짝수만 골라 두 배로 만드는 문제를 세 패러다임으로 쓰면 차이가 보인다.

   ```js
   // 명령형: 어떻게 할지를 순서대로 지시한다
   const result = [];
   for (const n of nums) {
     if (n % 2 === 0) result.push(n * 2);
   }

   // 함수형: 무엇을 원하는지를 함수 조합으로 선언한다. 원본은 바뀌지 않는다
   const result = nums.filter((n) => n % 2 === 0).map((n) => n * 2);

   // 객체지향: 데이터와 행위를 한 객체에 묶는다
   class NumberList {
     constructor(nums) {
       this.nums = nums;
     }

     evens() {
       return new NumberList(this.nums.filter((n) => n % 2 === 0));
     }

     doubled() {
       return new NumberList(this.nums.map((n) => n * 2));
     }
   }

   const result = new NumberList(nums).evens().doubled().nums;
   ```

5. "자바스크립트는 클래스 기반 객체지향 언어보다 효율적이면서 강력한 프로토타입 기반의 객체지향 언어다."는 저자의 의견이다
   프로토타입이 유연한 건 사실이지만, 커뮤니티가 ES6에서 class 문법을 넣고 TS에서 널리 쓰는 걸 보면 다수는 클래스 형태의 표현을 원한 것 같다. 프로토타입이 더 강력하다는 건 논쟁이 있는 주장이고, 사실과 의견을 구분해서 읽을 부분이라고 생각한다.
