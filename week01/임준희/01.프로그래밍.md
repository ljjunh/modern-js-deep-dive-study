## 프로그래밍이란?

- 프로그래밍은 컴퓨터와의 커뮤니케이션이다. 요구사항을 기계가 실행할 수 있을 만큼 정확하고 상세하게 설명하는 일이고, 그 결과물이 코드다.
- 문제 해결 능력은 알고리즘이 아니다. 알고리즘은 도구일 뿐, 요구사항을 명확히 이해하고 분해, 정리, 순서화하는 능력이 더 상위의 능력이다.
- 컴퓨터의 관점에서 사고해야 한다. 사람과 컴퓨터는 인지 방식이 다르므로, 문제를 작은 단위로 분해하고 패턴을 추출해야 한다.
- 모든 개념은 평가 가능하게 정의해야 한다. "크다/작다"가 아니라 "볼륨을 60으로 조정해라", "걷다"가 아니라 판단할 상태, 시기, 기준을 수치로 정의한다.

1. "문제 해결 능력 !== 알고리즘"을 굳이 강조한 이유
   어려웠던 문제를 돌아보면 알고리즘이 부족해서 막힌 경우보다 요구사항을 잘못 이해하서 다시 만든 경우가 훨씬 많았다. 저자가 첫 절에서 이 문장을 굳이 넣은 건, 이 책이 문법책이 아니라 "왜 그렇게 동작하는가"를 이해하는 책이라는 선언이라고 생각한다.

2. "평가 가능하게 정의"는 요구사항 명세를 쓰는 방법과 같은 이야기다.
   "빠르게", "많으면", "에러가 나면" 같은 말은 컴퓨터가 평가할 수 없다. "응답 200ms 이하", "동시 접속 1000 이상"처럼 바꿔야 코드가 된다. 타입스크립트도 결국 값의 형태를 컴파일러가 검사할 수 있게 선언하라고 강제하는 도구다.

3. 로봇의 "걷다" 예시는 상태 머신 설계와 같다
   "판단해야 하는 상태, 판단 시기, 판단 기준"은 상태, 상태가 바뀌는 시점, 바뀌는 조건에 그대로 대응한다. API 호출을 로딩/성공/실패로 관리하는 것도 같은 구조다.

## 프로그래밍 언어

- 명령을 수행하는 주체는 컴퓨터이므로 기계어로 전달해야 한다. 하지만 기계어는 비트 단위로 기술되어 사람이 직접 쓰기엔 체계가 너무 다르다.
- 대안은 프로그래밍 언어와 번역기다. 사람이 이해할 수 있는 약속된 구문으로 작성한 뒤, 컴파일러 또는 인터프리터가 기계어로 변환한다.
- 프로그래밍 언어는 사람과 컴퓨터(컴파일러, 인터프리터) 모두가 이해할 수 있는 약속된 인공어다.
- 프로그래밍 언어는 구문과 의미의 조합으로 표현된다.

1. "JS는 인터프리터 언어다"는 정확한 말인가
   인터프리터/컴파일러는 언어가 아니라 구현(엔진)의 속성이다. V8도 인터프리터(Ignition)로 빠르게 실행을 시작하고, 자주 호출되는 핫 코드는 JIT(TurboFan)이 기계어로 최적화한다. 책의 이분법은 출발점일 뿐, 실제로는 빌드타임 트랜스파일 → 인터프리팅 → JIT 최적화까지 여러 층의 번역이 겹쳐 있다.

2. "언어 공동체 내에서 이해될 수 있는 약속"은 누가 정했는가
   자바스크립트의 약속은 ECMAScript 표준이고, TC39가 매년 개정한다. 약속이 계속 바뀌기 때문에 브라우저마다 이해하는 버전이 다르고, 그래서 폴리필과 트랜스파일이 필요하다.
   - TC39: ECMAScript 표준을 만드는 위원회

   - 트랜스파일: 새 문법을 옛 문법으로 바꾸는 것. a?.b를 지원하지 않는 브라우저를 위해 빌드 시점에 a == null ? undefined : a.b 로 바꾼다. 문법은 브라우저가 파싱조차 못하면 코드 전체가 실행이 안 되기 때문에, 실행 전에 미리 바꿔야 한다. 컴파일과 구분해서 부르는 이유는 기계어가 아니라 같은 언어의 다른 버전으로 바꾸기 때문이다.

   - 폴리필: 새 함수나 객체를 옛 브라우저에 직접 채워 넣는 것이다. Array.prototype.at이 없는 브라우저라면, 앱 코드보다 먼저 로드되는 폴리필이 at과 똑같이 동작하는 함수를 옛 문법으로 구현해서 Array.prototype에 붙여 넣는다. 이후 앱 코드가 at을 호출하면 내장 구현 대신 이 함수가 실행되고, 호출하는 쪽은 차이를 모른다. 이미 있는 브라우저에서는 검사만 하고 넘어가서 네이티브 구현을 그대로 쓴다.

   트랜스파일과 다른 점은 대상이다. 문법은 파서가 모르면 방법이 없어서 미리 바꿔 써야 하지만(트랜스파일), 함수나 객체는 런타임에 없으면 만들어 넣을 수 있다(폴리필). 그래서 트랜스파일은 빌드 시점, 폴리필은 실행 시점에 동작한다. core-js가 대표적인 폴리필 모음이고, Babel이 타겟 브라우저 설정을 보고 코드에서 실제로 쓴 API 중 폴리필이 필요한 것만 골라 import 문을 자동으로 넣어준다.

## 구문과 의미

- 문법을 안다고 언어를 잘하는 건 아니다. 문법에 맞는 문장을 만드는 것에 더해 의미가 있어야 언어 역할을 한다.
- 촘스키의 "Colorless green ideas sleep furiously"는 문법적으로 완벽하지만 의미가 없다. 코드도 같다.
  const number = 'string'은 오류가 없지만 의미적으로 틀렸다.
- 코드는 해결 방안의 구현물이다. 문법에 맞는 것은 기본이고, 요구사항이 실제로 해결되어야 의미가 있다.
- 언어가 제공하는 문법은 변수와 값, 표현식과 문, 흐름 제어, 함수, 객체와 배열이다. 결국 프로그래밍은 요구사항을 분석해 적절한
  자료구조와 함수의 집합으로 바꾸고, 그 흐름을 제어하는 것이다.
