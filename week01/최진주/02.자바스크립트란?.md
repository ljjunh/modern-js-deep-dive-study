# 2장. 자바스크립트란?

## 한눈에 보기

| | 상황 | 문제 | 해결 |
| :-: | --- | --- | --- |
| 1 | JS 등장 | 브라우저마다 동작이 다름 | **ECMAScript** 표준화 |
| 2 | 서버 렌더링 | 매번 전체 페이지를 새로 받음 | **Ajax** |
| 3 | 웹이 앱처럼 됨 | DOM 조작 번거로움, 브라우저별 차이 | **jQuery** |
| 4 | 로직이 복잡해짐 | JS가 느림 | **V8** |
| 5 | JS가 빨라짐 | 브라우저 안에서만 실행됨 | **Node.js** |
| 6 | 프론트 규모 커짐 | 코드 복잡도 증가 | **SPA 프레임워크** |
| 7 | ES6 등장 | 구형 브라우저 미지원 | **Babel**, **Webpack** |

---

### 1. 자바스크립트 등장 (1995)
넷스케이프에서 브렌던 아이크가 만든, 브라우저에서 동작하는 가벼운 언어.<br />
Mocha → LiveScript → JavaScript로 이름이 바뀜 (Java랑은 상관없음)

- **문제** 마이크로소프트가 비슷한 JScript를 IE에 넣으며 경쟁적으로 자사 브라우저에서만 동작하는 기능 추가 → 브라우저마다 동작이 달라짐 (크로스 브라우징 이슈)
- **해결** → **ECMAScript** 표준화 (1997)

| 버전 | 연도 | 기억할 것 |
| --- | --- | --- |
| ES3 | 1999 | 정규표현식, try...catch |
| ES5 | 2009 | JSON, strict mode, forEach/map/filter 등 |
| **ES6** | **2015** | let/const, 화살표 함수, 클래스, Promise, 모듈 등 대거 추가 |
| 이후 | 매년 | 조금씩 추가 |

---

### 2. 초창기: 서버가 다 그리던 시절
JS는 정적인 HTML을 거드는 정도였고, 화면은 서버가 만들어서 내려줌

- **문제** 페이지 바뀔 때마다 서버에서 HTML 전체를 다시 받아 렌더링 → 화면 깜빡임, 바뀌지 않은 부분까지 다시 그림
- **해결** → **Ajax (1999)**: 서버와 비동기로 데이터만 주고받아서 필요한 부분만 갱신
  - 구글 맵스(2005)가 이걸로 데스크톱 앱 같은 웹을 보여주면서 주목받음

---

### 3. 웹이 앱처럼 되면서
- **문제** DOM 조작이 번거롭고, 여전히 브라우저마다 차이가 있음
- **해결** → **jQuery (2006)**: DOM 조작 쉽게 + 크로스 브라우징 문제 해결

---

### 4. 브라우저에서 할 일이 많아지면서
- **문제** 웹 앱 수준의 로직을 돌리기엔 JS가 느림
- **해결** → **V8 엔진 (2008)**: 구글이 만든 빠른 JS 엔진
  - 서버에서 하던 로직이 브라우저로 넘어옴 → 프론트엔드 영역 확대

---

### 5. JS가 빨라졌는데
- **문제** JS는 브라우저 안에서만 실행 가능
- **해결** → **Node.js (2009)**: 라이언 달이 V8 기반으로 만든 런타임. 브라우저 밖에서도 실행 → 서버도 JS로 개발

---

### 6. 프론트엔드가 커지면서
- **문제** 브라우저 쪽 애플리케이션이 복잡해지고 개발 규모가 커짐
- **해결** → **SPA 프레임워크**: 컴포넌트 단위로 개발 (Angular, React, Vue 등)

---

### 7. ES6가 나왔는데
- **문제** IE 같은 구형 브라우저는 ES6를 지원 안 함
- **해결** → **Babel**로 ES5로 변환, **Webpack**으로 모듈 번들링

---

## JS vs ECMAScript
- ECMAScript = 언어 **핵심 문법** 표준
- 자바스크립트 = ECMAScript + **브라우저가 주는 Web API** (DOM, fetch, Web Storage 등)
- 그래서 `document`, `fetch` 같은 건 ECMAScript가 아님

## 특징
- 문법은 C·Java, 프로토타입 상속은 Self, 일급 함수는 Scheme에서 영향
- 인터프리터 언어지만 요즘 엔진은 컴파일러 방식도 섞어서 빠름
- 멀티 패러다임 (명령형, 함수형, 프로토타입 기반 객체지향)
- class 문법이 있어도 본질은 **프로토타입 기반**
