# 23 실행 컨텍스트

## 23.1 소스코드의 타입

- 4가지 타입의 소스코드는 실행 컨텍스트를 생성

| 구분      | 포함                                                             | 미포함                                         |
| --------- | ---------------------------------------------------------------- | ---------------------------------------------- |
| 전역 코드 | 전역에 존재하는 소스 코드                                        | 전역에 정의된 함수, 클래스 등의 내부 코드      |
| 함수 코드 | 함수 내부에 존재하는 소스 코드                                   | 함수 내부에 중첩된 함수, 클래스 등의 내부 코드 |
| eval 코드 | eval 함수(빌트인 전역 함수)에 인수로 전달되어 실행되는 소스 코드 |
| 모듈 코드 | 모듈 내부에 존재하는 소스 코드                                   | 모듈 내부의 함수, 클래스 등의 내부 코드        |

## 23.2 소스코드의 평가와 실행

- **소스코드의 평가**
  - 실행 컨텍스트를 생성
  - 변수, 함수 등의 선언문만 먼저 실행
  - 생성된 변수나 함수 식별자를 키로 실행 컨텍스트가 관리하는 스코프(렉시컬 환경의 환경 레코드)에 등록
- **소스코드의 실행**
  - 런타임 시작(선언문을 제외한 소스코드를 순차적으로 실행)
  - 소스코드 실행에 필요한 정보(변수나 함수의 참조)를 실행 컨텍스트가 관리하는 스코프에서 검색해서 취득
  - 변수 값의 변경 등 소스코드의 실행 결과는 다시 실행 컨텍스트가 관리하는 스코프에 등록

## 23.3 실행 컨텍스트의 역할

- 식별자(변수, 함수, 클래스 등의 이름)를 등록하고 관리하는 스코프와 코드 실행 순서 관리를 구현한 내부 메커니즘으로, 모든 코드는 실행 컨텍스트를 통해 실행되고 관리
  - 식별자와 스코프는 실행 컨텍스트의 렉시컬 환경으로 관리
  - 코드 실행 순서는 실행 컨텍스트 스택으로 관리

## 23.4 실행 컨텍스트 스택

- 코드의 실행 순서 관리
- 스택의 최상위에는 현재 실행 중인 코드의 실행 컨텍스트(running execution context)가 있다.

```javascript
// #1 전역 실행 컨텍스트 push
const x = 1;

function foo() {
  const y = 2;

  function bar() {
    const z = 3;
    console.log(x + y + z);
  }
  bar(); // #3 bar 함수 실행 컨텍스트 push
  // #4 bar 함수 실행 컨텍스트 pop
}

foo(); // #2 foo 함수 실행 컨텍스트 push (출력: 6)
// #5 foo 함수 실행 컨텍스트 pop
// #6 전역 실행 컨텍스트 pop
```

## 23.5 렉시컬 환경

- 식별자와 식별자에 바인딩된 값, 그리고 상위 스코프에 대한 참조를 기록하는 자료구조로 실행 컨텍스트를 구성하는 컴포넌트
  - 스코프와 식별자를 관리

> 실행 컨텍스트 = LexicalEnvironment 컴포넌트 + VariableEnvironment 컴포넌트<br/>생성 초기에는 LexicalEnvironment와 VariableEnvironment는 동일한 렉시컬 환경 참조, 이후 몇 가지 상황을 만나면 VariableEnvironment 컴포넌트를 위한 새로운 렉시컬 환경을 생성하고, LexicalEnvironment와 VariableEnvironment의 내용이 달라지는 경우가 있음

- 렉시컬 환경 = 환경 레코드 + 외부 렉시컬 환경에 대한 참조
  - 환경 레코드(Environment Record): 스코프에 포함된 식별자 등록, 등록된 식별자에 바인딩된 값을 관리하는 저장소
  - 외부 렉시컬 환경에 대한 참조(Outer Lexical Environment Reference): 상위 스코프(실행 컨텍스트를 생성한 소스코드를 포함하는 상위 코드의 렉시컬 환경)를 가리킴.

[《코어 자바스크립트》 2장 요약](https://woodstock.hashnode.dev/1-1-1) · [《모던 자바스크립트 Deep Dive》 23장 요약](https://useyhnha.tistory.com/entry/모던-자바스크립트-Deep-Dive-23장-실행-컨텍스트)

- `LexicalEnvironment`는 변수 이름을 어디서부터 찾을지 정한다.
- `VariableEnvironment`는 `var` 선언의 바인딩이 속한 환경을 가리킨다.

```js
function example() {
  "use strict";
  var count = 1;

  {
    let step = 2;
    count += step;
  }

  console.log(count); // 3
}

example();
```

블록에 들어가면 변수 이름을 블록부터 찾는다. `step`은 블록에서 찾고, `count`는 바깥 함수 환경에서 찾는다. `VariableEnvironment`는 계속 같은 함수 환경을 가리키고, 그 안의 `count` 값은 1에서 3으로 바뀐다. [블록 평가](https://tc39.es/ecma262/2026/multipage/ecmascript-language-statements-and-declarations.html#sec-block-runtime-semantics-evaluation)

`function example(n = 1) { /* ... */ }`처럼 기본값 매개변수가 있으면, 본문을 실행하기 전에 본문의 `var` 선언을 위한 별도 환경을 만든다. 이때는 `VariableEnvironment`가 가리키는 환경 자체가 바뀐다. [함수 선언 초기화](https://tc39.es/ecma262/2026/multipage/ordinary-and-exotic-objects-behaviours.html#sec-functiondeclarationinstantiation)


### 왜 두 책의 설명이 다를까?

‘VariableEnvironment가 바뀌지 않는다’와 ‘특정 상황에서 새 환경을 가리킨다’는 설명은 서로 차이가 있다. 실제 명세도 버전에 따라 달라졌다.

| 명세 | 확인한 내용 |
| --- | --- |
| ES5.1 (2011), §10.3 | 두 항목은 처음에 같은 환경을 가리킨다. 이후 VariableEnvironment는 그대로이고 LexicalEnvironment는 바뀔 수 있다고 명시한다. |
| ES2015 (2015), §9.2.12 | 매개변수에 기본값 등의 표현식이 있으면 본문의 var를 위한 새 환경을 만들고 VariableEnvironment를 다시 설정한다. |
| ES2026, §10.2.11 | 매개변수와 본문의 var 환경을 분리하고 VariableEnvironment를 다시 설정하는 절차가 유지된다. |

[ES5.1 실행 컨텍스트](https://262.ecma-international.org/5.1/#sec-10.3) · [ES2015 함수 선언 초기화](https://262.ecma-international.org/6.0/#sec-functiondeclarationinstantiation) · [ES2026 함수 선언 초기화](https://tc39.es/ecma262/2026/multipage/ordinary-and-exotic-objects-behaviours.html#sec-functiondeclarationinstantiation)

코어의 해당 부분 하단에는 ES5를 설명하는 Dmitry Soshnikov의 글이 참고 자료로 제시되어 있다(책의 참고 링크는 독자가 제공). 이 글은 2011년에 작성되었고, with와 catch를 실행하는 동안 LexicalEnvironment를 다른 환경으로 바꾸는 ES5 모델을 설명한다. 따라서 코어의 설명을 이해할 때는 이 ES5 문맥을 함께 봐야 한다. ES2015 이후의 기본값 매개변수까지 포함하면 VariableEnvironment도 새 환경을 가리킬 수 있다. [코어가 참고한 ES5 해설](https://dmitrysoshnikov.com/ecmascript/es5-chapter-3-2-lexical-environments-ecmascript-implementation/)

참고 글에는 LexicalEnvironment를 VariableEnvironment의 복사본으로 표현하는 의사 코드도 있다. ES5.1 명세는 두 항목에 같은 환경을 설정한다. 따라서 이 복사 표현을 환경 안의 변수 값까지 별도로 복제해 보관한다는 뜻으로 읽으면 혼동할 수 있다. [ES5.1 함수 컨텍스트 진입](https://262.ecma-international.org/5.1/#sec-10.4.3)

환경을 나누는 이유는 다음 예시에서 볼 수 있다.

```js
var value = "바깥";

function example(read = () => value) {
  var value = "함수 본문";
  console.log(read()); // 바깥
}

example();
```

read 함수는 매개변수 기본값을 처리할 때 만들어진다. 이 함수가 본문의 var value를 볼 수 없도록 매개변수 환경과 본문의 var 환경을 나눈다. 그래서 read()는 바깥의 value를 읽는다. 이 과정에서 VariableEnvironment가 본문의 var 환경을 가리키도록 바뀐다. [ES2026 함수 선언 초기화](https://tc39.es/ecma262/2026/multipage/ordinary-and-exotic-objects-behaviours.html#sec-functiondeclarationinstantiation)

## 23.6 실행 컨텍스트의 생성과 식별자 검색 과정

```javascript
var x = 1;
const y = 2;

function foo(a) {
  var x = 3;
  const y = 4;

  function bar(b) {
    const z = 5;
    console.log(a + b + x + y + z);
  }
  bar(10);
}

foo(20); // 42
```

### 전역 객체 생성

- 빌트인 전역 프로퍼티, 빌트인 전역 함수, 표준 빌트인 객체, 호스트 객체를 포함
- Object.prototype 상속, 프로토타입 체인의 일원

### 전역 코드 평가

- 전역 실행 컨텍스트(Global Execution Context) 생성
- 전역 렉시컬 환경(Global Lexical Environment) 생성
  - 전역 환경 레코드(Global Environment Record) 생성: 전역 변수를 관리하는 전역 스코프, 전역 객체의 빌트인 전역 프로퍼티, 빌트인 전역 함수, 표준 빌트인 객체 제공
    - 객체 환경 레코드(Object Environment Record) 생성: var 키워드로 선언한 전역 변수, 함수 선언문으로 정의한 전역 함수, 빌트인 전역 프로퍼티, 빌트인 전역 함수, 표준 빌트인 객체
    - 선언적 환경 레코드(Declarative Environment Record) 생성: let, const 키워드로 선언한 전역 변수
  - this 바인딩: 전역 환경 레코드의 [[GlobalThisValue]] 내부 슬롯
  - 외부 렉시컬 환경에 대한 참조 결정

> 전역 코드 평가 과정에서 var 키워드로 선언한 전역 변수와 함수 선언문으로 정의된 전역 함수는 전역 환경 레코드의 객체 환경 레코드에 연결된 **BindingObject**를 통해 전역 객체의 프로퍼티와 메서드가 된다.(전역 객체를 가리키는 식별자 없이 전역 객체의 프로퍼티를 참조할 수 있는 매커니즘)

### 코드 실행과 함수 호출

- 실행 중에는 필요한 변수나 함수의 식별자를 검색한다(식별자 결정).
- 전역 코드에서 `foo`를 호출하면 `foo`의 코드를 평가한 뒤 실행한다. `foo`에서 `bar`를 호출할 때도 같은 순서를 따른다.
- 함수 코드를 평가할 때 함수 실행 컨텍스트와 렉시컬 환경을 생성한다.
  - 함수 환경 레코드에 매개변수, `arguments` 객체, 지역 변수, 중첩 함수를 등록한다.
  - 함수 환경 레코드의 `[[ThisValue]]` 내부 슬롯에 `this`를 바인딩한다.
  - 외부 렉시컬 환경에 대한 참조를 결정한다.

### 코드 실행 종료

- `bar`, `foo`, 전역 코드의 실행이 끝나는 순서대로 각 실행 컨텍스트를 스택에서 제거한다.
- 렉시컬 환경에 대한 참조가 남아 있으면 실행 컨텍스트가 스택에서 제거된 뒤에도 그 환경은 유지된다.

## 23.7 실행 컨텍스트와 블록 레벨 스코프

- var 키워드로 선언한 변수는 함수 레벨 스코프
  - 함수의 코드 블록만 지역 스코프로 인정
- let, const 키워드로 선언한 변수는 블록 레벨 스코프
  - 모든 코드 블록(함수, if 문, for 문, while 문, try/catch 문)을 지역 스코프로 인정

### for 문의 변수 선언문에 let 키워드를 사용하면

- `for (let i = …)`는 반복마다 새 렉시컬 환경을 만든다.
- 반복문 내에서 정의된 함수의 상위 스코프는 코드 블록이 생성한 렉시컬 환경
- 함수의 상위 스코프는 반복마다 식별자(for 문의 변수 선언문, for 문의 코드 블록 내에서 선언된 지역 변수)의 값을 유지
