# 23 실행 컨텍스트

## 23.1 소스코드의 타입

- 4가지 타입의 소스코드는 실행 컨텍스트를 생성

| 구분      | 포함                                                             | 미포함                                         |
| --------- | ---------------------------------------------------------------- | ---------------------------------------------- |
| 전역 코드 | 전역에 존재하는 소스 코드                                        | 전역에 정의된 함수, 클래스 등의 내부 코드      |
| 함수 코드 | 함수 내부에 존재하는 소스 코드                                   | 함수 내부에 중첩된 함수, 클래스 등의 내부 코드 |
| eval 코드 | eval 함수(빌트인 전역 함수)에 인수로 전달되어 실행되는 소스 코드 |
| 모듈 코드 | 모듈 내부에 존재하는 소스 코드                                   | 모듈 내부의 함수, 클래스 등의 내부 코드        |

## 23.2 소스코드의 평가와 실행

- **소스코드의 평가**
  - 실행 컨텍스트를 생성
  - 변수, 함수 등의 선언문만 먼저 실행
  - 생성된 변수나 함수 식별자를 키로 실행 컨텍스트가 관리하는 스코프(렉시컬 환경의 환경 레코드)에 등록
- **소스코드의 실행**
  - 런타임 시작(선언문을 제외한 소스코드를 순차적으로 실행)
  - 소스코드 실행에 필요한 정보(변수나 함수의 참조)를 실행 컨텍스트가 관리하는 스코프에서 검색해서 취득
  - 변수 값의 변경 등 소스코드의 실행 결과는 다시 실행 컨텍스트가 관리하는 스코프에 등록

## 23.3 실행 컨텍스트의 역할

- 식별자(변수, 함수, 클래스 등의 이름)를 등록하고 관리하는 스코프와 코드 실행 순서 관리를 구현한 내부 메커니즘으로, 모든 코드는 실행 컨텍스트를 통해 실행되고 관리
  - 식별자와 스코프는 실행 컨텍스트의 렉시컬 환경으로 관리
  - 코드 실행 순서는 실행 컨텍스트 스택으로 관리

## 23.4 실행 컨텍스트 스택

- 코드의 실행 순서 관리
- 스택의 최상위에는 현재 실행 중인 코드의 실행 컨텍스트(running execution context)가 있다.

```javascript
// #1 전역 실행 컨텍스트 push
const x = 1;

function foo() {
  const y = 2;

  function bar() {
    const z = 3;
    console.log(x + y + z);
  }
  bar(); // #3 bar 함수 실행 컨텍스트 push
  // #4 bar 함수 실행 컨텍스트 pop
}

foo(); // #2 foo 함수 실행 컨텍스트 push (출력: 6)
// #5 foo 함수 실행 컨텍스트 pop
// #6 전역 실행 컨텍스트 pop
```

## 23.5 렉시컬 환경

- 식별자와 식별자에 바인딩된 값, 그리고 상위 스코프에 대한 참조를 기록하는 자료구조로 실행 컨텍스트를 구성하는 컴포넌트
  - 스코프와 식별자를 관리

> 실행 컨텍스트 = LexicalEnvironment 컴포넌트 + VariableEnvironment 컴포넌트<br/>생성 초기에는 LexicalEnvironment와 VariableEnvironment는 동일한 렉시컬 환경 참조, 이후 몇 가지 상황을 만나면 VariableEnvironment 컴포넌트를 위한 새로운 렉시컬 환경을 생성하고, 내용이 달라지는 경우가 있음

- 렉시컬 환경 = 환경 레코드 + 외부 렉시컬 환경에 대한 참조
  - 환경 레코드(Environment Record): 스코프에 포함된 식별자 등록, 등록된 식별자에 바인딩된 값을 관리하는 저장소
  - 외부 렉시컬 환경에 대한 참조(Outer Lexical Environment Reference): 상위 스코프(실행 컨텍스트를 생성한 소스코드를 포함하는 상위 코드의 렉시컬 환경)를 가리킴.

## 23.6 실행 컨텍스트의 생성과 식별자 검색 과정

```javascript
var x = 1;
const y = 2;

function foo(a) {
  var x = 3;
  const y = 4;

  function bar(b) {
    const z = 5;
    console.log(a + b + x + y + z);
  }
  bar(10);
}

foo(20); // 42
```

### 전역 객체 생성

- 빌트인 전역 프로퍼티, 빌트인 전역 함수, 표준 빌트인 객체, 호스트 객체를 포함
- Object.prototype 상속, 프로토타입 체인의 일원

### 전역 코드 평가

- 전역 실행 컨텍스트(Global Execution Context) 생성
- 전역 렉시컬 환경(Global Lexical Environment) 생성
  - 전역 환경 레코드(Global Environment Record) 생성: 전역 변수를 관리하는 전역 스코프, 전역 객체의 빌트인 전역 프로퍼티, 빌트인 전역 함수, 표준 빌트인 객체 제공
    - 객체 환경 레코드(Object Environment Record) 생성: var 키워드로 선언한 전역 변수, 함수 선언문으로 정의한 전역 함수, 빌트인 전역 프로퍼티, 빌트인 전역 함수, 표준 빌트인 객체
    - 선언적 환경 레코드(Declarative Environment Record) 생성: let, const 키워드로 선언한 전역 변수
  - this 바인딩: 전역 환경 레코드의 [[GlobalThisValue]] 내부 슬롯
  - 외부 렉시컬 환경에 대한 참조 결정

> 전역 코드 평가 과정에서 var 키워드로 선언한 전역 변수와 함수 선언문으로 정의된 전역 함수는 전역 환경 레코드의 객체 환경 레코드에 연결된 **BindingObject**를 통해 전역 객체의 프로퍼티와 메서드가 된다.(전역 객체를 가리키는 식별자 없이 전역 객체의 프로퍼티를 참조할 수 있는 매커니즘)

### 코드 실행과 함수 호출

- 실행 중에는 필요한 변수나 함수의 식별자를 검색한다(식별자 결정).
- 전역 코드에서 `foo`를 호출하면 `foo`의 코드를 평가한 뒤 실행한다. `foo`에서 `bar`를 호출할 때도 같은 순서를 따른다.
- 함수 코드를 평가할 때 함수 실행 컨텍스트와 렉시컬 환경을 생성한다.
  - 함수 환경 레코드에 매개변수, `arguments` 객체, 지역 변수, 중첩 함수를 등록한다.
  - 함수 환경 레코드의 `[[ThisValue]]` 내부 슬롯에 `this`를 바인딩한다.
  - 외부 렉시컬 환경에 대한 참조를 결정한다.

### 코드 실행 종료

- `bar`, `foo`, 전역 코드의 실행이 끝나는 순서대로 각 실행 컨텍스트를 스택에서 제거한다.
- 렉시컬 환경에 대한 참조가 남아 있으면 실행 컨텍스트가 스택에서 제거된 뒤에도 그 환경은 유지된다.

## 23.7 실행 컨텍스트와 블록 레벨 스코프

- var 키워드로 선언한 변수는 함수 레벨 스코프
  - 함수의 코드 블록만 지역 스코프로 인정
- let, const 키워드로 선언한 변수는 블록 레벨 스코프
  - 모든 코드 블록(함수, if 문, for 문, while 문, try/catch 문)을 지역 스코프로 인정

### for 문의 변수 선언문에 let 키워드를 사용하면

- `for (let i = …)`는 반복마다 새 렉시컬 환경을 만든다.
- 반복문 내에서 정의된 함수의 상위 스코프는 코드 블록이 생성한 렉시컬 환경
- 함수의 상위 스코프는 반복마다 식별자(for 문의 변수 선언문, for 문의 코드 블록 내에서 선언된 지역 변수)의 값을 유지
