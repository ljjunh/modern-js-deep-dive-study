# 24 클로저

- "A closure is the combination of a function and the lexical environment within which that function was declared."
  - 클로저는 함수와 그 **함수가 선언된 렉시컬 환경**과의 조합(MDN)

## 24.1 렉시컬 스코프

- 렉시컬 스코프(정적 스코프)에서는 함수가 정의된 위치에 따라 상위 스코프가 결정된다.

## 24.2 함수 객체의 내부 슬롯 [[Environment]]

- 함수 정의가 평가되어 **함수 객체가 생성될 때**, 현재 실행 중인 실행 컨텍스트의 렉시컬 환경에 대한 참조를 내부 슬롯 `[[Environment]]`에 저장한다. 함수 객체는 자신이 존재하는 한 이 참조를 통해 상위 스코프를 기억한다.
- **함수를 호출하면** 새 함수 렉시컬 환경이 생성된다. 이 환경의 ‘외부 렉시컬 환경에 대한 참조’에 `[[Environment]]`에 저장된 참조를 할당한다.

## 24.3 클로저와 렉시컬 환경

- 외부 함수의 실행이 끝나면 그 실행 컨텍스트는 스택에서 제거된다. 중첩 함수가 `[[Environment]]`를 통해 외부 함수의 렉시컬 환경을 계속 참조하면 그 환경은 유지된다.
- **중첩 함수가 외부 함수보다 오래 유지되면**, 외부 함수의 실행이 끝난 뒤에도 상위 스코프의 변수를 참조할 수 있다. 외부 함수가 중첩 함수를 반환하는 경우가 클로저의 대표적인 예다.
- 클로저가 참조하는 상위 스코프의 변수를 **자유 변수(free variable)**라고 한다. 클로저라는 이름은 함수가 자유 변수에 대해 닫혀 있다는 뜻이다.

## 24.4 클로저의 활용

### 상태 은닉과 공유

- `increase`와 `decrease`는 같은 `count`를 참조한다. 외부에서는 이 메서드를 통해 상태를 변경한다.
- `makeCounter()`를 호출할 때마다 별도의 렉시컬 환경이 생성되어 각 카운터의 상태가 독립적으로 유지된다.

```javascript
function makeCounter() {
  let count = 0;

  return {
    increase() {
      return ++count;
    },
    decrease() {
      return count > 0 ? --count : 0;
    },
  };
}

const first = makeCounter();
const second = makeCounter();

console.log(first.increase()); // 1
console.log(first.increase()); // 2
console.log(first.decrease()); // 1
console.log(second.increase()); // 1
```

### 상태 변경 규칙을 보조 함수로 전달

- `createCounter`는 호출이 끝난 뒤에도 `count`를 기억하는 함수를 반환하는 고차 함수다.
- 함수형 프로그래밍에서는 불변성을 지향하고 부수 효과를 줄이기 위해 값의 계산과 상태 갱신을 분리할 수 있다.
- 이 예제에서 `increase`, `decrease`, `reset`은 상태를 직접 변경하지 않고 다음 값을 반환하는 순수 함수다. 클로저인 `updateCount`가 보조 함수에 현재 값을 전달하고 그 결과로 내부 상태 `count`를 갱신한다.

```javascript
function createCounter() {
  let count = 0;

  return function (update) {
    count = update(count);
    return count;
  };
}

const updateCount = createCounter();
const increase = (count) => count + 1;
const decrease = (count) => Math.max(0, count - 1);
const reset = () => 0;

console.log(updateCount(increase)); // 1
console.log(updateCount(increase)); // 2
console.log(updateCount(decrease)); // 1
console.log(updateCount(reset)); // 0
```

## 24.5 캡슐화와 정보 은닉

- 캡슐화는 객체의 상태를 나타내는 프로퍼티와 프로퍼티를 참조하고 조작할 수 있는 동작인 메서드를 하나로 묶는 것
- 캡슐화는 객체의 특정 프로퍼티나 메서드를 감출 목적으로 사용하기도 하는데 이를 정보 은닉이라 한다.
  - 정보를 보호, 결합도(객체 간의 상호 의존성)를 낮추는 효과

- 자바스크립트는 public, private, protected 같은 접근 제한자를 제공하지 않음
  - 자바스크립트 객체의 모든 프로퍼티와 메서드는 기본적으로 public

- 자바스크립트는 정보 은닉을 완전하게 지원하지 않음.
  - 인스턴스 메서드를 사용하면 자유 변수를 통해 private를 흉내 낼 수는 있지만 프로토타입 메서드를 사용하면 이마저도 불가능
  - ES6의 Symbol 또는 WeakMap을 사용하여 private한 프로퍼티를 흉내 내기도 하지만 근본적인 해결책이 되지는 않는다.
  - 다행히도 TC39 프로세스의 stage 3(candidate)에는 클래스에 private 필드를 정의할 수 있는 새로운 표준 사양이 제안

## 24.6 자주 발생하는 실수

- for 문의 변수 선언문에서 var 키워드로 선언한 i 변수는 블록 레벨 스코프가 아닌 함수 레벨 스코프를 갖기 때문에 전역 변수
  - ES6의 let 키워드 사용
    - for 문의 코드 블록이 반복 실행될 때마다 새로운 렉시컬 환경 생성
  - 함수형 프로그래밍 기법인 고차 함수를 사용
    - 변수와 반복문의 사용을 억제할 수 있기 때문에 오류를 줄이고 가독성을 좋게 만든다.
