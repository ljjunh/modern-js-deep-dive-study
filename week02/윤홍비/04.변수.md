## 메모리의 구조

- CPU는 연산을, 메모리는 데이터 저장을 담당한다.
- 메모리는 데이터를 저장할 수 있는 메모리 셀(memory cell)의 집합체다.
- 메모리셸의 하나의 크기는 1byte(8비트)이다. 컴퓨터는 메모리 셸의 크기 (1byte) 단위로 데이터를 저장하거나 읽어들인다.
  - 만일 1byte보다 저장해야할 데이터가 크다면 필요한 셸 갯수만큼 늘려서 저장한다. 만약 저장할 데이터가 2byte라면 두개의 셸을 사용한다.
  - 각 셸은 하나의 주소를 가지고 있다. 만약 하나의 데이터지만 연속된 셸을 사용한다면 맨 앞의 셸의 주소를 통해 CPU는 값에 접근한다.
- 메모리에 저장되는 값은 모두 2진수로 저장된다.

## 변수가 필요한 이유

- 개발자가 직접 메모리 주소를 접근하면 치명적인 오류를 발생 시킬 수 있다.
- 또한 값이 저장될 메모리 주소는 실행할 때마다 달라지므로 개발자가 미리 알 수 없다.
- 그래서 자바스크립트는 메모리 주소에 대한 직접 접근을 허용하지 않는다.
  - 대신 변수를 사용해 값을 저장하고 참조한다.
  - 변수: 하나의 값을 저장하기 위해 확보한 메모리 공간, 또는 그 공간을 식별하기 위해 붙인 이름
- 변수는 컴파일러나 인터프리터에 의해 값이 저장된 메모리 주소로 치환되어 실행된다.

## 변수 선언과 호이스팅

- 변수가 호이스팅 된다는 것은 런타임 이전에 자바스크립트 엔진이 소스코드 평가 과정에서 선언된 변수, 함수 등을 소스코드에서 찾아내 먼저 실행하는 것을 뜻한다.
- 변수 선언은 호이스팅 단계에서 실행되고, 런타임 단계에서는 선언문을 제외하고 실행한다.
- var로 선언한 변수는 이 단계에서 undefined로 초기화된다.

## 값의 할당과 원시 값의 불변성

- 변수에 원시 값을 할당하면, 기존 undefined가 저장된 메모리 공간을 덮어쓰지 않는다.
- 새로운 메모리 공간에 값을 저장하고, 변수는 그 새 주소를 가리키도록 변경된다.
- 이렇게 동작하는 이유는 **원시 값이 불변(immutable)** 하기 때문이다.
- 불변이기 때문에 같은 원시 값을 여러 변수가 하나의 메모리 공간을 공유하도록 최적화할 수도 있다. (실제 공유 여부는 엔진 구현에 따라 다름)
