# 모던 자바스크립트 Deep Dive 6장 - 데이터 타입

## 1. 데이터 타입이란

- 값의 종류
- 타입에 따라 메모리 저장 방식, 읽는 방식 결정

| 구분 | 타입 | 설명 |
|---|---|---|
| 원시 타입 | number | 숫자, 정수/실수 구분 없음 |
| | string | 문자열 |
| | boolean | true / false |
| | undefined | 값 미할당 상태 |
| | null | 의도적인 값 없음 표현 |
| | symbol | 중복 불가능한 유일한 값 (ES6) |
| | bigint | 아주 큰 정수 (ES2020, 책 이후 추가) |
| 객체 타입 | object | 원시 타입 외 전부, 배열/함수 포함 |

- 책 기준 7개(ES6), 현재 bigint 포함 8개

## 2. 숫자 타입

- 숫자 타입은 number 하나뿐 (타 언어는 int, float, long 등으로 구분)
- 모든 숫자를 64비트 부동소수점(실수)으로 저장
- 정수 타입 없음, `1`도 내부적으로 실수

```js
console.log(1 === 1.0); // true
```

- 특별한 값 3가지

```js
10 / 0;     // Infinity
-10 / 0;    // -Infinity
1 * 'abc';  // NaN (계산 불가 결과)
```

- NaN은 자기 자신과도 불일치, `Number.isNaN()`으로 체크

```js
const price = Number('만원');

price === NaN;        // false, 잘못된 체크
Number.isNaN(price);  // true
```

## 3. 문자열과 템플릿 리터럴

- `'`, `"`, `` ` `` 로 감싸서 생성
- 감싸는 이유: 변수 이름, 키워드와 구분
- 템플릿 리터럴(백틱) 장점
  - 줄바꿈 그대로 입력 가능
  - `${}`로 변수, 표현식 삽입 가능

```js
const name = '진주';
const amount = 15000;

// 이어붙이기: 가독성 낮음, 공백 누락 위험
const msg1 = name + '님, ' + amount + '원 결제 완료';

// 템플릿 리터럴
const msg2 = `${name}님, ${amount}원 결제 완료`;
```

## 4. undefined와 null

| | undefined | null |
|---|---|---|
| 할당 주체 | 자바스크립트 엔진 | 개발자 |
| 상황 | 변수 선언 후 값 미할당 | 값 없음을 의도적으로 표현 |

- undefined 직접 할당 비권장 (엔진 할당과 구분 불가)

```js
let a;
console.log(a); // undefined, 엔진이 할당

let selectedCard = undefined; // 비권장
let selectedCard2 = null;     // 권장, "선택 안 됨" 표현
```

- null 반환 대표 사례

```js
document.querySelector('.없는-클래스'); // null
```

## 5. 데이터 타입이 필요한 이유

- 메모리 = 1바이트 칸이 늘어선 사물함
- 변수는 값의 시작 주소만 기억

```
주소:  100  101  102  103  104  105  106  107
      [          숫자 값 8칸 (64비트)          ]
       ↑ 변수는 시작 주소만 기억
```

- 저장: 값에 맞는 메모리 공간 확보 (숫자는 8바이트)
- 읽기: 시작 주소부터 읽을 바이트 수 결정
- 해석: 2진수를 숫자로 볼지 문자로 볼지 결정
- 예시: `01000001` → 숫자면 65, 문자면 'A'
- 참고: 개념 모델, 실제 엔진은 더 복잡하게 최적화

## 6. 동적 타이핑

- 정적 타입 언어(Java, C): 선언 시 타입 지정, 다른 타입 할당 불가
- 동적 타입 언어(자바스크립트): 변수에 타입 없음, 값에 타입 있음
- 재할당 시 변수가 가리키는 값의 타입도 변경

```js
let x = 10;
console.log(typeof x); // "number"

x = '10';
console.log(typeof x); // "string", 에러 없음
```

### 단점

- 값의 타입 변화 추적 어려움
- 실행 전까지 에러 발견 불가

### 단점을 줄이는 습관

- 변수는 필요한 만큼만 선언
- 스코프 최소화
- 전역 변수 지양
- 변하지 않는 값은 `const` 사용
- 목적이 드러나는 변수명 사용

### TypeScript 연결

- 변수에 타입 지정, 코드 작성 단계에서 타입 에러 확인
- 한계: 컴파일 후 타입 정보 제거, 런타임 검사 없음
- API 응답 등 외부 데이터는 zod 등으로 런타임 검증 필요

## 7. 실무 사례

### 금액 계산

- 부동소수점 특성상 소수 계산 오차 발생

```js
0.1 + 0.2; // 0.30000000000000004
```

- 원인: 0.1을 2진수로 정확히 표현 불가, 근사값 저장
- 할인율, 적립률, 환율 계산에서 문제 발생 가능
- 해결 방법
  - 정수끼리 곱한 뒤 나누기
  - 소수 중심 계산(환율, 이자)은 decimal.js 등 라이브러리 사용
  - 반올림은 계산 마지막에 정책대로 1회만

```js
const discount = (9900 * 10) / 100; // 990
```

### input 값은 항상 문자열

- `type="number"`여도 value는 문자열
- 수량, 금액 입력 시 숫자 변환 + NaN 체크 필수

```js
input.value;             // "3"
input.value + 1;         // "31"
Number(input.value) + 1; // 4
```

### API 응답의 null과 undefined

- 쿠폰 필드 `null`: 쿠폰 없음 → "사용 가능한 쿠폰 없음" 노출
- 쿠폰 필드 없음(`undefined`): 데이터 미수신 또는 응답 이상 가능성
- 두 경우 구분해야 빈 상태 화면 정확히 처리 가능
