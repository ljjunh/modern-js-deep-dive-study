# 5장. 표현식과 문

## 1. 표현식과 문이란

- 표현식: 값으로 평가될 수 있는 코드
- 문: 프로그램을 구성하는 최소 실행 단위, 컴퓨터에 내리는 명령
- 둘은 별개가 아닌 포함 관계, 표현식도 문의 한 종류
```
┌──────────── 문 ───────────────┐
│  ┌─ 표현식인 문 ─┐              │
│  │ x = 3        │  var x;    │
│  │ 1 + 2        │  if (...)  │
│  │ foo()        │  for (...) │
│  └──────────────┘            │
└──────────────────────────────┘
```
 
---

## 2. 값

- 표현식이 평가되어 나온 결과
- 평가: 식을 해석해 값을 만들거나 참조하는 과정
- 모든 값은 데이터 타입을 가지며 메모리에 2진수로 저장
- 변수에 저장되는 것은 식이 아닌 평가 결과값
```js
var sum = 10 + 20; // sum에 저장되는 것은 식이 아닌 30
```

### undefined와 null도 값

- "값 없음"을 나타내는 것 역시 값
- 각각 자기만의 타입을 가진 원시 값, 타입당 값이 하나뿐

  | | undefined | null |
  |---|---|---|
  | 할당 주체 | 자바스크립트 엔진 | 개발자 |
  | 의미 | 아직 아무것도 할당 안 됨 | 값 없음을 의도적으로 명시 |
  | 예시 | `var x;` | `let coupon = null;` |

- `typeof null`의 결과는 `"object"`, 초기 설계 버그가 호환성 때문에 유지된 것
- null 확인은 `x === null`로 처리
---

## 3. 리터럴

- 사람이 이해할 수 있는 문자나 약속된 기호로 값을 직접 적어 생성하는 표기법
- 엔진이 런타임에 평가해 값 생성
- 숫자·문자열뿐 아니라 객체, 배열, 함수도 리터럴

  | 종류 | 예시 |
  |---|---|
  | 정수 / 부동소수점 | `100`, `10.5` |
  | 2진수 / 8진수 / 16진수 | `0b01000001`, `0o101`, `0x41` |
  | 문자열 | `'Hello'` |
  | 불리언 | `true`, `false` |
  | null / undefined | `null`, `undefined` |
  | 객체 | `{ name: 'Lee' }` |
  | 배열 | `[1, 2, 3]` |
  | 함수 | `function () {}` |
  | 정규 표현식 | `/[A-Z]+/g` |
  | 템플릿 | `` `Hello ${name}` `` |

---

## 4. 표현식

- 값으로 평가될 수 있는 문
- 리터럴은 값으로 평가되므로 그 자체로 표현식
```js
100;               // 리터럴 표현식
50 + 50;           // 연산자 표현식
score;             // 식별자 표현식 (변수 참조)
person.name;       // 식별자 표현식 (프로퍼티 참조)
square();          // 함수 호출 표현식
person.getName();  // 메서드 호출 표현식
```

### 표현식과 값은 동등

- 엔진은 표현식을 먼저 값으로 평가한 뒤 사용
- 따라서 값이 올 수 있는 자리에는 표현식도 올 수 있음
```js
const price = 1000;
const qty = 3;
 
const total = price * qty;           // 할당 우항
console.log(price * qty);            // 함수 인자
const arr = [price, price * 2];      // 배열 요소
`결제금액: ${price * qty}원`;          // 템플릿 리터럴, "결제금액: 3000원"
```

- 표현식은 중첩 가능, 안쪽부터 차례로 값으로 평가
```js
Math.max(price, 500) + 100; // 1000 + 100 → 1100
```

- 표현식이 아닌 문은 값 자리에 올 수 없음
```js
const a = if (price > 0) { 1 };   // SyntaxError, if문은 값이 없음
const a = price > 0 ? 1 : 0;      // 삼항 연산자는 표현식이므로 가능
```

## 5. 문과 토큰

- 문: 여러 토큰으로 구성
- 토큰: 문법적 의미를 가지며 더 이상 나눌 수 없는 코드의 최소 단위
  - 키워드, 식별자, 연산자, 리터럴, 세미콜론, 마침표 등
```js
var sum = 1 + 2;
// 토큰: var / sum / = / 1 / + / 2 / ;
```

- 문의 종류: 선언문, 할당문, 조건문, 반복문 등
```js
var x;               // 변수 선언문
x = 5;               // 할당문
function foo() {}    // 함수 선언문
if (x > 1) {}        // 조건문
for (var i = 0; i < 2; i++) {} // 반복문
```

## 6. 세미콜론과 ASI

- 세미콜론: 문의 종료 표시
- 코드 블록 `{}` 뒤에는 세미콜론 생략 (if문, for문, 함수 선언문 등)
  - 코드 블록은 그 자체로 종결되는 독립 구조
- ASI(Automatic Semicolon Insertion): 엔진이 세미콜론을 자동 삽입하는 기능
- ASI가 개발자 의도와 다르게 동작하는 경우 존재
### return 뒤 줄바꿈

```js
// 실수: return 뒤에 세미콜론이 자동 삽입됨
function getPrice() {
  return
    1000 * 2;
}
getPrice(); // undefined
 
// 개선: 반환할 표현식을 return과 같은 줄에서 시작
function getPrice() {
  return 1000 * 2;
}
```

- 같은 줄에서 괄호를 열면 여러 줄로 나눠도 무방, JSX의 `return (` 패턴이 이 이유
```js
return (
  1000 * 2
);
```

- 주의: return 뒤의 `{}`는 값 자리이므로 객체 리터럴로 해석
```js
return { 1000 * 2; }  // SyntaxError, 객체 안에 키: 값 형태가 아님
return { id: 1 };     // 객체 반환
```

### 다음 줄이 괄호로 시작

```js
// 실수: 세미콜론이 삽입되지 않아 두 줄이 이어서 해석됨
var bar = function () {}
(function () {})();
 
// 개선
var bar = function () {};
(function () {})();
```

- 세미콜론 사용 여부는 커뮤니티 논쟁 주제, 팀의 ESLint·Prettier 규칙을 따름
- 어느 쪽이든 ASI 함정을 알고 있는 것이 중요

## 7. 표현식인 문과 표현식이 아닌 문

| 구분 | 설명 | 예시 |
|---|---|---|
| 표현식인 문 | 값으로 평가 가능 | `x = 1 + 2;`, `a + 1;` |
| 표현식이 아닌 문 | 값으로 평가 불가 | `var x;`, `if (x) {}` |

- 구분법: 변수에 할당해 보기
```js
var foo = var x;     // SyntaxError, 선언문은 표현식 아님
var foo = x = 100;   // 가능, 할당문은 표현식
```

- `var foo = x = 100` 평가 순서: 할당은 오른쪽부터 처리
  - `x = 100` 평가 → x에 100 할당, 이 할당문이 100으로 평가
  - `var foo = 100` → foo에 100 할당
- 단, 문장 전체는 `var`로 시작하는 선언문이므로 표현식이 아닌 문
- 문장 맨 앞 키워드가 `var`, `let`, `const`, `if`, `for`이면 표현식이 아닌 문
- 참고: 위 예시의 x는 선언 없이 사용되어 암묵적 전역 변수 생성, strict mode에서는 ReferenceError, 실무 사용 금지
### 크롬 콘솔의 완료 값

- 표현식이 아닌 문 입력 시 `undefined` 출력, 이를 완료 값이라 함
- 표현식인 문 입력 시 평가된 값 출력
- 완료 값은 다른 표현식의 일부로 사용 불가
```js
> var x = 10
< undefined   // 선언문 → 완료 값
> x = 20
< 20          // 할당문 → 평가 값
```

## 8. 실무 사례

### JSX 중괄호 안의 조건부 렌더링

- 상황: JSX `{}` 안에 if문 작성 시 SyntaxError
- 원인: JSX `{}`는 값 자리, if문은 표현식이 아닌 문
- 해결: 삼항 연산자, 논리 연산자 등 표현식으로 대체
```jsx
// 실수
<div>{if (isPaid) { <PaidBadge /> }}</div>
 
// 개선
<div>
  {isPaid ? <PaidBadge /> : <PayButton />}
  {hasCoupon && <CouponBanner />}
</div>
```

- 조건이 복잡하면 JSX 밖(문 자리)에서 if문으로 먼저 계산 후 변수만 삽입
```jsx
let paymentStatus;
if (isSoldOut) paymentStatus = <SoldOut />;
else if (isPaid) paymentStatus = <PaidBadge />;
else paymentStatus = <PayButton />;
 
return <div>{paymentStatus}</div>;
```

### JSX 리스트 렌더링

- 상황: JSX `{}` 안에서 for문으로 목록 렌더링 불가
- 원인: for문은 표현식이 아닌 문, 값이 나오지 않음
- 해결: `map()` 사용
  - 메서드 호출 표현식이므로 새 배열이라는 값으로 평가
  - React는 배열을 받으면 요소를 순서대로 렌더링
```jsx
<ul>
  {products.map((p) => <li key={p.id}>{p.name}</li>)}
</ul>
```

- `key`는 React가 리스트 항목을 구분하는 식별자, 누락 시 콘솔 경고
### null, undefined와 렌더링

- 결제 API에서 "쿠폰 없음"을 null로 응답하는 경우가 흔함
- JSX에 `null`, `undefined`, `false`가 들어가면 화면에 아무것도 그리지 않음
```jsx
<div>{order.coupon?.name ?? '적용된 쿠폰 없음'}</div>
```
