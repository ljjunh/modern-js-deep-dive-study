## 데이터 타입

- ECMAScript 언어 타입은 ES6 기준 7개(String, Number, Boolean, Null, Undefined, Symbol, Object)이고, ES2020(ES11)에서 BigInt가 추가되어 현재 8개다.
- Object를 제외한 7개가 원시 타입이다.
- Number 타입은 IEEE 754-2019 binary64(배정밀도 64비트 부동소수점)을 따른다.
- typeof의 결과는 언어 타입과 일치하지 않는다. typeof null은 "object", typeof function(){}은 "function"이다.
- typeof는 언어 타입을 돌려주는 연산자가 아니라 사양 13.5.3의 표를 돌려주는 연산자다. 원시 타입은 1:1로 대응하지만 Object 타입은 [[Call]] 내부 메서드가 있으면 "function", 없으면 "object"로 갈라진다. 함수는 사양에서 호출 가능한 Object일 뿐이므로 "function"은 별도 타입이 아니라 Object의 부분집합에 붙은 이름이다.

### Q1. 책은 "숫자 타입은 8바이트를 차지하고, 변수는 그 공간의 시작 주소를 기억한다"고 설명한다. 그럼 실제로 셀 8개를 확보하는 건가?

이건 이해를 돕는 그림이고, 사양이 정한 것도 엔진이 실제로 하는 것도 아니다.

사양은 저장 방식을 정하지 않는다. ECMAScript는 Number가 64비트 부동소수점(IEEE 754 binary64) 값이라는 것과 연산 결과가 그 규칙을 따라야 한다는 것만 정한다. 그 값을 메모리에 몇 바이트로 어떻게 넣을지는 엔진의 자유다.

여기부턴 V8 이야기다

변수는 슬롯 하나를 갖는다. 슬롯은 변수마다 하나씩 있는 8바이트 칸이다. 이 칸에 무엇이 들어가느냐가 값에 따라 갈린다.

- 100처럼 작은 정수는 Smi(Small Integer) 형식으로 슬롯에 값이 직접 들어간다. 힙에 따로 만드는 것이 없고 주소도 없다. score = 200으로 바꾸면 그 칸을 덮어 쓴다. Smi 범위는 Node에서 32비트, Chrome에서 31비트 정수다.
- 100.5나 2^40처럼 Smi로 표현할 수 없는 수는 힙에 HeapNumber라는 객체를 만들고, 변수 슬롯에는 그 주소가 들어간다. 문자열, 객체, undefined도 같은 방식으로 슬롯에 주소가 들어간다.

```js
var a = 100; // a의 슬롯 : [100 (Smi)]
var b = 100.5; // b의 슬롯 : [ 주소 ] -> 힙: HeapNumber 100.5
var c = "hi"; // c의 슬롯 : [ 주소 ] -> 힙: "hi"
var d = {}; // d의 슬롯 : [ 주소 ] -> 힙: 객체
```

그래서 100은 8바이트를 쓴다. 하지만 "숫자가 64비트라서"가 아니라 "슬롯이 8바이트이고 그 안에 값이 다 들어가서"다. 책의 8바이트와 숫자가 같은 것은 우연이다. 같은 Number 타입인 100.5는 슬롯 8바이트에 힙 객체 16바이트가 더해져 24바이트를 쓴다.

타입 정보는 값과 함께 다닌다. C는 변수 타입이 정해져 있어서 "이 자리에서 8바이트를 double로 읽어라"를 컴파일 시점에 정해 둔다. 자바스크립트는 같은 변수에 뭐든 들어올 수 있어서 그렇게 못 하고, 타입 정보를 값과 함께 메모리에 둔다. V8은 슬롯의 마지막 비트로 "값인지 주소인지"를 표시하고, 힙 객체의 첫 워드에 "어떤 종류의 객체인지"를 가리키는 맵 포인터를 둔다. 읽을 때는 슬롯을 보고, 태그를 확인하고, 주소면 따라가서 맵을 본 뒤에야 어떻게 해석할지 정한다. 이 확인 단계가 동적 타입 언어의 비용이다.
