값

- 값은 표현식이 평가되어 생성된 결과. 평가는 식을 해석해 값을 생성하거나 참조하는 것
- 모든 값은 데이터 타입을 가지며 비트로 저장된다. 같은 비트도 타입에 따라 다르게 해석된다.
- 변수에 할당되는 것은 표현식이 아니라 표현식이 평가된 값이다.

리터럴

- 사람이 이해할 수 있는 문자나 약속된 기호로 값을 생성하는 표기법.
- 3은 숫자가 아니라 숫자 리터럴이고, 엔진이 평가해 값 3을 만든다.

표현식

- 값으로 평가될 수 있는 것
- 표현식과 그 평가 결과는 동치라서, 값이 올 자리에 표현식이 올 수 있따.

문

- 프로그램의 최소 실행 단위. 토큰으로 구성된다.
- 선언문, 할당문, 조건문, 반복문 등

표현식인 문 / 표현식이 아닌 문

- 구별법은 변수에 할당해 보는 것

세미콜론과 ASI

- 세미콜론은 문의 끝. 코드 블록 뒤에는 붙이지 않는다.
- 생략 가능한 이유는 엔진이 문의 끝으로 예측되는 지점에 세미콜론을 자동 삽입(ASI)하기 때문. 단, 예측이 어긋나는 경우도 있다.

놓인 자리에 따라 문인지 표현식인지가 갈린다.

```js
console.log(eval("{}")); // undefined 문 자리라 빈 블록. 값 없음
console.log(eval("({})")); // {} 괄호 안은 표현식 자리라 객체 리터럴
console.log(eval("function f(){}")); // undefined 문 자리. 함수 선언. 값 없음
console.log(eval("(function f(){})")); // [Function: f] 표현식 자리. 값 있음
```

IIFE를 (function(){...})() 괄호로 감싸는 이유가 정확히 이 규칙. 괄호 없이 function(){}()으로 쓰면 문 자리에서 함수 선언으로 읽혀 이름이 없다는 SyntaxError가 난다.
