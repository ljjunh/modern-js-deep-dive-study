### 자바스크립트 객체의 분류

| 종류             | 누가 정하나               | 예                                         |
| ---------------- | ------------------------- | ------------------------------------------ |
| 표준 빌트인 객체 | ECMAScript 사양           | Object, String, Array, Promise, Math, JSON |
| 호스트 객체      | 실행 환경(브라우저, Node) | DOM, fetch, setTimeout, process            |
| 사용자 정의 객체 | 개발자                    | 직접 만든 객체                             |

- 표준 빌트인 객체는 전역 객체의 프로퍼티라서 선언 없이 바로 쓸 수 있고, 사양에 정의돼 있으니 브라우저든 Node든 동작이 같다.

### 표준 빌트인 객체

- 생성자 함수인 것: String, Number, Boolean, Array, Date, RegExp, Promise, Map 등
  - 인스턴스가 쓰는 메서드는 X.prototype에 있음 -> (1.5).toFixed()
  - 인스턴스 없이 쓰는 정적 메서드는 X 자체에 있음 -> Number.isInteger(0.5)
- 생성자가 아닌 것: Math, JSON, Reflect, Atomics, Intl 함수가 아니라 그냥 객체라 정적 메서드만 있음
- Symbol, BigInt는 함수지만 new를 붙이면 TypeError

### 원시값과 래퍼 객체

- 문자열, 숫자, 불리언, 심벌, BigInt는 객체가 아닌데 'hi'.length처럼 쓸 수 있음
- 사양이 정한 순서
  1. ToObject(원시값)으로 임시 객체를 만든다. 문자열이면 String 인스턴스, 원래 값은 [[StringData]] 슬롯에 들어간다.
  2. 임시 객체에서 프로퍼티를 찾는다. String.prototype까지 체인을 탄다.
  3. 값을 돌려주고 임시 객체는 버린다.
- 이 임시 객체가 래퍼 객체다.
- null, undefined는 ToObject가 TypeError라서 null.foo는 에러가 난다
- new String('hi')는 쓸 이유가 없다. 원시값으로도 메서드를 다 쓸 수 있고, typeof가 Object가 되고, new Boolean(false)는 truthy다.

### 전역 객체

- 코드 실행 전에 엔진이 만드는 객체로 브라우저는 window, Node는 global
- ES2020부터 globalThis로 환경 상관없이 가리킬 수 있다
- 전역 객체의 프로퍼티인 것
  - 표준 빌트인 객체 전부
  - 호스트 객체
  - var 전역 변수, 전역 함수 선언문
  - 선언 없이 할당한 암묵적 전역
- 아닌 것: let, const, class 전역 선언(Global Environment Record의 Declarative쪽)
- "최상위 객체"는 프로토타입 체인 꼭대기라는 뜻이 아니다. 다른 객체의 프로퍼티가 아니면서 빌트인, 호스트 객체를 전부 프로퍼티로 갖는다는 뜻
- 빌트인 전역 프로퍼티 Infinity, NaN, undefined는 전부 writable, enumerable, configurable이 false라서 덮어쓰기나 삭제 불가

### isFinite / isNaN

- 인수를 먼저 숫자로 변환한 뒤 검사한다. 변환 없이 검사하는 Number.isFinite, Number.isNaN과 결과가 다르다

  | 입력      | isFinite | Number.isFinite | isNaN | Number.isNaN |
  | --------- | -------- | --------------- | ----- | ------------ |
  | '10'      | true     | false           | false | false        |
  | null      | true     | false           | false | false        |
  | ''        | true     | false           | false | false        |
  | undefined | false    | false           | true  | false        |
  | NaN       | false    | false           | true  | true         |

### parseFloat / parseInt

- 문자열을 앞에서부터 읽을 수 있는 데 까지 읽고 나머지는 버린다.
- 앞뒤 공백 무시
- 첫 글자부터 못 읽으면 NaN

```js
parseInt("123abs"); // 123
Number("123abc"); // NaN (Number는 전체가 숫자여야 함)
parseInt(""); // NaN
Number(""); // 0
parseFloat("1e3"); // 1000
parseInt("1e3"); // 1 (e에서 멈춤)
```

### encodeURI / encodeURIComponent

왜 필요한가

- URL에는 아스키 문자만 들어갈 수 있다. 한글, 공백 같은 건 그대로 못 쓴다
- 그래서 그런 문자를 %XX 형태로 바꿔서 넣는다. 이걸 인코딩이라 한다
- 방법은 "문자를 UTF-8 바이트로 바꾸고, 바이트마다 앞에 %를 붙인다". 한글은 UTF-8로 3바이트라 %XX가 세 개 나온다
  encodeURI('가'); // '%EA%B0%80'
  encodeURI(' '); // '%20'

두 함수의 차이는 딱 하나다

- / ? = & # 같은 문자는 URL에서 구조를 나누는 역할을 한다(경로 구분, 쿼리 시작, 키=값, 항목 구분)
- 이 문자들을 바꾸느냐 안 바꾸느냐가 두 함수의 차이다
  | | encodeURI | encodeURIComponent |
  | 입력으로 받는 것 | URL 전체 | URL의 한 조각 (쿼리 값 하나 등) |
  | ; / ? : @ & = + $ , # | 그대로 둠(구조 문자니까 살려야 함) | 전부 %XX로 바꿈 |
  | 알파벳, 숫자, - \_ . ! ~ \* ' ( ) | 그대로 둠 | 그대로 둠 |
  | 그 외 (한글, 공백 등) | %XX로 바꿈 | %XX로 바꿈 |

```js
encodeURI("http://a.com?name=이웅모&job=programmer");
// 'http://a.com?name=%EC%9D%B4%EC%9B%85%EB%AA%A8&job=programmer'
// ?, =, & 는 살아 있고 한글만 바뀜

encodeURIComponent("name=이웅모&job=programmer");
// 'name%3D%EC%9D%B4%EC%9B%85%EB%AA%A8%26job%3Dprogrammer'
// =, & 까지 바뀜
```

언제 뭘 써야 하나

- URL 전체를 통째로 넘길 때 -> encodeURI 구조 문자를 살려야 URL로 동작한다
- 쿼리 값 하나를 URL에 끼워 넣을 때 -> encodeURIComponent. 값 안에 &나 =가 들어 있어도 구조로 오해받지 않게 전부 바꿔야 한다

### decode

- decodeURI는 %26(&) 같은 구조 문자는 안 풀어준다. encodeURI가 안 바꿨던 문자니까 풀면 구조가 깨진다
- decodeURIComponent는 전부 푼다

### 암묵적 전역

```js
function foo() {
  y = 20;
}
foo();
console.log(y); // 20
```

- PutValue가 식별자를 못 찾으면 non-strict에서 Set(globalObj, 'y', 20)으로 전역 객체에 프로퍼티를 만든다. strict는 ReferenceError
- y는 변수가 아니라 그냥 프로퍼티다
