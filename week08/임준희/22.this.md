### this

- 함수 안에서 "지금 이 호출의 주인이 누구인가"를 가리키는 키워드
- 변수가 아니다. this = 1은 SyntaxError
- 값은 함수를 호출할 때 정해진다. 함수를 어디에 정의했는지는 상관없다 (렉시컬 스코프와 반대)
- 함수가 호출되면 그 호출의 Function Environment Record에 this값이 저장되고, 코드에서 this를 만나면 가장 가까운 "this 바인딩을 가진" 환경을 찾아 그 값을 돌려준다

### this는 두 단계로 정해진다

1단계: 호출 형태가 "넘길 this"를 정한다
| 호출 형태 | 넘기는 this |
| -- | -- |
| obj.fn() | obj(점 앞의 것) |
| fn() | undefined |
| new fn() | 새로 만든 객체 |
| fn.call(x), fn.apply(x), fn.bind(x)() | x |

2단계: 함수 종류가 받은 this를 변환한다
| 함수 종류 | 받은 this를 어떻게 하나 |
| strict 함수 | 그대로 쓴다 |
| non-strict 함수 | undefined, null -> globalThis / 원시값 -> 래퍼 객체 |
| 화살표 함수 | 무시하고 바깥 함수의 this를 쓴다 |
| bind된 함수 | 무시하고 bind 때 고정한 this를 쓴다 |

### 일반 함수 호출

```js
function foo() {
  return this;
}
foo(); // non-strict: globalThis / strict: undefined
```

- 중첩 함수든 콜백이든 fn() 형태로 부르면 전부 일반 호출이다
- 메서드 안에서 콜백을 넘기면 콜백 안의 this가 메서드의 this와 달라지는 문제가 생긴다.
  - 해결법 세 가지
  - const that = this로 담아 두고 콜백에서 that 사용
  - callback.bind(this)
  - 화살표 함수 (바깥 this를 그대로 씀)

### 메서드 호출

```js
const person = {
  name: "Lee",
  getName() {
    return this.name;
  },
};
person.getName(); // 'Lee' this는 점 앞의 person

const other = { name: "Kim" };
other.getName = person.getName;
other.getName(); // 'Kim' 같은 함수인데 점 앞이 other

const getName = person.getName;
getName(); // 일반 호출. non-strict면 globalThis.name
```

- this는 메서드를 소유한 객체가 아니라 호출한 객체다. 메서드는 객체에 포함된 게 아니라 프로퍼티가 가리키는 별도의 함수 객체라서, 어디에 붙여서 부르느냐에 따라 달라진다

### 생성자 함수 호출

```js
function Circle(r) {
  this.radius = r;
}
const c = new Circle(5); // this는 새로 만든 객체 c
Circle(15); // new 없음 -> 일반 호출. non-strict면 globalThis.radius = 15
```

- new로 부르면 빈 객체를 만들고 그걸 this로 넘긴다
- new 없이 부르면 그냥 일반 호출이라 this가 전역 객체가 되고, 프로퍼티가 전역에 새어 나간다

### call / apply / bind

```js
function getThis() {
  return this;
}
const arg = { a: 1 };

getThis.call(arg, 1, 2, 3); // this = arg. 인수를 쉼표로
getThis.apply(arg, [1, 2, 3]); // this = arg. 인수를 배열로
getThis.bind(arg); // 함수 호출은 안하고 this가 arg로 고정된 새 함수를 반환
getThis.bind(arg)(); // arg
```

- call과 apply는 함수를 바로 호출한다. 첫 인수가 this가 되고, 나머지 인수를 넘기는 방식만 다르다
- bind는 함수를 호출하지 않고 this가 고정된 새 함수를 만든다.
- bind된 함수는 call, apply, 또 다른 bind로 this를 바꿀 수 없다. 처음 고정한 게 끝까지 간다
- 단 bind된 함수를 new로 부르면 고정한 this를 무시하고 새 객체를 만든다

### 화살표 함수

- 화살표 함수는 this 바인딩 자체가 없다. this를 만나면 바깥 함수의 this를 그대로 쓴다
- call, apply, bind로 바꿀 수 없고, new로 부르면 TypeError
- 클래스 필드에 화살표 함수를 쓰면 인스턴스에 this가 고정된다.

### 화살표 함수에는 왜 this가 없나?

일반 함수가 this를 갖는 방식

- 함수가 호출되면 그 호출 전용 Function Environment Record가 만들어진다
- 이 저장소에는 변수 말고도 [[ThisValue]]칸이 있다. 호출 때 정해진 this가 여기 들어간다
- 코드에서 this를 만나면 엔진은 "지금 환경에 this칸이 있나?"를 묻고, 있으면 그 값을 돌려준다

화살표 함수는 this 칸이 없는 환경을 만든다

- 화살표 함수도 호출되면 자기 Environment Record를 만든다. 그런데 [[ThisBindingStatus]]가 lexical로 표시돼 있다.
- 이 환경에 "this 칸 있나?"를 물으면 false가 나온다
- 그러면 엔진은 [[OuterEnv]]를 따라 바깥 환경으로 올라가서 다시 묻는다. this칸이 있는 환경을 만날 때까지 올라간다
- 그래서 화살표 함수 안의 this는 가장 가까운 바깥 일반 함수의 this가 된다. 바깥에 일반 함수가 없으면 최상위 this(브라우저 스크립트는 window, 모듈은 undefined)

### React에서 this가 사라진 이유

클래스 컴포넌트 시절의 문제

```js
class Button extends React.Component {
  handleClick() {
    this.setState({ on: true }); // TypeError: Cannot read properties of undefined
  }
  render() {
    return <button onClick={this.handleClick}>클릭</button>;
  }
}
```

- onClick={this.handleClick}은 함수를 넘기기만 한다. 호출은 나중에 React가 한다
- React는 핸들러를 일반 함수처럼 부른다. 점 앞에 아무 객체도 없으니 this로 undefined가 넘어온다
- 클래스 안의 함수는 전부 strict라 undefined가 그대로 남는다. this.setState에서 터진다

  당시 해결법(React 공식 문서 기준)
  | 방법 | 코드 | 비고 |
  | --- | --- | --- |
  | 생성자에서 bind | this.handleClick = this.handleClick.bind(this) | 인스턴스마다 한 번 |
  | 클래스 필드 + 화살표 | handleClick = () => {...} | 바깥 this 고정 |
  | JSX 안에서 화살표 | onClick={() => this.handleClick()} | 렌더마다 새 함수가 생겨서 자식에게 넘기면 불필요한 리렌더 유발|

함수 컴포넌트로 넘어가며 this가 사라졌다

- React 팀이 Hooks를 소개하면서 든 이유 중 하나가 클래스의 this다. "this가 어떻게 동작하는지 이해해야 하고, bind를 기억해야 한다"는 부담
- 그래서 함수 컴포넌트는 애초에 this를 쓰지 않는 구조로 만들었다. 인스턴스가 없고, 상태와 핸들러가 전부 클로저로 묶인다

```js
function Button() {
  const [on, setOn] = useState(false);
  const handleClick = () => setOn(true); // this없음, setOn을 클로저로 잡음
  return <button onClick={handleClick}>클릭</button>;
}
```

- handleClick은 this를 안 쓴다. 필요한 값은 전부 바깥 스코프의 변수(setOn)로 잡는다. React가 어떤 방식으로 부르든 상관없다
- 그래서 지금 React 코드에서 22장 this의 내용이 거의 안 보인다. this를 잘 다루게 된 게 아니라 안 쓰게 된 것이다
