# 21 빌트인 객체

## 21.1 자바스크립트 객체의 분류

### 1. 표준 빌트인 객체

- ECMAScript 사양에 정의된 객체
- 자바스크립트 실행 환경(브라우저 or Node.js 환경)과 관계없이 언제나 사용
- 전역 객체의 프로퍼티로서 제공
- 전역 변수처럼 언제나 참조 가능

### 2. 호스트 객체

- 자바스크립트 실행 환경(브라우저 or Node.js 환경)에서 추가로 제공하는 객체
  - ECMAScript 사양에 정의되어 있지 않음
- 브라우저 환경
  - 클라이언트 사이드 Web API를 호스트 객체로 제공
    - DOM, BOM, Canvas, XMLHttpRequest, fetch, requestAnimationFrame, SVG, Web Storage, Web Component, Web Worker
- Node.js 환경
  - Node.js 고유의 API를 호스트 객체로 제공

### 3. 사용자 정의 객체

- 사용자가 직접 정의한 객체

## 21.2 표준 빌트인 객체

- Object, String, Number, Boolean, Symbol, Date, Math, RegExp, Array, Map/Set, WeakMap/WeakSet, Function, Promise, Reflect, Proxy, JSON, Error 등 40여 개의 표준 빌트인 객체 제공
- Math, Reflect, JSON을 제외한 표준 빌트인 객체는 모두 인스턴스를 생성할 수 있는 생성자 함수 객체
  - 생성자 함수 객체인 표준 빌트인 객체: 프로토타입 메서드와 정적 메서드 제공
  - 생성자 함수 객체가 아닌 표준 빌트인 객체는 정적 메서드만 제공

- 생성자 함수인 표준 빌트인 객체가 생성한 인스턴스의 프로토타입은 표준 빌트인 객체의 prototype 프로퍼티에 바인딩된 객체 (e.g. `String.prototype`)
  - 다양한 기능의 빌트인 프로토타입 메서드를 제공
  - 인스턴스 없이도 호출 가능한 빌트인 정적 메서드 제공

```javascript
// Number 객체 생성
const numObj = new Number(1.5);

// Number.prototype의 프로토타입 메서드
console.log(numObj.toFixed()); // 2

// Number의 정적 메서드
console.log(Number.isInteger(0.5)); // false
```

## 21.3 원시값과 래퍼 객체

- 문자열, 숫자, 불리언 값에 대해 객체처럼 접근하면 생성되는 임시 객체를 래퍼 객체라고 한다.
  - 프로퍼티에 접근하거나 메서드를 호출하고 다시 원시값으로 되돌아감
  - 식별자가 원시값을 갖도록 되돌리고 래퍼 객체는 가비지 컬렉션의 대상이 됨

- 심벌도 래퍼 객체를 생성
  - 일반적인 원시값과는 달리 리터럴 표기법으로 생성할 수 없고 Symbol 함수를 통해 생성해야 하므로 다른 원시값과는 차이 있음

- 문자열, 숫자, 불리언, 심벌은 암묵적으로 생성되는 래퍼 객체에 의해 객체처럼 사용할 수 있음
  - 표준 빌트인 객체인 String, Number, Boolean, Symbol의 프로토타입 메서드 또는 프로퍼티를 참조할 수 있다.
  - String, Number, Boolean 생성자 함수를 new 연산자와 함께 호출하여 문자열, 숫자, 불리언 인스턴스를 생성할 필요가 없으며 권장하지도 않음.

- null과 undefined는 래퍼 객체를 생성하지 않음

### 래퍼 객체의 수명과 new를 권장하지 않는 이유

- 원시값도 래퍼 객체를 사용하는 방식으로 프로토타입 메서드에 접근할 수 있으므로 객체를 직접 만들 필요 없음
- 임시 래퍼 객체에 추가한 프로퍼티는 원시값에 저장되지 않음

```javascript
// non-strict mode에서 실행
const str = "hello";
str.language = "English";
console.log(str.language); // undefined
// strict mode에서는 위 대입 자체가 TypeError

console.log((1.234).toFixed(2)); // "1.23": 원시값도 메서드 사용 가능
console.log(typeof new Number(10)); // "object"
console.log(new Number(10) === 10); // false
console.log(new Number(10) === new Number(10)); // false: 서로 다른 객체

const flag = new Boolean(false);
console.log(Boolean(flag)); // true: 감싼 값과 관계없이 객체는 참으로 평가
```

- 보통 문자열, 숫자, 불리언은 원시값으로 사용
- new 없이 `Number("10")`, `String(10)`, `Boolean(0)`처럼 호출하면 객체 생성이 아닌 원시값으로의 타입 변환

## 21.4 전역 객체

- 코드가 실행되기 이전 단계에 자바스크립트 엔진에 의해 어떤 객체보다도 먼저 생성되는 특수한 객체, 어떤 객체에도 속하지 않은 최상위 객체
  - 브라우저 환경: window(또는 self, this, frames)
  - Node.js 환경: global
  - ECMAScript2020(ES11)에서 도입된 globalThis는 전역 객체를 가리키던 다양한 식별자를 통일한 식별자
- 전역 객체는 표준 빌트인 객체와 환경에 따른 호스트 객체(클라이언트 Web API or Node.js의 호스트 API), 그리고 var 키워드로 선언한 전역 변수와 전역 함수를 프로퍼티로 가짐

- 전역 객체는 계층적 구조상 어떤 객체에도 속하지 않은 모든 빌트인 객체(표준 빌트인 객체, 호스트 객체)의 최상위 객체
  - 프로토타입 상속 관계상에서 최상위 객체라는 의미가 아님
  - 어떤 객체의 프로퍼티도 아니며 표준 빌트인 객체와 호스트 객체를 프로퍼티로 소유

### 특징

- 개발자가 의도적으로 생성할 수 없다. 전역 객체를 생성할 수 있는 생성자 함수 제공되지 않음.
- 프로퍼티를 참조할 때 window(또는 global)를 생략할 수 있음.
- 모든 표준 빌트인 객체를 프로퍼티로 가지고 있음.
- 자바스크립트 실행 환경(브라우저, Node.js)에 따라 추가적으로 프로퍼티와 메서드를 가짐.
- var 키워드로 선언한 전역 변수와 선언하지 않은 변수에 값을 할당한 암묵적 전역, 전역 함수는 전역 객체의 프로퍼티가 된다.
- let이나 const 키워드로 선언한 전역 변수는 전역 객체의 프로퍼티가 아니다.
  - 보이지 않는 개념적인 블록(전역 렉시컬 환경의 선언적 환경 레코드) 내에 존재
- 브라우저 환경의 모든 자바스크립트 코드는 하나의 전역 객체 window를 공유

## 21.4.1 빌트인 전역 프로퍼티

- Infinity: 무한대를 나타내는 숫자값
- NaN: 숫자가 아님을 나타내는 숫자값, Number.NaN 프로퍼티와 같음
- undefined

### NaN과 Number.NaN, 검사 함수의 차이

- NaN과 Number.NaN은 명세상 같은 숫자값 NaN을 제공하며 연산 동작도 같음
- NaN은 자기 자신을 포함하여 어떤 값과도 === 비교 결과가 false
- 값 자체가 NaN인지 확인하려면 Number.isNaN 사용

```javascript
console.log(typeof NaN); // "number"
console.log(NaN === Number.NaN); // false
console.log(Object.is(NaN, Number.NaN)); // true

console.log(isNaN("hello")); // true: 숫자로 변환한 결과가 NaN
console.log(Number.isNaN("hello")); // false: 문자열 자체는 NaN이 아님
console.log(isNaN("10")); // false: 숫자 10으로 변환
console.log(Number.isNaN(NaN)); // true
console.log(Number.isNaN(Number.NaN)); // true
```

| 구분               | isNaN               | Number.isNaN             |
| ------------------ | ------------------- | ------------------------ |
| 숫자 타입으로 변환 | 수행                | 수행하지 않음            |
| 검사 대상          | 변환한 값이 NaN인지 | 전달한 값 자체가 NaN인지 |

## 21.4.2 빌트인 전역 함수

- eval 함수
  - 자바스크립트 코드를 나타내는 문자열을 인수로 전달받는다.
    - 문자열 코드가 표현식이라면 런타임에 평가하여 값을 생성
    - 표현식이 아닌 문이라면 런타임에 실행
    - 여러 개의 문으로 이루어져 있다면 모든 문 실행, 마지막 결과값 반환

  - 기존의 스코프를 런타임에 동적으로 수정
    - strict mode에서 eval 함수는 자신의 자체적인 스코프를 생성(기존의 스코프 수정하지 않음)

  - 인수로 전달받은 문자열 코드가 let, const 키워드를 사용한 변수 선언문이라면 암묵적으로 strict mode 적용

  - **eval 함수의 사용은 금지해야 한다**
    - 사용자로부터 입력받은 콘텐츠를 실행하는 것은 보안에 매우 취약
    - 자바스크립트 엔진에 의해 최적화가 수행되지 않아 처리 속도가 느림

- isFinite
  - 전달받은 인수가 유한수이면 true 반환, 무한수이면 false를 반환
  - 전달받은 인수의 타입이 숫자가 아닌 경우, 숫자로 타입을 변환한 후 검사 수행
    - NaN으로 평가되는 값이라면 false 반환
- isNaN
  - 전달받은 인수가 NaN인지 검사하여 불리언 타입으로 반환
  - 전달받은 인수의 타입이 숫자가 아닌 경우, 숫자로 타입을 변환한 후 검사 수행

- parseFloat
  - 전달받은 문자열 인수를 부동 소수점 숫자, 즉 실수로 해석하여 반환

- parseInt
  - 전달받은 문자열 인수를 정수로 해석하여 반환
  - 전달받은 인수가 문자열이 아니면 문자열로 변환한 다음, 정수로 해석하여 반환
  - 두 번째 인수로 진법을 나타내는 기수(2 ~ 36)를 전달할 수 있다.(기본값 10진수)
  - **10진수 숫자를 해당 기수의 문자열로 변환하고 싶을 때는 Number.prototype.toString 메서드 사용**
  - 첫 번째 인수로 전달된 문자열이 "0x" 또는 "0X"로 시작하는 16진수 리터럴이라면 16진수로 해석하여 10진수 정수로 반환
    - 2진수 리터럴과 8진수 리터럴은 제대로 해석하지 못함
  - 첫 번째 인수로 전달한 문자열의 첫 번째 문자가 해당 기수의 숫자로 변환될 수 없다면 NaN 반환
  - 첫 번째 인수로 전달한 문자열의 두 번째 문자부터 해당 진수를 나타내는 숫자가 아닌 문자와 마주치면 무시 후 해석된 정수값만 반환
  - 첫 번째 인수로 전달한 문자열에 공백이 있다면 첫 번째 문자열만 해석하여 반환하며 앞뒤 공백 무시
    - 첫 번째 문자열을 숫자로 해석할 수 없는 경우 NaN 반환

- encodeURI / decodeURI
  - encodeURI: 완전한 URI를 문자열로 전달받아 이스케이프 처리를 위해 인코딩
    - URI는 인터넷에 있는 자원을 나타내는 유일한 주소, URI의 하위 개념으로 URL, URN이 있다.
    - 이스케이프 처리: 네트워크를 통해 정보를 공유할 때 어떤 시스템에서도 읽을 수 있는 아스키 문자 셋으로 변환하는 것
  - decodeURI: 인코딩된 URI를 인수로 전달받아 이스케이프 처리 이전으로 디코딩

- encodeURIComponent / decodeURIComponent
  - encodeURIComponent 함수는 URI 구성 요소를 인수로 전달받아 인코딩
    - 인코딩: URI의 문자들을 이스케이프 처리하는 것
  - decodeURIComponent 함수는 매개변수로 전달된 URI 구성 요소를 디코딩

- encodeURI와 encodeURIComponent
  - 공통점: 알파벳, 0~9의 숫자, -\_.!~\*'()문자는 이스케이프 처리에서 제외
  - encodeURI는 쿼리스트링 구분자(=, ?, &)를 인코딩하지 않지만 encodeURIComponent는 쿼리 스트링 구분자까지 인코딩

### 리다이렉트 URL을 쿼리 값으로 전달하기

- encodeURI는 완성된 URI를 인코딩하며 ?, =, & 등의 구조 구분자를 유지
- encodeURIComponent는 개별 값을 인코딩하므로 값에 포함된 구분자도 인코딩
- 리다이렉트 주소 전체를 쿼리의 값으로 넣을 때는 encodeURIComponent 사용
  - 인코딩하지 않으면 안쪽 주소의 &가 바깥 주소의 매개변수 구분자로 해석될 수 있음
- 인코딩은 표현 형식의 변환이며 암호화가 아님

```javascript
const redirectUrl = "https://example.com/mypage?tab=orders&sort=latest";
const loginUrl =
  "https://example.com/login?redirect=" + encodeURIComponent(redirectUrl);

const params = new URL(loginUrl).searchParams;
console.log(params.get("redirect") === redirectUrl); // true
// URLSearchParams.get은 디코딩된 값을 반환하므로 다시 decodeURIComponent 하지 않음

// URLSearchParams를 사용하면 직접 인코딩하지 않고 원래 값을 전달
const url = new URL("https://example.com/login");
url.searchParams.set("redirect", redirectUrl);
console.log(url.searchParams.get("redirect") === redirectUrl); // true
```

## 21.4.3 암묵적 전역

- 선언하지 않은 식별자에 값을 할당하면 전역 객체의 프로퍼티가 되어 마치 전역 변수처럼 동작하는 현상
- 변수 호이스팅이 발생하지 않는다.(ReferenceError 발생)
- 전역 변수와 달리 delete 연산자로 삭제할 수 있다.

  - 래퍼 객체가 실제로 만들어지지는 않아도 된다.
