# 20 strict mode

## 20.1 strict mode란?

- ES5부터 strict mode 추가
  - 오타나 문법 지식의 미비로 인한 실수는 언제나 발생
  - 잠재적인 오류를 발생시키기 어려운 개발 환경에서 개발하는 것이 근본적인 해결책

- strict mode?
  - 자바스크립트 언어의 문법을 좀 더 엄격히 적용
  - 오류를 발생시킬 가능성이 높거나
  - 자바스크립트 엔진의 최적화 작업에 문제를 일으킬 수 있는 코드에 대해 명시적 에러 발생

### 엔진 최적화와 strict mode

- 엔진이 변수의 참조 대상과 값의 변화를 미리 파악하기 어려우면 최적화에 제약이 생김
  - `with`: 같은 이름이 객체의 프로퍼티인지 외부 변수인지 전달된 객체에 따라 달라짐
  - 직접 호출한 `eval`: non-strict mode에서는 `var` 선언으로 호출한 함수의 스코프에 변수를 추가할 수 있음
  - `arguments`: non-strict mode의 단순 매개변수 목록에서는 매개변수와 인덱스 프로퍼티가 연결되어 서로 변경에 영향을 줌
- strict mode는 `with`를 금지하고, eval의 선언이 외부로 새어 나오지 않게 하며, 매개변수와 arguments의 연결을 제거
- 모든 경우에 에러를 발생시키는 것은 아니며, 일부는 동작을 단순화하는 방식으로 처리
- strict mode에서도 eval은 주변 변수에 접근할 수 있으므로 최적화 제약이 전부 사라지는 것은 아님

```javascript
function example(a) {
  "use strict";

  eval("var localOnly = 20");
  // console.log(localOnly) // ReferenceError
  console.log(typeof localOnly); // "undefined": eval 밖에 선언되지 않음

  arguments[0] = 30;
  console.log(a); // 10: arguments[0]과 연결되지 않음
}

example(10);
```

- ESLint 같은 린트 도구를 사용해도 strict 모드와 유사한 효과
  - 정적 분석 기능을 통해 소스코드를 실행하기 전 문법적 오류, 잠재적 오류를 찾고 원인을 리포팅
  - strict mode가 제한하는 오류 + 코딩 컨벤션을 설정 파일 형태로 정의하고 강제

- ES6에서 도입된 클래스와 모듈은 기본적으로 strict mode가 적용

### strict mode와 ESLint의 차이

| 구분                      | strict mode                   | ESLint                                 |
| ------------------------- | ----------------------------- | -------------------------------------- |
| 역할                      | 자바스크립트의 실행 규칙 변경 | 실행 전에 소스 코드를 규칙에 따라 검사 |
| 선언하지 않은 변수에 대입 | 실행 시 ReferenceError        | no-undef 규칙으로 미리 지적 가능       |
| 사용하지 않은 변수        | 허용                          | no-unused-vars 규칙으로 지적 가능      |

- 서로 보완하는 도구이며 ESLint가 strict mode의 실행 규칙을 대신하지는 않음

## 20.2 strict mode의 적용

- 전역의 선두 또는 함수 몸체의 선두에 'use strict'; 를 추가
  - 전역의 선두: 스크립트 전체에 strict mode 적용
  - 함수 몸체의 선두: 해당 함수와 중첩 함수에 strict mode 적용

### 클래스와 모듈의 적용 범위

- 클래스: 메서드 등을 포함한 클래스 본문에 자동 적용. 클래스 밖까지 적용되지는 않음
- ES 모듈: 모듈 코드 전체에 자동 적용하므로 별도의 `"use strict"` 불필요
- 브라우저에서는 `<script type="module" src="app.js"></script>`로 모듈을 불러올 수 있음
  - import/export가 없어도 type="module"로 불러오면 모듈
  - 일반적인 .js 확장자만으로는 모듈 여부를 결정할 수 없음
- 브라우저 일반 스크립트의 최상위 this는 strict mode에서도 window
- ES 모듈의 최상위 this는 undefined이며, 이는 모듈 자체의 규칙

## 20.3 전역에 strict mode를 적용하는 것은 피하자

- strict mode 스크립트와 non-strict mode 스크립트를 혼용하는 것은 오류를 발생
- 외부 서드파티 라이브러리의 경우 non-strict mode인 경우

### => 즉시 실행 함수로 스크립트 전체를 감싸서 스코프를 구분하고 즉시 실행 함수 선두에 strict mode를 적용

## 20.4 함수 단위로 strict mode를 적용하는 것도 피하자

- 모든 함수에 일일이 strict mode를 적용하는 것은 번거로운 일
- strict mode가 적용된 함수가 참조할 함수 외부의 컨텍스트에 strict mode를 적용하지 않는다면 문제 발생할 수 있음.

### => strict mode는 즉시 실행 함수로 감싼 스크립트 단위로 적용하는 것이 바람직

### 즉시 실행 함수로 감싸는 이유

- 내 스크립트 전체에 일관되게 적용하면서 다른 코드와 적용 범위를 구분하기 위함
- 별도 script 요소로 불러온 파일끼리는 한 파일의 strict mode가 다른 파일로 전파되지 않음
- 다만 여러 파일을 하나로 합치면 선두의 strict mode가 합쳐진 전체 스크립트에 영향을 줄 수 있음
- ES 모듈은 자체 스코프와 자동 strict mode를 제공하므로 이 목적의 즉시 실행 함수는 불필요

```javascript
(function () {
  "use strict";

  // 이 함수 및 내부에 정의된 함수에 strict mode 적용
})();

// 바깥 코드는 위 지시문의 영향을 받지 않음
```

## 20.5 strict mode가 발생시키는 에러

### 20.5.1 암묵적 전역

- 선언하지 않은 변수를 참조하면 ReferenceError가 발생

### 20.5.2 변수, 함수, 매개변수의 삭제

- delete 연산자로 변수, 함수, 매개변수를 삭제하면 SyntaxError가 발생

### 20.5.3 매개변수 이름의 중복

- 중복된 매개변수 이름을 사용하면 SyntaxError가 발생

### 20.5.4 with 문의 사용

- with 문을 사용하면 SyntaxError가 발생
  - with 문은 전달된 객체를 스코프 체인에 추가
  - 동일한 객체의 프로퍼티를 반복해서 사용할 때 객체 이름 생략
    - 코드 간단
    - 성능과 가독성이 나빠지는 문제

## 20.6 strict mode 적용에 의한 변화

### 20.6.1 일반 함수의 this

- strict mode에서 함수를 일반 함수로서 호출하면 this에 undefined가 바인딩
- 생성자 함수가 아닌 일반 함수 내부에서는 this를 사용할 필요가 없기 때문

### 20.6.2 arguments 객체

- strict mode에서는 매개변수에 인수를 재할당하여 변경해도 arguments 객체에 반영되지 않는다.
