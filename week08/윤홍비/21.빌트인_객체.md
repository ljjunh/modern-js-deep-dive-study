### 자바스크립트 객체의 분류

- 자바스크립트 객체는 크게 3개로 분류할 수 있다.

| 분류             | 설명                                                          | 예                                  |
| ---------------- | ------------------------------------------------------------- | ----------------------------------- |
| 표준 빌트인 객체 | ECMAScript 사양에 정의된 객체. 실행 환경과 관계없이 사용 가능 | Object, String, Array, Math 등      |
| 호스트 객체      | 실행 환경(브라우저, Node.js)이 추가로 제공하는 객체           | DOM, XMLHttpRequest, fetch, process |
| 사용자 정의 객체 | 사용자가 직접 정의한 객체                                     | -                                   |

- 표준 빌트인 객체는 **전역 객체의 프로퍼티로서 제공**되므로 별도 선언 없이 사용할 수 있다.

### 표준 빌트인 객체

- 자바스크립트는 Object, String, Number, Boolean, Symbol, Date, Math, RegExp, Array, Map/Set, Function, Promise, JSON, Error 등
  - 40여 개의 표준 빌트인 객체를 제공한다.
- Math, Reflect, JSON을 제외한 표준 빌트인 객체는 모두 **인스턴스를 생성할 수 있는 생성자 함수 객체**다.
  - 생성자 함수 객체인 표준 빌트인 객체는 프로토타입 메서드와 정적 메서드를 제공한다.
  - 생성자 함수 객체가 아닌 표준 빌트인 객체는 정적 메서드만 제공한다.
  - ```javascript
    const strObj = new String("Lee"); // String {'Lee'}
    const numObj = new Number(123); // Number {123}

    Math.max(1, 2); // Math는 생성자 함수가 아니다
    new Math(); // TypeError: Math is not a constructor
    ```

- 생성자 함수인 표준 빌트인 객체가 생성한 인스턴스의 프로토타입은
  - **표준 빌트인 객체의 prototype 프로퍼티에 바인딩된 객체**다. ([19장](../../week07/윤홍비/19.프로토타입.md#프로토타입-객체))
  - ```javascript
    const numObj = new Number(1.5);

    Object.getPrototypeOf(numObj) === Number.prototype; // true

    numObj.toFixed(); // 2 (Number.prototype의 프로토타입 메서드)
    Number.isInteger(0.5); // false (Number의 정적 메서드)
    ```

| 구분              | 소유          | 호출 주체   | 예                   |
| ----------------- | ------------- | ----------- | -------------------- |
| 프로토타입 메서드 | `~.prototype` | 인스턴스    | `numObj.toFixed()`   |
| 정적 메서드       | 생성자 함수   | 생성자 함수 | `Number.isInteger()` |

### 원시값과 래퍼 객체

- 원시값은 객체가 아니므로 프로퍼티나 메서드를 가질 수 없다.
  - 그런데도 원시값인 문자열이 마치 객체처럼 동작한다.
  - ```javascript
    const str = "hello";

    console.log(str.length); // 5
    console.log(str.toUpperCase()); // HELLO
    ```

- 이는 원시값에 마침표 표기법으로 접근하면
  - 자바스크립트 엔진이 **일시적으로 원시값을 연관된 객체로 변환해주기 때문**이다.
  - 즉 원시값을 객체처럼 사용하면 암묵적으로 연관된 객체를 생성하여 프로퍼티에 접근하거나 메서드를 호출하고
  - 다시 원시값으로 되돌린다.
- 이처럼 문자열, 숫자, 불리언 값에 대해 객체처럼 접근하면 생성되는 임시 객체를 **래퍼 객체(wrapper object)** 라 한다.

#### 래퍼 객체의 동작 과정

- ```javascript
  const str = "hello";

  str.name = "Lee"; // 래퍼 객체가 생성되고 프로퍼티가 추가된 후 즉시 버려진다

  console.log(str.name); // undefined (새로운 래퍼 객체가 생성되었다)
  console.log(typeof str); // string (여전히 원시값이다)
  ```

- 위 코드는 다음 순서로 동작한다.
  - ```
    1. str.name = 'Lee'
       → 래퍼 객체 String {'hello'} 인스턴스 생성
       → 그 객체에 name 프로퍼티 추가
       → 처리가 끝나면 str은 다시 원시값 'hello'로 되돌아간다
       → 래퍼 객체는 참조가 끊겨 가비지 컬렉션의 대상이 된다

    2. console.log(str.name)
       → 또 다른 래퍼 객체 String {'hello'} 생성 (1번과 다른 객체다)
       → name 프로퍼티가 없으므로 undefined
    ```

- 즉 접근할 때마다 **매번 새로운 래퍼 객체가 생성되고 버려진다**.
  - 따라서 원시값에 프로퍼티를 추가해도 유지되지 않는다.
- 래퍼 객체의 `[[Prototype]]`에는 각 생성자 함수의 prototype이 연결된다.
  - 따라서 String.prototype의 메서드를 상속받아 사용할 수 있다.
  - ```javascript
    "hello".toUpperCase === String.prototype.toUpperCase; // true
    ```
- 문자열, 숫자, 불리언, 심벌은 래퍼 객체를 생성하므로
  - **new 연산자로 래퍼 객체를 직접 생성할 필요가 없다**. ([17장](../../week07/윤홍비/17.생성자함수에_의한_객체생성.md#newtarget))
  - 오히려 혼란을 야기할 수 있으므로 권장하지 않는다.
  - ```javascript
    const num = new Number(0);

    num == 0; // true (암묵적 타입 변환)
    num === 0; // false (객체와 원시값이다)

    if (new Boolean(false)) {
      console.log("실행된다"); // 객체는 항상 truthy다
    }
    ```

- null과 undefined는 래퍼 객체를 생성하지 않는다.
  - 따라서 객체처럼 사용하면 에러가 발생한다.
  - ```javascript
    null.toString(); // TypeError: Cannot read properties of null
    ```

### 전역 객체

- 전역 객체는 코드가 실행되기 이전 단계에 자바스크립트 엔진에 의해 **가장 먼저 생성되는 특수한 객체**다.
  - 어떤 객체에도 속하지 않은 최상위 객체다.
- 실행 환경에 따라 가리키는 이름이 다르다.
  - 브라우저 : window(또는 self, this, frames)
  - Node.js : global
  - ES11에서 도입된 **globalThis**로 통일해서 사용할 수 있다.
  - ```javascript
    globalThis === this; // true (브라우저)
    globalThis === window; // true (브라우저)
    globalThis === global; // true (Node.js)
    ```
- 전역 객체는 표준 빌트인 객체와 호스트 객체, 그리고 var로 선언한 전역 변수와 전역 함수를 프로퍼티로 갖는다.

#### 전역 객체의 특징

- 전역 객체는 **개발자가 의도적으로 생성할 수 없다**.
  - 전역 객체를 생성할 수 있는 생성자 함수가 제공되지 않는다.
- 전역 객체의 프로퍼티를 참조할 때 **window(또는 global)를 생략할 수 있다**.
  - ```javascript
    window.parseInt("F", 16); // 15
    parseInt("F", 16); // 15 (생략 가능하다)
    ```
- var 키워드로 선언한 전역 변수와 전역 함수는 전역 객체의 프로퍼티가 된다.
  - 선언하지 않은 변수에 값을 할당한 암묵적 전역도 마찬가지다.
  - ```javascript
    var foo = 1;
    function bar() {}
    baz = 3; // 암묵적 전역

    window.foo; // 1
    window.bar; // f bar()
    window.baz; // 3
    ```

- 하지만 **let, const로 선언한 전역 변수는 전역 객체의 프로퍼티가 아니다**. ([15장](../../week06/윤홍비/15.let,const키워드와_블록레벨스코프.md#전역-객체와-let))
  - ```javascript
    let foo = 1;
    window.foo; // undefined
    ```
- 이는 **전역 렉시컬 환경의 환경 레코드가 두 개로 나뉘어 있기 때문**이다.
  - 렉시컬 환경은 식별자와 값을 담는 환경 레코드와 상위 스코프를 가리키는 참조로 구성된다.
  - 이 중 환경 레코드가 전역에서만 두 종류로 나뉜다.
  - ```
    전역 렉시컬 환경
      ├─ 환경 레코드
      │    ├─ 객체 환경 레코드   → window (var, function이 저장된다)
      │    └─ 선언적 환경 레코드 → 엔진 내부 공간 (let, const가 저장된다)
      └─ 외부 렉시컬 환경 참조 → null (전역이므로 상위가 없다)
    ```

| 구분               | 실체            | 외부 접근     | 저장되는 것             |
| ------------------ | --------------- | ------------- | ----------------------- |
| 객체 환경 레코드   | window 객체     | `window.foo`  | 전역 var, function      |
| 선언적 환경 레코드 | 엔진 내부 공간  | 불가능        | let, const, 지역 변수   |

- 즉 객체 환경 레코드는 **window 객체 자체를 표로 사용**하므로 프로퍼티로 접근할 수 있다.
  - 반면 선언적 환경 레코드는 엔진 내부에 있어 코드로 접근할 수 없다.
  - 원래 전역 변수는 모두 window의 프로퍼티였으나 ES6에서 let, const를 도입하면서
  - 전역 객체의 오염을 막기 위해 별도의 환경 레코드를 사용하도록 한 것이다.
  - 주의할 점은 **스코프가 좁아지는 것이 아니라 저장소만 다르다**는 것이다.
    - let으로 선언해도 전역 스코프이므로 어디서나 참조할 수 있다.
    - ```javascript
      let foo = 1;

      function bar() {
        console.log(foo); // 1 (전역 스코프이므로 참조할 수 있다)
      }
      ```
  - 따라서 저장소가 달라도 **같은 전역 스코프이므로 이름이 충돌한다**.
    - ```javascript
      var x = 1;
      let x = 2; // SyntaxError: Identifier 'x' has already been declared
      ```
- 브라우저 환경의 모든 자바스크립트 코드는 **하나의 전역 객체를 공유한다**.
  - 여러 개의 script 태그로 분리되어 있어도 마찬가지다.

### 빌트인 전역 프로퍼티

- 전역 객체의 프로퍼티를 의미하며 주로 애플리케이션 전역에서 사용하는 값을 제공한다.

| 프로퍼티    | 설명                                    |
| ----------- | --------------------------------------- |
| `Infinity`  | 무한대를 나타내는 숫자값                |
| `NaN`       | 숫자가 아님(Not-a-Number)을 나타내는 값 |
| `undefined` | 원시 타입 undefined를 값으로 갖는다     |

- ```javascript
  console.log(3 / 0); // Infinity
  console.log(Number("xyz")); // NaN
  console.log(typeof NaN); // number
  ```

### 빌트인 전역 함수

- 애플리케이션 전역에서 호출할 수 있는 빌트인 함수로서 전역 객체의 메서드다.

#### eval

- 전달받은 문자열 코드를 런타임에 평가하여 실행한다.
  - ```javascript
    eval("1 + 2;"); // 3
    eval("var x = 5;");
    console.log(x); // 5
    ```
- eval 함수는 기존의 스코프를 런타임에 동적으로 수정한다.
  - **보안에 취약하고 최적화가 수행되지 않아 처리 속도가 느리다**.
  - 따라서 eval 함수의 사용은 금지해야 한다.

#### isFinite

- 전달받은 인수가 유한수인지 검사하여 불리언 값을 반환한다.
  - 인수가 숫자가 아닌 경우 숫자로 타입을 변환한 후 검사한다.
  - ```javascript
    isFinite(0); // true
    isFinite("10"); // true (숫자로 변환된다)
    isFinite(Infinity); // false
    isFinite(NaN); // false
    isFinite(null); // true (null은 0으로 변환된다)
    ```
- null이 0으로 변환되어 true가 되는 점에 주의해야 한다.

#### isNaN

- 전달받은 인수가 NaN인지 검사하여 불리언 값을 반환한다.
  - 마찬가지로 숫자가 아닌 경우 숫자로 타입을 변환한 후 검사한다.
  - ```javascript
    isNaN(NaN); // true
    isNaN("blabla"); // true (NaN으로 변환된다)
    isNaN(""); // false (0으로 변환된다)
    isNaN(null); // false (0으로 변환된다)
    ```
- 암묵적 타입 변환 때문에 혼란스러우므로 **ES6의 Number.isNaN을 사용하는 것이 안전하다**.
  - Number.isNaN은 타입 변환 없이 검사한다.
  - ```javascript
    isNaN("blabla"); // true
    Number.isNaN("blabla"); // false (문자열이지 NaN이 아니다)
    ```

#### parseFloat / parseInt

- parseFloat는 문자열을 실수로, parseInt는 정수로 해석하여 반환한다.
  - ```javascript
    parseFloat("3.14"); // 3.14
    parseFloat("10.53abc"); // 10.53 (앞부분만 해석한다)

    parseInt("10"); // 10
    parseInt("10.123"); // 10
    ```

- parseInt는 두 번째 인수로 **진법을 나타내는 기수**를 전달할 수 있다.
  - ```javascript
    parseInt("10", 2); // 2 (2진수 10 = 10진수 2)
    parseInt("10", 16); // 16
    parseInt("0x10"); // 16 (16진수 리터럴은 기수를 생략해도 된다)
    ```
- 첫 번째 문자가 숫자로 해석할 수 없으면 NaN을 반환한다.
  - 앞뒤 공백은 무시되며 중간에 공백이 있으면 첫 번째 문자열만 변환한다.
  - ```javascript
    parseInt("He110"); // NaN
    parseInt("34 45 66"); // 34
    ```

#### encodeURI / decodeURI

- encodeURI는 완전한 URI를 문자열로 전달받아 이스케이프 처리를 위해 인코딩한다.
  - 이스케이프 처리란 네트워크를 통해 정보를 공유할 때 어떤 시스템에서도 읽을 수 있는
  - 아스키 문자 셋으로 변환하는 것이다.
  - ```javascript
    const uri = "http://example.com?name=이웅모&job=programmer";
    const enc = encodeURI(uri);

    console.log(enc);
    // http://example.com?name=%EC%9D%B4%EC%9B%85%EB%AA%A8&job=programmer

    console.log(decodeURI(enc)); // 원래 URI로 복원된다
    ```

- URI 문법상 의미를 갖는 문자(`?`, `=`, `&`, `#` 등)나 알파벳, 숫자는 인코딩하지 않는다.

#### encodeURIComponent / decodeURIComponent

- encodeURIComponent는 URI **구성 요소**를 인수로 전달받아 인코딩한다.
  - 쿼리 스트링 구분자로 사용되는 `=`, `?`, `&`까지 **모두 인코딩**한다.
  - ```javascript
    const uriComp = "name=이웅모&job=programmer";

    encodeURIComponent(uriComp);
    // name%3D%EC%9D%B4%EC%9B%85%EB%AA%A8%26job%3Dprogrammer (=, &도 인코딩된다)

    encodeURI(uriComp);
    // name=%EC%9D%B4%EC%9B%85%EB%AA%A8&job=programmer (=, &는 유지된다)
    ```

| 함수                 | 대상            | `=`, `?`, `&` 처리 |
| -------------------- | --------------- | ------------------ |
| `encodeURI`          | 완전한 URI 전체 | 인코딩하지 않는다  |
| `encodeURIComponent` | URI의 구성 요소 | **인코딩한다**     |

- 즉 쿼리 스트링의 값 하나를 인코딩할 때는 encodeURIComponent를 사용해야 한다.
  - 값에 `&`가 포함되어 있어도 구분자로 오해되지 않기 때문이다.

### 암묵적 전역 다시 보기

- 선언하지 않은 식별자에 값을 할당하면 전역 객체의 프로퍼티가 된다.
  - ```javascript
    var x = 10;

    function foo() {
      y = 20; // window.y = 20
    }
    foo();

    console.log(x + y); // 30
    ```

- 이때 y는 **변수가 아니라 전역 객체의 프로퍼티**다.
  - 따라서 변수 호이스팅이 발생하지 않는다.
  - ```javascript
    console.log(x); // undefined (변수 호이스팅이 발생한다)
    console.log(y); // ReferenceError (호이스팅이 발생하지 않는다)

    var x = 10;
    function foo() {
      y = 20;
    }
    foo();
    ```

- 또한 변수가 아니므로 **delete 연산자로 삭제할 수 있다**.
  - ```javascript
    var x = 10;
    function foo() {
      y = 20;
    }
    foo();

    delete x; // false (변수는 삭제되지 않는다)
    delete y; // true (프로퍼티는 삭제된다)

    console.log(window.x); // 10
    console.log(window.y); // undefined
    ```
