### this 키워드

- 객체는 상태를 나타내는 프로퍼티와 동작을 나타내는 메서드를 하나의 논리적 단위로 묶은 자료구조다.
  - 메서드가 자신이 속한 객체의 프로퍼티를 참조하려면 **자신이 속한 객체를 가리키는 식별자를 참조**할 수 있어야 한다.
- 객체 리터럴 방식에서는 재귀적으로 자기 자신을 참조할 수 있다.
  - ```javascript
    const circle = {
      radius: 5,
      getDiameter() {
        return 2 * circle.radius; // 자기 자신을 참조한다
      },
    };
    ```
  - 하지만 이 방식은 **객체 이름이 바뀌면 함께 고쳐야 하므로** 바람직하지 않다.
- 생성자 함수 방식은 더 큰 문제가 있다.
  - 인스턴스를 생성하기 **이전에** 함수를 정의해야 하므로 참조할 식별자 이름을 알 수 없다.
  - ```javascript
    function Circle(radius) {
      // 이 시점에는 인스턴스를 가리키는 식별자가 무엇인지 알 수 없다
      ????.radius = radius;
    }

    const circle = new Circle(5); // 함수를 정의한 뒤에야 이름이 정해진다
    ```

- 따라서 자바스크립트는 **this라는 특수한 식별자**를 제공한다.
  - this는 자신이 속한 객체 또는 자신이 생성할 인스턴스를 가리키는 **자기 참조 변수**다.
  - this를 통해 자신이 속한 객체의 프로퍼티나 메서드를 참조할 수 있다.
- this는 자바스크립트 엔진에 의해 암묵적으로 생성되며 **코드 어디서든 참조할 수 있다**.
- 함수를 호출하면 arguments 객체와 this가 함수 내부에 암묵적으로 전달된다.
  - 개발자가 매개변수로 선언하지 않았는데도 함수 안에서 사용할 수 있다.

  - 함수를 호출하면 엔진이 실행 컨텍스트를 만들면서 arguments 객체와 this를 함께 넣어준다.

  - ```javascript
    function foo() {
      // 매개변수를 선언하지 않았지만 둘 다 사용할 수 있다
      console.log(arguments); // [Arguments] { '0': 1, '1': 2 }
      console.log(this); // window
    }
    foo(1, 2);
    ```
  - 즉 **인수로부터 만들어지는 것이 arguments, 호출 방식으로 결정되는 것이 this**다.

- this는 지역 변수처럼 사용할 수 있지만 **재할당은 불가능하다**.
  - ```javascript
    function foo() {
      this = {}; // SyntaxError: Invalid left-hand side in assignment
    }
    ```
  - 일반 변수는 개발자가 재할당할 수 있지만 this는 엔진만 연결할 수 있기 때문이다.
- 단 금지되는 것은 **함수 내부에서 this에 다른 값을 재할당하는 것**이다.
  - 가리키고 있는 객체의 내용을 변경하는 것은 가능하다.
  - ```javascript
    const obj = {
      a: 1,
      foo() {
        this.name = "Lee"; // 가능하다 (객체의 내용을 변경한다)
        // this = {};      // 불가능하다 (가리키는 대상을 바꾼다)
      },
    };

    obj.foo();

    console.log(obj); // { a: 1, foo: f, name: 'Lee' } (원본이 변경되었다)
    ```

  - this에는 객체의 **주소가 담겨 있으므로** 다른 변수에 복사해도 같은 객체를 가리킨다.
  - ```javascript
    const obj = {
      name: "Lee",
      foo() {
        const that = this; // 주소가 복사된다

        console.log(that === this); // true (같은 객체를 가리킨다)

        that.name = "Kim"; // this.name = 'Kim' 과 동일하다
      },
    };

    obj.foo();

    console.log(obj.name); // 'Kim' (that으로 바꿔도 원본이 바뀐다)
    ```

  - 이처럼 this를 변수에 담아두는 것은 중첩 함수에서 this를 유지할 때 사용된다.

- 정리하면 **const로 선언한 변수와 비슷하게 동작한다**.
  - 재할당은 금지되지만 가리키는 객체의 내용은 변경할 수 있다. ([15장](../../week06/윤홍비/15.let,const키워드와_블록레벨스코프.md#const-키워드와-객체))

- **this가 가리키는 값은 함수 호출 방식에 의해 동적으로 결정된다**. ([17장](../../week07/윤홍비/17.생성자함수에_의한_객체생성.md#this))
  - 자바와 같은 클래스 기반 언어에서 this는 언제나 인스턴스를 가리키지만
  - 자바스크립트의 this는 **호출할 때마다 달라진다**.
- 참고로 strict mode에서 일반 함수로 호출하면 this에 undefined가 바인딩된다. ([20장](./20.strict_mode.md#일반-함수의-this))

### 함수 호출 방식과 this 바인딩

- this 바인딩은 함수 호출 방식, 즉 **함수가 어떻게 호출되었는지에 따라 동적으로 결정**된다.
- 주의할 점은 **렉시컬 스코프와 this 바인딩은 결정 시기가 다르다**는 것이다.
  - 함수의 상위 스코프는 **함수를 정의할 때** 결정된다.
  - 하지만 this 바인딩은 **함수를 호출할 때** 결정된다.
  - 따라서 **같은 함수를 다르게 호출하면 this만 달라진다**.
  - ```javascript
    const name = "전역";

    function foo() {
      console.log(name); // 언제나 '전역' (정의된 위치가 고정이다)
      console.log(this.name); // 호출할 때마다 달라진다
    }

    const a = { name: "A", foo };
    const b = { name: "B", foo };

    a.foo(); // '전역', 'A'
    b.foo(); // '전역', 'B'
    foo(); // '전역', undefined (일반 함수 호출)
    ```

  - foo는 하나뿐이지만 호출 방식에 따라 this가 계속 바뀐다.
    - 반면 상위 스코프는 foo를 정의한 위치인 전역으로 고정되어 있다.
    - 따라서 어디서 어떻게 호출하든 name은 항상 '전역'이다.

| 함수 호출 방식                  | this가 가리키는 값                  |
| ------------------------------- | ----------------------------------- |
| 일반 함수 호출                  | 전역 객체 (strict mode는 undefined) |
| 메서드 호출                     | 메서드를 호출한 객체 (마침표 앞)    |
| 생성자 함수 호출                | 생성자 함수가 생성할 인스턴스       |
| `apply`/`call`/`bind` 간접 호출 | 첫 번째 인수로 전달한 객체          |

#### 일반 함수 호출

- 기본적으로 this에는 **전역 객체가 바인딩**된다.
  - 중첩 함수를 일반 함수로 호출해도 마찬가지다.
  - ```javascript
    function foo() {
      console.log(this); // window

      function bar() {
        console.log(this); // window (중첩 함수도 마찬가지다)
      }
      bar();
    }
    foo();
    ```

- strict mode에서는 undefined가 바인딩된다.
- **메서드 내에서 정의한 중첩 함수도 일반 함수로 호출하면 전역 객체가 바인딩된다**.
  - ```javascript
    var value = 1;

    const obj = {
      value: 100,
      foo() {
        console.log(this); // {value: 100, foo: f}
        console.log(this.value); // 100

        function bar() {
          console.log(this); // window (일반 함수로 호출되었다)
          console.log(this.value); // 1
        }
        bar();
      },
    };

    obj.foo();
    ```

- 콜백 함수도 일반 함수로 호출되면 마찬가지다.
  - ```javascript
    const obj = {
      value: 100,
      foo() {
        setTimeout(function () {
          console.log(this.value); // undefined (this는 window다)
        }, 100);
      },
    };

    obj.foo();
    ```

- 이처럼 **중첩 함수와 콜백 함수의 this가 메서드의 this와 달라지는 것은 헬퍼 함수로 동작하기 어렵게 만든다**.
  - 메서드 내부의 중첩 함수나 콜백 함수의 this를 일치시키는 방법은 다음과 같다.

##### 1. this를 변수에 할당

- ```javascript
  const obj = {
    value: 100,
    foo() {
      const that = this; // this를 변수에 저장한다

      setTimeout(function () {
        console.log(that.value); // 100
      }, 100);
    },
  };
  ```

- 관례적으로 that, self, \_this 같은 이름을 사용한다.

##### 2. bind 메서드 사용

- ```javascript
  const obj = {
    value: 100,
    foo() {
      setTimeout(
        function () {
          console.log(this.value); // 100
        }.bind(this),
        100,
      );
    },
  };
  ```

##### 3. 화살표 함수 사용

- 화살표 함수는 자신만의 this를 갖지 않고 **상위 스코프의 this를 그대로 사용**한다.
  - ```javascript
    const obj = {
      value: 100,
      foo() {
        setTimeout(() => console.log(this.value), 100); // 100
      },
    };
    ```
  - 가장 간결하므로 ES6 이후로는 주로 이 방법을 사용한다.

#### 메서드 호출

- 메서드를 호출한 객체, 즉 **마침표 앞에 기술한 객체**가 바인딩된다.
  - 주의할 점은 메서드를 소유한 객체가 아니라 **호출한 객체**라는 것이다.
  - ```javascript
    const person = {
      name: "Lee",
      getName() {
        return this.name;
      },
    };

    console.log(person.getName()); // 'Lee'
    ```

- 메서드는 객체에 포함된 것이 아니라 **독립적으로 존재하는 별도의 객체**다.
  - 객체의 프로퍼티가 함수 객체를 가리키고 있을 뿐이다.
  - 메모리 관점에서 보면 **객체는 함수의 주소만 갖고 있다**.
  - ```
    힙(Heap)
    ┌───────────────────────────┐
    │ 0x100: {                  │  person 객체
    │   name: "Lee"             │  값이 직접 들어있다
    │   getName → 0x200         │ ──┐  주소만 갖고 있다
    │ }                         │   │
    │                           │   │
    │ 0x200: function           │ ←─┘  함수 객체는 따로 존재한다
    │   (본문: return this.name) │
    └───────────────────────────┘
    ```
  - 따라서 다른 객체의 프로퍼티에 할당하면 그 객체의 메서드가 될 수도 있다.
  - ```javascript
    const anotherPerson = { name: "Kim" };

    anotherPerson.getName = person.getName; // 할당했다

    console.log(anotherPerson.getName()); // 'Kim' (호출한 객체가 바인딩된다)
    ```

  - 이때 함수가 복사되는 것이 아니라 **주소가 복사**되므로 같은 함수를 공유한다.
  - ```
    힙(Heap)
    ┌───────────────────────────┐
    │ 0x100: { name: "Lee",     │
    │          getName → 0x200  │ ──┐
    │        }                  │   │
    │                           │   │
    │ 0x300: { name: "Kim",     │   │
    │          getName → 0x200  │ ──┤  같은 주소를 가리킨다
    │        }                  │   │
    │                           │   │
    │ 0x200: function           │ ←─┘  함수는 여전히 하나뿐이다
    └───────────────────────────┘
    ```
  - ```javascript
    person.getName === anotherPerson.getName; // true (같은 함수다)
    ```
  - 즉 함수는 **어느 객체에도 속해 있지 않으므로** 자신이 누구의 메서드인지 알 수 없다.
    - 따라서 호출할 때 누가 호출했는지를 보고 this를 결정할 수밖에 없다.
    - 이것이 this가 동적으로 결정되는 근본적인 이유다.

- 마침표에서 떼어내 일반 함수로 호출하면 this가 전역 객체가 된다.
  - ```javascript
    const getName = person.getName; // 함수만 꺼냈다

    console.log(getName()); // '' (window.name은 빈 문자열이다)
    ```

  - 즉 **this는 함수에 붙어 있는 것이 아니라 호출하는 순간에 결정된다**.

- 프로토타입 메서드도 동일하다.
  - 메서드가 어디에 정의되어 있는지는 this와 무관하며 **호출한 객체**가 바인딩된다.
  - ```javascript
    function Person(name) {
      this.name = name;
    }

    Person.prototype.getName = function () {
      return this.name;
    };

    const me = new Person("Lee");
    console.log(me.getName()); // 'Lee' (this는 me다)

    Person.prototype.name = "Kim";
    console.log(Person.prototype.getName()); // 'Kim' (this는 Person.prototype이다)
    ```

  - 즉 `getName`은 `Person.prototype`에 있지만 this는 호출한 객체를 따라간다. ([19장](../../week07/윤홍비/19.프로토타입.md#프로토타입-체인))

#### 생성자 함수 호출

- 생성자 함수가 **생성할 인스턴스**가 바인딩된다.
  - ```javascript
    function Circle(radius) {
      this.radius = radius;
      this.getDiameter = function () {
        return 2 * this.radius;
      };
    }

    const circle1 = new Circle(5);
    console.log(circle1.getDiameter()); // 10
    ```

- new 연산자 없이 호출하면 일반 함수로 동작하므로 this가 전역 객체를 가리킨다. ([17장](../../week07/윤홍비/17.생성자함수에_의한_객체생성.md#new-연산자))
  - ```javascript
    const circle3 = Circle(15); // new를 빠뜨렸다

    console.log(circle3); // undefined
    console.log(radius); // 15 (전역 변수가 되었다)
    ```

#### Function.prototype.apply/call/bind 메서드에 의한 간접 호출

- apply, call, bind는 Function.prototype의 메서드이므로 **모든 함수가 상속받아 사용**할 수 있다.
- apply와 call은 **this로 사용할 객체와 인수를 전달하면서 함수를 호출**한다.
  - 본질적인 기능은 함수를 호출하는 것이다.
  - 두 메서드는 **인수를 전달하는 방식만 다르고 동일하게 동작**한다.
  - ```javascript
    function getThisBinding() {
      console.log(arguments);
      return this;
    }

    getThisBinding.apply(thisArg, [1, 2, 3]); // 배열로 전달한다
    getThisBinding.call(thisArg, 1, 2, 3); // 쉼표로 구분해 전달한다
    ```

  - 반면 bind는 **호출하지 않고 this가 교체된 새로운 함수를 반환**한다.
  - ```javascript
    const bound = getThisBinding.bind(thisArg, 1, 2, 3);

    console.log(bound); // f getThisBinding() (아직 실행되지 않았다)
    console.log(bound()); // {a: 1} (호출해야 실행된다)
    ```

  - 즉 apply와 call은 **그 호출에만** 적용되지만 bind는 **함수에 고정**된다.
  - ```javascript
    getThisBinding.call(thisArg); // {a: 1} (이번 호출만)
    getThisBinding(); // window (다시 원래대로)

    const bound = getThisBinding.bind(thisArg);
    bound(); // {a: 1}
    bound(); // {a: 1} (언제 호출해도 동일하다)
    ```

| 메서드  | 인수 전달 방식 | 함수 호출           | this 적용 범위 |
| ------- | -------------- | ------------------- | -------------- |
| `apply` | 배열           | 즉시 호출           | 해당 호출만    |
| `call`  | 쉼표로 구분    | 즉시 호출           | 해당 호출만    |
| `bind`  | 쉼표로 구분    | **호출하지 않는다** | **영구 고정**  |

- apply와 call의 대표적인 용도는 **유사 배열 객체에 배열 메서드를 사용하는 것**이다.
- 유사 배열 객체란 **인덱스와 length를 가져 배열처럼 보이지만 배열이 아닌 객체**를 말한다.
  - arguments 객체가 대표적이다. ([18장](../../week05/윤홍비/18.함수와_일급_객체.md#arguments-프로퍼티))
  - ```javascript
    function f() {
      console.log(arguments); // { 0: 1, 1: 2, 2: 3, length: 3 }

      arguments[0]; // 1 (인덱스로 접근할 수 있다)
      arguments.length; // 3 (길이도 있다)
      arguments.slice(); // TypeError (배열 메서드는 없다)
    }

    f(1, 2, 3);
    ```
  - 배열 메서드는 Array.prototype에 있는데 **유사 배열 객체는 이를 상속받지 않기 때문**이다.
  - ```
    진짜 배열  → Array.prototype  → slice, map, filter ...
    arguments → Object.prototype → 배열 메서드가 없다
    ```
- 하지만 메서드는 어느 객체에도 속해 있지 않으므로 **this만 바꿔주면 빌려 쓸 수 있다**.
  - slice는 내부적으로 this[0], this.length를 사용할 뿐이다.
  - 따라서 인덱스와 length만 있으면 진짜 배열인지 여부는 상관이 없다.
  - ```javascript
    function convertArgsToArray() {
      // Array.prototype의 slice를 빌려 arguments를 this로 지정해 실행한다
      return Array.prototype.slice.call(arguments);
    }

    convertArgsToArray(1, 2, 3); // [1, 2, 3] (진짜 배열이 된다)
    ```
  - NodeList나 문자열처럼 다른 유사 배열 객체에도 사용할 수 있다.
  - ```javascript
    const divs = document.querySelectorAll("div"); // NodeList (배열이 아니다)
    Array.prototype.forEach.call(divs, (el) => console.log(el));

    Array.prototype.map.call("abc", (c) => c.toUpperCase()); // ['A', 'B', 'C']
    ```
- 다만 ES6 이후에는 더 간단한 방법이 있으므로 이 패턴은 주로 기존 코드에서 보게 된다.
  - ```javascript
    Array.prototype.slice.call(arguments); // 기존 방식
    Array.from(arguments); // ES6
    [...arguments]; // 스프레드 문법

    function f(...args) {
      args.map((x) => x * 2); // 애초에 배열로 받는 것이 가장 깔끔하다
    }
    ```

- bind는 메서드의 this와 중첩 함수, 콜백 함수의 this가 불일치하는 문제를 해결할 때 유용하다.
  - 콜백은 내가 호출하는 것이 아니라 setTimeout이 호출하므로 this를 제어할 수 없다.
  - 따라서 **this를 미리 고정한 함수를 만들어 전달**한다.
  - ```javascript
    const person = {
      name: "Lee",
      foo(callback) {
        setTimeout(callback.bind(this), 100); // this를 고정한다
      },
    };

    person.foo(function () {
      console.log(`Hi! my name is ${this.name}`); // Hi! my name is Lee
    });
    ```

### 정리

| 함수 호출 방식                  | this 바인딩                         |
| ------------------------------- | ----------------------------------- |
| 일반 함수 호출                  | 전역 객체 (strict mode는 undefined) |
| 메서드 호출                     | 메서드를 호출한 객체                |
| 생성자 함수 호출                | 생성자 함수가 생성할 인스턴스       |
| `apply`/`call`/`bind` 간접 호출 | 첫 번째 인수로 전달한 객체          |

- 결국 this는 **함수를 어떻게 호출했는지**만 보면 알 수 있다.
  - 함수가 어디에 정의되어 있는지, 누가 소유하고 있는지는 관계가 없다.
  - 단 화살표 함수는 예외로 **상위 스코프의 this를 그대로 사용**한다. (26장)
