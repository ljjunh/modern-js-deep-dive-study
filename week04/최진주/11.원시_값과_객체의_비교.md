# 11장. 원시 값과 객체의 비교

자바스크립트의 값은 원시 값과 객체 두 종류뿐. 둘은 변경 가능 여부, 변수에 저장되는 것, 복사 시 전달되는 것 세 가지가 정반대로 동작함.

| 구분 | 원시 값 | 객체 |
|---|---|---|
| 변수에 저장되는 것 | 값 자체 | 참조 값(메모리 주소) |
| 변경 가능 여부 | 불가 (불변) | 가능 (가변) |
| 다른 변수에 할당 시 | 값 복사 | 주소 복사 |
| 복사 후 관계 | 완전히 독립 | 같은 객체 공유 |
| `===` 비교 기준 | 값 | 주소 |

---

## 원시 값은 불변

- 원시 타입: number, string, boolean, undefined, null, symbol, bigint
- 한 번 생성된 원시 값은 절대 바뀌지 않음
- 재할당은 값을 고치는 게 아니라 새 값을 만들고 변수가 그쪽을 가리키게 바꾸는 것
- 불변성은 값의 성질이지 변수의 성질이 아님
    - `const`는 변수 재할당 금지일 뿐, 값의 불변과는 별개 개념
    - `const`로 선언한 객체의 프로퍼티는 변경 가능

```js
let score = 80;
score = 90; // 80이 90으로 바뀐 게 아니라, 변수가 새 값 90을 가리킴
```

### 문자열의 특수성

- 문자열은 원시 값이지만 인덱스와 `length`로 접근 가능 → 유사 배열 객체
- 객체처럼 쓰는 순간 엔진이 임시 래퍼 객체를 만들었다 버림 (21장)
- 읽기는 가능, 인덱스로 쓰기는 무시됨 (strict 모드에서는 TypeError)

```js
const str = 'abc';
console.log(str[1]);  // 'b'
str[1] = 'X';         // 무시
console.log(str);     // 'abc'
```

### 값에 의한 전달

- 원시 값을 다른 변수에 할당하면 값이 복사되어 각자 다른 메모리 공간에 존재
- 한쪽을 재할당해도 다른 쪽에 영향 없음

```js
let a = 10;
let b = a;
a = 20;
console.log(a, b); // 20 10
```

## 객체는 가변

- 재할당 없이 프로퍼티 추가, 수정, 삭제 가능
- 변수에는 객체 자체가 아닌 객체가 있는 메모리 주소(참조 값)가 저장됨
- 설계 이유: 객체는 크기가 가변적이고 중첩 가능해서 변경마다 통째로 복사하면 비용이 큼
- 대가: 여러 변수가 하나의 객체를 공유할 수 있어 부작용(side effect) 발생 가능

```js
const user = { name: 'Jinju' };
user.name = 'Jin';   // 수정
user.role = 'FE';    // 추가
delete user.role;    // 삭제
// const인데도 가능 — 변수가 가리키는 주소는 그대로, 주소 안의 내용만 변경
```

### 배열도 객체

- `const` 배열에 `push`가 되는 이유는 배열이라서가 아니라 배열도 객체이기 때문
- 메서드로 내부를 고치는 것은 재할당이 아님

```js
const arr = [1, 2];
arr.push(3);     // 가능 — 배열 내부 변경
arr = [1, 2, 3]; // TypeError — 재할당
```

## 변수와 객체의 관계: 메모지와 집

- 객체 = 집, 변수 = 집 주소가 적힌 메모지
- 객체를 다른 변수에 할당 = 메모지 한 장 더 만들어 같은 주소를 베껴 적음
- 메모지는 여러 장, 집은 한 채

| 동작 | 코드 | 의미 | 다른 변수에 영향 |
|---|---|---|---|
| 프로퍼티 수정 | `obj.x = 1` | 주소 따라가서 집 안을 고침 | 있음 |
| 재할당 | `obj = {}` | 내 메모지에 다른 주소를 덮어씀 | 없음 |

```js
const a = { count: 0 };
const b = a;   // 주소 복사, 같은 객체
b.count = 99;
console.log(a.count); // 99
```

### 함수 매개변수에서의 동작

- 매개변수는 인수의 주소를 복사받은 별개의 변수
- 매개변수로 프로퍼티를 수정하면 바깥 객체에 영향
- 매개변수를 재할당하면 매개변수만 다른 객체를 가리킴, 바깥 변수는 그대로

```js
function change(o) {
  o.v = 1;        // 바깥 x와 같은 객체를 수정 → x.v = 1
  o = { v: 2 };   // o만 새 객체를 가리킴
  o.v = 3;        // 새 객체 수정, x와 무관
}
const x = { v: 0 };
change(x);
console.log(x.v); // 1
```

```js
function f(o) {
  o = { v: 9 };
  return o;
}
const a = { v: 1 };
const r = f(a);
console.log(a.v, r.v); // 1 9
```

### 용어 정리

- 참조 공유: 두 변수가 같은 객체를 가리키는 상태 (위 예시의 `o`와 `x`)
- 중첩: 객체 안에 객체가 있는 구조 (`a.address.city`)
- 둘은 다른 개념, 혼용 주의

### 참조에 의한 전달이라는 표현

- 값 전달이든 참조 전달이든 "변수에 저장된 값을 복사한다"는 점은 동일
- 원시 값은 저장된 값이 값 자체라 값이 복사, 객체는 저장된 값이 주소라 주소가 복사
- 엄밀히는 자바스크립트에 값에 의한 전달만 존재, 객체의 경우를 공유에 의한 전달(call by sharing)이라 구분하기도 함
- 진짜 참조 전달이라면 매개변수 재할당이 바깥에 반영되어야 하지만 그렇지 않음

## 객체 비교

- 객체끼리 `===`는 주소 비교, 내용이 같아도 다른 객체면 false
- 프로퍼티 값이 원시 값이면 값 비교

```js
const p1 = { name: 'Lee' };
const p2 = { name: 'Lee' };
console.log(p1 === p2);           // false
console.log(p1.name === p2.name); // true
```

## 객체 복사

| 방식 | 새 객체 생성 | 최상위 원시 값 | 중첩 객체 |
|---|---|---|---|
| `b = a` | 없음 | 공유 | 공유 |
| `b = {...a}` (얕은 복사) | 있음 | 독립 | 공유 |
| `structuredClone(a)` (깊은 복사) | 있음 | 독립 | 독립 |

- 얕은 복사가 중첩 객체를 공유하는 이유: 복사되는 프로퍼티 값이 객체 자체가 아니라 객체의 주소이기 때문
- `Object.assign({}, a)`도 얕은 복사
- `JSON.parse(JSON.stringify(a))`는 함수, undefined, Date 등이 손실되므로 `structuredClone` 권장
- `structuredClone`은 함수, DOM 노드 복사 불가

```js
const a = { name: 'Jinju', address: { city: 'Seoul' } };

const b = { ...a };
b.name = 'Jin';
b.address.city = 'Busan';
console.log(a.name);         // 'Jinju' — 독립
console.log(a.address.city); // 'Busan' — 공유

const c = structuredClone(a);
c.address.city = 'Jeju';
console.log(a.address.city); // 'Busan' — 영향 없음
```

## Object.freeze

- 객체의 프로퍼티 추가, 수정, 삭제를 막음, 읽기는 가능
- 일반 모드에서는 조용히 무시, strict 모드(ES 모듈, 클래스 내부)에서는 TypeError
- 되돌릴 수 없음, 변경이 필요하면 복사해서 새 객체 생성
- `Object.isFrozen(obj)`으로 확인

### 얕은 동결

- 최상위 프로퍼티만 동결, 중첩 객체는 동결되지 않음
- 프로퍼티가 동결된다는 것은 그 프로퍼티에 재할당 못 한다는 뜻
- 프로퍼티가 가리키는 객체는 별개이므로 내부 변경 가능

```js
const theme = Object.freeze({ color: { primary: '#03C75A' }, list: [1, 2] });
theme.color = {};             // 무시 — 최상위 재할당 차단
theme.color.primary = 'red';  // 가능 — 중첩 객체는 동결 안 됨
theme.list.push(3);           // 가능 — 같은 이유
```

### 깊은 동결

```js
function deepFreeze(obj) {
  Object.values(obj).forEach(v => {
    if (typeof v === 'object' && v !== null) deepFreeze(v);
  });
  return Object.freeze(obj);
}
```

### 비슷한 메서드

| 메서드 | 추가 | 삭제 | 수정 |
|---|---|---|---|
| `Object.preventExtensions` | 불가 | 가능 | 가능 |
| `Object.seal` | 불가 | 불가 | 가능 |
| `Object.freeze` | 불가 | 불가 | 불가 |

### TypeScript `as const`와의 차이

- `as const`는 타입 수준에서만 읽기 전용, 런타임에는 아무것도 안 함
- `Object.freeze`는 런타임에서 실제로 차단
- 둘을 같이 쓰면 컴파일과 런타임 모두 보호

## 실무 연결

### React 상태 업데이트

- React는 이전 상태와 새 상태를 `===`로 비교해 리렌더 여부 결정
- 객체는 주소 비교이므로 내용만 바꾸고 주소가 같으면 변경 감지 실패
- 기존 객체를 직접 수정하지 않고 새 객체를 만들어 전달해야 함

```js
// 문제: 같은 객체를 수정 → 주소 동일 → 리렌더 안 됨
function addItem(item) {
  cart.items.push(item);
  setCart(cart);
}

// 개선: 새 객체 생성
function addItem(item) {
  setCart(prev => ({
    ...prev,
    items: [...prev.items, item],
  }));
}
```

- 중첩 상태를 바꿀 때는 바꾸는 경로의 모든 단계에서 새 객체 필요
    - `{...prev}`만 하면 `prev.items`는 여전히 공유 상태

### 디자인 토큰, 설정 객체

- 여러 컴포넌트가 공유하는 테마 객체를 한 곳에서 직접 수정하면 전체 UI에 영향
- 토큰, 색상 상수, 설정 객체는 `Object.freeze` 또는 `as const`로 보호
- React 상태 객체에는 freeze 불필요, 어차피 새 객체를 만드는 패턴

### 결제 데이터 처리

- 서버에서 받은 주문 객체를 가공할 때 원본을 직접 수정하면 다른 곳에서 원본을 참조하는 로직이 깨짐
- 가공 전 복사본 생성, 중첩 구조면 깊은 복사

## 핵심 정리

- `const`는 메모지(변수)를 고정, 집(값)을 고정하는 게 아님
- `obj.x = 1`은 집을 고침 → 같은 집을 가리키는 모든 변수에 영향
- `obj = {}`는 메모지를 바꿈 → 다른 변수에 영향 없음
- 얕은 복사와 얕은 동결은 같은 원리, 중첩 객체는 주소만 다루므로 공유됨
- 자바스크립트에는 값에 의한 전달만 존재, 객체는 그 값이 주소일 뿐
