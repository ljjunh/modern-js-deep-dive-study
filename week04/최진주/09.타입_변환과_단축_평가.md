# 9장. 타입 변환과 단축 평가

## 핵심 요약

- 타입 변환은 개발자가 직접 하는 명시적 변환, 엔진이 문맥에 맞춰 하는 암묵적 변환으로 구분
- 원시값은 변경 불가하므로 변환 시 기존 값을 바꾸지 않고 새 값을 생성
- 불리언 변환과 숫자 변환은 서로 다른 규칙, 같은 값이라도 결과가 따로 결정됨
- `&&`, `||`는 불리언이 아닌 결과를 결정한 피연산자 자체를 반환
- `?.`, `??`는 null, undefined만 기준으로 판단 (falsy 전체가 아님)

```js
const x = 10;
const str = x + '';
console.log(typeof x, typeof str); // number string
```

## 변환 결과표

### 불리언 변환과 숫자 변환 비교

| 값 | 불리언 변환 | 숫자 변환 |
|---|---|---|
| `''` | false | 0 |
| `' '` (공백) | true | 0 |
| `'0'` | true | 0 |
| `'abc'` | true | NaN |
| `null` | false | 0 |
| `undefined` | false | NaN |
| `[]` | true | 0 |
| `{}` | true | NaN |

- 불리언 변환은 빈 문자열 여부만 판단, 숫자 변환은 숫자로 읽히는지 판단
- Falsy 값: `false`, `undefined`, `null`, `0`, `-0`, `NaN`, `''`
- 위 목록 외 값은 모두 Truthy (빈 배열, 빈 객체, 공백 문자열 포함)

### null과 undefined의 숫자 변환 차이

- 명세상 규칙: null은 0, undefined는 NaN
- null은 의도적으로 비워 둔 값, undefined는 아직 값이 정해지지 않은 상태로 해석 가능
- 공식적인 설계 이유가 명세에 명시되어 있지는 않음

```js
null + 1;           // 1
undefined + 1;      // NaN
undefined + null;   // NaN (NaN + 0)
```

### NaN

- 숫자 연산이 실패했을 때의 결과, 타입은 number
- 자기 자신과도 일치하지 않으므로 `Number.isNaN()`으로 확인

```js
typeof NaN;              // 'number'
NaN === NaN;             // false
isNaN('abc');            // true  (먼저 숫자로 변환 후 판단)
Number.isNaN('abc');     // false (NaN 값 자체인지만 판단)
```

## 암묵적 변환 규칙

| 상황 | 변환 방향 | 예시 |
|---|---|---|
| `+` 피연산자 중 문자열 존재 | 문자열 | `'10' + 5 // '105'` |
| `-`, `*`, `/`, 단항 `+` | 숫자 | `'10' - 5 // 5` |
| `if`, 삼항 조건, `!` | 불리언 | `if ('0')` 실행됨 |

- 결과의 타입까지 확인하는 습관 필요 (`'105'`는 문자열)
- 심벌은 문자열로 암묵적 변환 시 TypeError 발생

## 명시적 변환 방법

| 목표 | 방법 |
|---|---|
| 문자열 | `String(v)`, `v.toString()`, `v + ''` |
| 숫자 | `Number(v)`, `parseInt(v, 10)`, `parseFloat(v)`, `+v` |
| 불리언 | `Boolean(v)`, `!!v` |

### 래퍼 함수 호출 시 new 사용 금지

- `new` 없이 호출하면 원시값 반환, `new`와 호출하면 객체 반환
- 객체는 항상 truthy이고 원시값과 일치 비교 불가

```js
typeof String(1);       // 'string'
typeof new Number(5);   // 'object'
new Number(0) === 0;    // false

if (new Boolean(false)) {
  console.log('실행됨'); // 실행됨
}
```

### String(v)와 v.toString() 차이

- `String(v)`는 함수에 값을 전달, `v.toString()`은 값이 가진 메서드 호출
- null, undefined는 속성과 메서드가 없으므로 점 접근 시 TypeError
- API 응답처럼 null 가능성이 있는 값은 `String()` 사용

```js
String(null);       // 'null'
null.toString();    // TypeError
(500).toString();   // '500' (숫자 리터럴은 괄호로 감싸야 소수점과 구분됨)
```

### Number, parseInt, parseFloat 차이

| 입력 | `Number` | `parseInt` | `parseFloat` |
|---|---|---|---|
| `'10px'` | NaN | 10 | 10 |
| `'3.99원'` | NaN | 3 | 3.99 |
| `'px10'` | NaN | NaN | NaN |
| `''` | 0 | NaN | NaN |
| `null` | 0 | NaN | NaN |

- `Number`: 문자열 전체가 숫자여야 변환, 모든 타입 입력 가능
- `parseInt`: 앞에서부터 읽을 수 있는 정수까지만 변환, 문자열 전용
- `parseFloat`: `parseInt`와 동일하나 소수점까지 변환
- 변환 실패 시 에러가 아닌 NaN 반환, 버그가 조용히 화면까지 전달될 수 있음

## 단축 평가

### 논리 연산자의 반환값

```js
'Cat' && 'Dog';   // 'Dog'
'Cat' || 'Dog';   // 'Cat'
false && 'Dog';   // false
0 || 10;          // 10
```

- `&&`: 좌항이 falsy면 좌항 반환, truthy면 우항 반환
- `||`: 좌항이 truthy면 좌항 반환, falsy면 우항 반환
- 활용: 조건부 실행, 객체 존재 확인 후 속성 접근, 기본값 설정

### &&와 ?. 비교

| 코드 | user가 `null` | user가 `''` |
|---|---|---|
| `user && user.name` | null | `''` |
| `user?.name` | undefined | undefined |

- `&&`는 falsy 전체에서 멈춤, `?.`는 null, undefined에서만 멈춤
- `''.name`은 문자열에 name 속성이 없으므로 undefined (에러 아님)

```js
const str = '';
str && str.length;   // ''
str?.length;         // 0
```

### ||와 ?? 비교

```js
const discount = 0;
discount || 1000;    // 1000 (유효한 0이 기본값으로 대체됨)
discount ?? 1000;    // 0
```

- 0, 빈 문자열이 유효한 값이면 `??` 사용
- 빈 문자열도 기본값으로 대체해야 하면 `||` 사용
- 둘 중 선택은 빈 상태(empty state)를 어떻게 보여줄지에 대한 기획 판단에 따름

```js
const user = { name: '' };
user?.name ?? '비회원';   // ''
user?.name || '비회원';   // '비회원'
```

## 실무 사례

### 폼 요소의 value는 항상 문자열

- DOM 명세상 `value`는 문자열 타입, `type="number"`도 동일
- `select`, `textarea`도 문자열, checkbox 선택 여부는 `checked`(불리언) 사용
- 숫자가 필요하면 `Number()` 또는 `valueAsNumber`로 변환

```js
// <input type="number">에 3 입력
input.value + 2;          // '32'
Number(input.value) + 2;  // 5
input.valueAsNumber;      // 3
```

### 금액 문자열 변환

```js
parseInt('10,000');                      // 10
Number('10,000');                        // NaN
Number('10,000'.replace(/,/g, ''));      // 10000
```

- 금액처럼 오차가 허용되지 않는 값은 `Number`로 엄격하게 변환
- `parseInt`는 잘못된 값을 조용히 반환하므로 버그 발견이 어려움
- 단위가 붙은 CSS 값(`getComputedStyle` 결과 등)은 `parseFloat` 적합

### React 조건부 렌더링

| `{}` 안의 값 | 렌더링 결과 |
|---|---|
| `false`, `true`, `null`, `undefined` | 렌더링하지 않음 |
| `''` | 빈 텍스트 |
| `0`, `NaN` | 텍스트로 렌더링 |

- React는 값의 의미가 아닌 타입 기준으로 렌더링 결정
- 숫자 0은 표시해야 하는 데이터일 수 있으므로 숨기지 않음

```jsx
// 0건일 때 화면에 0 노출
{cartCount && <Badge count={cartCount} />}
{items.length && <List items={items} />}

// 비교식으로 불리언 생성
{cartCount > 0 && <Badge count={cartCount} />}
{items.length > 0 && <List items={items} />}

// 0건도 항상 표시하고 null만 대체
<span>{cartCount ?? 0}</span>
```
