# 10장. 객체 리터럴

## 객체의 구조

- 객체: 0개 이상의 프로퍼티(키 + 값) 묶음
- 원시 값(number, string, boolean, undefined, null, symbol, bigint)을 제외한 모든 값은 객체
- 원시 값은 변경 불가, 객체는 변경 가능
- 값이 함수인 프로퍼티는 메서드로 구분 → 객체 = 상태(프로퍼티) + 동작(메서드)

```js
const counter = {
  num: 0,                        // 프로퍼티
  increase() { this.num++; },    // 메서드
};
```

---

## 객체 리터럴로 생성

- 클래스 정의 없이 `{}`만으로 생성, 변수에 할당되는 시점에 평가되어 객체 생성
- 코드 블록 `{}`와 모양이 같지만 값으로 평가되는 표현식이므로 끝에 세미콜론

| 키 종류 | 따옴표 | 예시 |
|---|---|---|
| 식별자 규칙 준수 | 생략 가능 | `name: 'Lee'` |
| 하이픈·공백 포함 | 필수 | `'last-name': 'Lee'` |
| 숫자 | 생략 가능, 문자열로 변환 | `1: 10` → 키는 `'1'` |

- 키 중복 시 에러 없이 뒤의 값이 앞의 값을 덮어씀

```js
const obj = { a: 1, a: 2 };
console.log(obj); // { a: 2 }
```

## 프로퍼티 접근: 마침표 vs 대괄호

| 표기 | 형태 | 키의 해석 |
|---|---|---|
| 마침표 | `obj.name` | 글자 그대로 `'name'` |
| 대괄호 | `obj['name']` | 문자열 `'name'` |
| 대괄호 + 변수 | `obj[name]` | 변수 `name`의 값 |

- 대괄호 안에 따옴표 없이 쓰면 변수 참조 → 변수가 없으면 ReferenceError
- 키가 식별자 규칙을 어기면(`'last-name'`) 대괄호만 가능
- `obj.last-name`은 `obj.last - name`으로 평가되어 NaN

```js
const person = { name: 'Lee' };
const key = 'name';

person.name;      // 'Lee'
person['name'];   // 'Lee'
person[key];      // 'Lee'  (key 변수의 값 'name'이 키)
person[name];     // ReferenceError: name is not defined (name 변수 없음)
```

## 읽기와 쓰기의 차이

- 없는 프로퍼티 읽기 → `undefined` 반환, 객체는 변하지 않음
- 없는 프로퍼티에 할당 → 그 시점에 프로퍼티 생성
- 없는 변수 참조 → ReferenceError

```js
const o = { a: 1 };
o.b;        // undefined, o는 여전히 { a: 1 }
o.b = 2;    // 이때 생성 → { a: 1, b: 2 }
delete o.b; // 삭제 → { a: 1 }
delete o.c; // 없는 키 삭제는 에러 없이 무시
c;          // ReferenceError
```

- 결과가 다른 이유
  - 프로퍼티 접근: 객체 안에서 키 탐색, 없으면 "없음"을 뜻하는 `undefined` 반환
  - 변수 참조: 스코프 체인(안쪽 → 바깥쪽 → 전역)에서 식별자 탐색, 없으면 에러
- 실무: API 응답에서 `res.data.user.address`처럼 중간 값이 없을 때 `undefined.xxx` 접근으로 런타임 에러 발생 → 옵셔널 체이닝 `?.`의 필요성

## ES6 확장 문법

### 프로퍼티 축약

- 변수 이름과 키가 같으면 키 생략
- 같은 이름의 변수가 스코프에 존재해야 함

```js
const amount = 1000, method = 'card';
const payload = { amount, method };
// { amount: 1000, method: 'card' }
```

### 계산된 프로퍼티 이름

- 키 자리에 그냥 쓰면 글자 그대로 키, `[]`로 감싸면 표현식을 평가한 결과가 키
- 대괄호 안에는 변수, 문자열 연결, 함수 호출, 템플릿 리터럴 등 모든 표현식 가능
- ES5는 리터럴 밖에서 `obj['a' + 'b'] = 1`로 추가해야 했음

```js
const k = 'age';
function getKey() { return 'id'; }

const obj = {
  k: 1,                 // 키 'k'
  [k]: 2,               // 키 'age'
  ['a' + 'b']: 3,       // 키 'ab'
  [getKey()]: 4,        // 키 'id'
};
// { k: 1, age: 2, ab: 3, id: 4 }
```

- 키 자리에 올 수 있는 것은 식별자·문자열·숫자뿐
- `e.target.name`처럼 점이 포함된 표현식을 대괄호 없이 쓰면 SyntaxError

### 메서드 축약

- `function` 키워드와 콜론 생략, 키(메서드 이름)는 유지
- 축약 메서드는 생성자로 사용 불가(`new` 불가), 상세는 26장

```js
const obj = {
  a: function () {},   // new obj.a() 가능
  b() {},              // new obj.b() → TypeError
};
```

## 함수 참조와 함수 호출

| 표기 | 의미 | 시점 |
|---|---|---|
| `fn` | 함수 객체 자체 | 실행 안 함 |
| `fn()` | 함수 실행 후 리턴값 | 즉시 실행 |

- 이벤트 핸들러에는 함수 자체를 전달해야 함
- 함수 자체를 전달하면 이벤트 발생 시 첫 번째 인자로 이벤트 객체가 전달됨

```jsx
function greet(who) { console.log(`Hi ${who}`); }

<button onClick={greet}>A</button>              // 클릭 시 'Hi [object Object]' (who = 이벤트 객체)
<button onClick={greet('진주')}>B</button>       // 렌더링 시 1회 실행, 클릭 시 무반응 (onClick = undefined)
<button onClick={() => greet('진주')}>C</button> // 클릭 시 'Hi 진주'
```

- 인자와 이벤트 둘 다 필요하면 `(e) => fn(id, e)`

## 실무 패턴: 입력 폼 상태 관리

- 계산된 프로퍼티 이름 + 스프레드로 핸들러 하나가 여러 input 담당
- input의 `name` 속성값이 키가 되어 해당 프로퍼티를 생성 또는 갱신

```jsx
function handleChange(e) {
  setForm({ ...form, [e.target.name]: e.target.value });
}

<input name="cardNumber" onChange={handleChange} />
<input name="expiry" onChange={handleChange} />
```

- 동작 순서
  - `...form`으로 이전 상태의 프로퍼티를 새 객체에 복사
  - `e.target.name`을 평가해 `'cardNumber'` 등의 키 결정
  - 같은 키가 이미 있으면 뒤의 값이 덮어씀 → 갱신

## 정리

- 객체는 키와 값의 집합, 런타임에 프로퍼티 추가·삭제 가능
- 읽기는 생성이 아님 → 없는 키는 `undefined`, 할당 시에만 생성
- 대괄호는 "안쪽을 계산해서 키로 사용"하라는 표시
- 축약 표현 3가지(프로퍼티·계산된 키·메서드)는 React 코드에서 상시 사용
- `fn`과 `fn()` 구분, 핸들러에는 함수 자체 전달
