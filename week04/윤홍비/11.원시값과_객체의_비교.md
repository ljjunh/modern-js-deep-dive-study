### 원시 값과 객체의 비교

- 자바스크립트의 데이터 타입은 크게 원시 타입과 객체 타입으로 구분된다.

|                    | 원시 값                           | 객체(참조) 값                      |
| ------------------ | --------------------------------- | ---------------------------------- |
| 변경 가능 여부     | 변경 불가능한 값(immutable value) | 변경 가능한 값(mutable value)      |
| 변수에 저장되는 값 | 원시 값 자체                      | 참조 값(객체가 저장된 메모리 주소) |
| 다른 변수에 할당   | 원시 값이 복사(값에 의한 전달)    | 참조 값이 복사(참조에 의한 전달)   |

### 원시 값

#### 변경 불가능한 값

- 원시 타입의 값은 변경 불가능한 값으로 한번 생성된 원시 값은 읽기 전용(read only) 값이다.
- 여기서 "변경 불가능"은 **변수**가 아니라 **값 자체**에 대한 표현이다.
  - 변수는 언제든 재할당을 통해 변수 값을 변경(교체)할 수 있다.
  - 하지만 값 자체는 수정할 수 없다.
  - 즉 재할당은 변수를 갈아끼우는 것이고, 변경은 값 자체를 수정하는 것이다.
    - 원시 값은 재할당만 가능하고, 객체는 둘 다 가능하다.
- 원시 값을 할당한 변수에 새로운 원시 값을 재할당하면
  - 메모리 공간에 저장된 값을 변경하는 것이 아니라
  - 새로운 메모리 공간을 확보하고 재할당한 원시 값을 저장한 후, 변수가 참조하던 주소를 변경한다.
  - 이러한 특성을 불변성(immutability)이라 한다.
- 불변성을 갖는 원시 값을 할당한 변수는 재할당 이외에 변수 값을 변경할 수 있는 방법이 없다.
  - 따라서 예기치 않은 변경, 즉 상태 변경을 걱정할 필요가 없다.

#### 문자열과 불변성

- 원시 값인 문자열은 다른 원시 값과 비교할 때 독특한 특징이 있다.
  - 문자열은 0개 이상의 문자로 이뤄진 집합이며 1개의 문자는 2바이트의 메모리 공간에 저장된다.
  - 즉 문자열은 몇 개의 문자로 이뤄졌느냐에 따라 필요한 메모리 공간의 크기가 결정된다.
- 자바스크립트는 개발자의 편의를 위해 원시 타입인 문자열 타입을 제공한다.
  - 문자열은 유사 배열 객체이면서 이터러블이므로 배열과 유사하게 각 문자에 접근할 수 있다.
  - ```javascript
    var str = "string";

    console.log(str[0]); // 's'
    console.log(str.length); // 6
    console.log(str.toUpperCase()); // 'STRING'
    ```

- 하지만 문자열은 원시 값이므로 변경할 수 없다. 이때 에러가 발생하지 않는다.
  - ```javascript
    var str = "string";

    str[0] = "S"; // 에러 없이 무시된다.
    console.log(str); // 'string'
    ```

- 원시 값은 어떤 일이 있어도 불변하므로 데이터의 신뢰성을 보장한다.

#### 값에 의한 전달

- 변수에 원시 값을 갖는 변수를 할당하면 할당받는 변수에는 할당되는 변수의 원시 값이 복사되어 전달된다.
  - 이를 값에 의한 전달(pass by value)이라 한다.
  - ```javascript
    var score = 80;
    var copy = score;

    console.log(score, copy); // 80 80
    console.log(score === copy); // true

    score = 100; // score만 변경

    console.log(score, copy); // 100 80
    console.log(score === copy); // false
    ```

- `score`와 `copy`는 숫자 값 80을 갖는다는 점에서는 동일하지만
  - **다른 메모리 공간에 저장된 별개의 값**이다.
  - 따라서 `score` 값을 변경해도 `copy` 값에는 어떠한 영향도 주지 않는다.
- 엄밀히 말하면 변수에 변수를 할당할 때 무엇이 어떻게 전달되는지는 자바스크립트 엔진의 구현에 따라 다를 수 있다.
  - 중요한 것은 **두 변수의 원시 값은 서로 간섭할 수 없는 별개의 값**이라는 것이다.

  - 반면 객체는 변경 가능하므로 참조를 공유하면 서로 영향을 주고받는다.

### 객체

- 객체는 프로퍼티의 개수가 정해져 있지 않으며 동적으로 추가되고 삭제할 수 있다.
  - 프로퍼티 값에도 제약이 없다.
  - 따라서 객체는 원시 값과 같이 확보해야 할 메모리 공간의 크기를 사전에 정해둘 수 없다.
- 자바스크립트 객체의 관리 방식은 프로퍼티 키를 인덱스로 사용하는 해시 테이블이라 생각할 수 있다.
  - 단, 클래스 없이 객체를 생성할 수 있고 프로퍼티와 메서드를 동적으로 추가할 수 있어 편리하지만
  - 그만큼 성능 면에서 비효율적이고 생성과 프로퍼티 접근에 비용이 많이 든다.
  - V8 자바스크립트 엔진에서는 이를 보완하기 위해 히든 클래스(hidden class)라는 방식을 사용한다.

#### 변경 가능한 값

- 객체 타입의 값, 즉 객체는 변경 가능한 값(mutable value)이다.
- 객체를 할당한 변수가 기억하는 메모리 주소를 통해 메모리 공간에 접근하면 **참조 값(reference value)** 에 접근할 수 있다.
  - 참조 값은 생성된 객체가 저장된 메모리 공간의 주소 그 자체다.
  - 원시 값을 할당한 변수는 "값을 갖는다", 객체를 할당한 변수는 "참조한다"고 표현한다.
- 객체는 변경 가능한 값이므로 재할당 없이 객체를 직접 변경할 수 있다.
  - 프로퍼티를 동적으로 추가할 수 있고, 값을 갱신할 수 있으며, 삭제할 수도 있다.
  - ```javascript
    var person = { name: "Lee" };

    person.name = "Kim"; // 프로퍼티 값 갱신
    person.address = "Seoul"; // 프로퍼티 동적 생성

    console.log(person); // { name: 'Kim', address: 'Seoul' }
    ```

- 객체를 생성하고 관리하는 방식은 매우 복잡하며 비용이 많이 드는 일이다.
  - 객체를 변경할 때마다 원시 값처럼 복사해서 새로 만든다면 명확하고 안전하겠지만
  - 객체는 크기가 매우 클 수도 있고, 프로퍼티 값이 객체일 수도 있어서 복사 비용이 많이 든다.
  - 따라서 메모리의 효율적 소비가 어렵고 성능이 나빠진다.
- 이러한 구조적 단점에 따른 부작용이 있다.
  - 원시 값과는 다르게 **여러 개의 식별자가 하나의 객체를 공유할 수 있다**는 것이다.

#### 참조에 의한 전달

- 객체를 가리키는 변수를 다른 변수에 할당하면 원본의 참조 값이 복사되어 전달된다.
  - 이를 참조에 의한 전달(pass by reference)이라 한다.
  - ```javascript
    var person = { name: "Lee" };

    // 참조 값을 복사(얕은 복사)
    var copy = person;

    // copy를 통해 객체를 변경
    copy.name = "Kim";

    // person을 통해 객체를 변경
    person.address = "Seoul";

    // 두 변수는 같은 객체를 가리킨다.
    console.log(person); // { name: 'Kim', address: 'Seoul' }
    console.log(copy); // { name: 'Kim', address: 'Seoul' }
    ```

- `person`과 `copy`는 **동일한 참조 값**을 갖는다. 즉 하나의 객체를 공유한다.
  - 따라서 어느 한쪽에서 객체를 변경하면 서로 영향을 주고받는다.
- 결국 "값에 의한 전달"과 "참조에 의한 전달"은 식별자가 기억하는 메모리 공간에 저장된 값을 복사해서 전달한다는 면에서 동일하다.
  - 다만 식별자가 기억하는 메모리 공간에 저장된 값이 **원시 값인지 참조 값인지**의 차이만 있을 뿐이다.
  - 따라서 자바스크립트에는 "참조에 의한 전달"은 존재하지 않고 "값에 의한 전달"만이 존재한다고 말할 수 있다.

#### 얕은 복사와 깊은 복사

- 객체를 프로퍼티 값으로 갖는 객체의 경우
  - 얕은 복사(shallow copy) : 한 단계까지만 복사하는 것
  - 깊은 복사(deep copy) : 객체에 중첩되어 있는 객체까지 모두 복사하는 것
- 얕은 복사는 새로운 객체를 만들고 각 프로퍼티의 값을 하나씩 복사한다.
  - 이때 프로퍼티 값이 원시 값이면 값이 복사되고, 객체면 그 값이 주소이므로 주소가 복사된다.
  - ```javascript
    const o = { a: 1, x: { y: 1 } };
    const c1 = { ...o };

    // a의 값은 1 → 숫자 1이 복사된다.
    // x의 값은 주소 → 주소가 복사되어 같은 객체를 가리킨다.
    ```
  - 따라서 1단계 프로퍼티는 분리되지만 중첩 객체는 공유된다.
    - ```javascript
      c1.a = 999; // o.a는 1 그대로 (값이 복사되었으므로)
      c1.x.y = 999; // o.x.y도 999로 변경 (주소를 공유하므로)
      ```
  - 깊은 복사는 주소를 복사하지 않고 그 주소를 따라가 중첩 객체까지 새로 만든다.
- 즉 복사는 항상 값을 복사하는 동작이며, 객체의 값이 주소이기에 대상을 공유하게 되는 것이다.
- ```javascript
  const o = { x: { y: 1 } };

  // 얕은 복사
  const c1 = { ...o };
  console.log(c1 === o); // false
  console.log(c1.x === o.x); // true (중첩 객체는 참조를 공유)

  // 깊은 복사
  const c2 = structuredClone(o);
  console.log(c2 === o); // false
  console.log(c2.x === o.x); // false (중첩 객체까지 복사)
  ```

- 얕은 복사와 깊은 복사로 생성된 객체는 모두 원본과는 다른 별개의 객체다.
  - 단, 얕은 복사는 중첩된 객체의 경우 참조 값을 복사하고, 깊은 복사는 원시 값처럼 완전한 복사본을 만든다.
- 참고로 원시 값을 할당한 변수를 다른 변수에 할당하는 것을 깊은 복사,
  - 객체를 할당한 변수를 다른 변수에 할당하는 것을 얕은 복사라고 부르는 경우도 있다.

### 정리

- 원시 값은 변경 불가능한 값이므로 변수에 재할당하면 **새로운 메모리 공간**을 확보한다.
  - 다른 변수에 할당하면 값이 복사되므로 두 변수는 서로 간섭할 수 없다.
- 객체는 변경 가능한 값이므로 재할당 없이 **직접 변경**할 수 있다.
  - 다른 변수에 할당하면 참조 값이 복사되므로 두 변수가 하나의 객체를 공유한다.
  - 따라서 한쪽에서의 변경이 다른 쪽에 영향을 준다.
- 즉 원시 값은 "값이 복사", 객체는 "주소가 복사"된다.
