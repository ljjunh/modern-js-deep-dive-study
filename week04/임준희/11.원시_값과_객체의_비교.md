|                      | 원시 값                  | 객체                           |
| -------------------- | ------------------------ | ------------------------------ |
| 변경 가능성          | immutable                | mutable                        |
| 변수에 저장되는 것   | 실제 값                  | 참조 값(메모리 주소)           |
| 다른 변수에 할당하면 | 값 복사 (값에 의한 전달) | 참조 값 복사(참조에 의한 전달) |

### 원시 값

"원시 값은 변경 불가능하다"는 말은 값 자체를 바꿀 수 없다는 뜻이지 변수를 바꿀 수 없다는 뜻이 아니다. 변수는 재할당으로 언제든 다른 값을 가리킬 수 있다.
재할당하면 변수가 참조하는 메모리 주소가 바뀐다. 만약 원시 값이 변경 가능했다면 같은 자리에서 값을 덮어썼을 것이고 주소는 안 바뀌었을 것이다.

### 상수와 불변 값은 다른 개념이다

const는 재할당을 막는 것이지 값을 불변으로 만드는 게 아니다. 상수는 "재할당이 금지된 변수"일 뿐이다.

### 문자열도 원시 값이라 변경 불가능하다

```javaScript
var str = 'string';
str[0] = 'S';
console.log(str); // 'string' 바뀌지 않고 에러도 없음
```

문자열은 인덱스 접근과 length가 되는 유사 배열 객체처럼 동작하지만 원시 값이다. 한 글자를 바꾸려는 시도는 무시된다.

### 객체는 변경 가능하다

```javaScript
var person = { name: 'Lee' };
person.name = 'Kim';
person.address = 'Seoul';
```

변수 person에 저장된 건 객체가 아니라 객체가 있는 메모리 주소(참조 값)다. 프로퍼티를 바꿔도 person의 참조 값은 그대로다. 같은 주소에 있는 객체의 내용만 바뀐다.

### 얕은 복사와 깊은 복사

```javaScript
const o = { x: { y: 1 } };

const c1 = { ...o };          // 얕은 복사
c1 === o;                      // false  ← 겉 객체는 새로 만들어짐
c1.x === o.x;                  // true   ← 안쪽 객체는 여전히 공유

const c2 = _.cloneDeep(o);    // 깊은 복사
c2.x === o.x;                  // false  ← 안쪽까지 전부 새로 만들어짐
```

얕은 복사는 한 단계만 복사하고 중첩된 객체는 참조를 그대로 복사한다. 깊은 복사는 중첩된 객체까지 모두 새로 만든다.

### 얕은 복사는 어디까지 안전한가

객체를 복사하는 방법은 여러가지다. 각각 어느 깊이까지 복사하고, 어떤 값에서 깨질까

```javaScript
const original = {
    n: 1,
    nested: { x: 1 },
    date: new Date(),
    fn: () => 1,
    undef: undefined,
};

const a = { ...original };
const b = Object.assign({}, original);
const c = JSON.parse(JSON.stringify(original));
const d = structuredClone(original); // fn때문에 에러 발생
```

| 방법                          | 깊이  | Date            | 함수                             | undefined                        | 순환 참조 |
| ----------------------------- | ----- | --------------- | -------------------------------- | -------------------------------- | --------- |
| 스프레드 { ...o }             | 1단계 | 참조 공유       | 참조 공유                        | 유지                             | 문제 없음 |
| Object.assign({}, o)          | 1단계 | 참조 공유       | 참조 공유                        | 유지                             | 문제 없음 |
| JSON.parse(JSON.stringify(o)) | 전체  | 문자열로 변환됨 | 객체일땐 사라지고 배열일 땐 null | 객체일땐 사라지고 배열일 땐 null | 에러      |
| structuredClone(o)            | 전체  | 복사됨          | 에러                             | 유지                             | 복사됨    |
| \_.cloneDeep(o)               | 전체  | 복사됨          | 참조 공유                        | 유지                             | 복사됨    |

스프레드와 Object.assign은 한 단계만 복사한다. 중첩 객체는 주소만 복사되어 원본과 공유된다.

JSON 방식은 "직렬화 가능한 값"만 살아남는다. Date는 ISO 문자열이 되고, 함수와 undefined는 프로퍼티째 사라지며, 순환 참조가 있으면 TypeError다.

structuredClone은 Date, Map, Set, 순환 참조를 올바르게 복사한다. 단 함수와 DOM 노드가 들어 있으면 DataCloneError를 던진다. 함수가 없는 순수 데이터 객체라면 라이브러리 없이 쓸 수 있는 가장 좋은 선택이다.

cloneDeep은 함수를 만나면 에러 대신 참조를 공유한다. 함수가 섞인 객체도 복사해야 할 때 쓴다.

### 문자열이 원시 값인데 메서드가 되는 이유

'abc'.length, 'abc'.toUpperCase()가 동작한다. 프로퍼티와 메서드는 객체의 것인데 원시 값인 문자열이 어떻게 사용할까?
그리고 str[0] = 'S'은 왜 에러 없이 무시될까?

```javaScript
const str = 'string';
str.length; // 6
str.toUpperCase(); // 'STRING'
typeof str; // 'string' <- 여전히 원시값

str[0] = 'S';
str; // 'string' <- 변경 안 됨, 에러 없음

str.custom = 'x';
str.custom; // undefined <- 프로퍼티 추가도 불가능
```

원리: 래퍼 객체
원시 값에 마침표나 대괄호로 접근하는 순간

1. 해당 원시 값을 감싸는 임시 객체를 만든다. 문자열이면 String 객체
2. 그 객체의 [[StringData]] 내부 슬롯에 원시 값을 넣고, 프로토타입을 String.prototype으로 연결
3. 요청된 프로퍼티나 메서드를 임시 객체에서 실행
4. 실행이 끝나면 임시 객체를 버리고, 식별자는 원래의 원시 값으로 되돌린다.

```javaScript
// 엔진 내부 동작을 풀어 쓰면
str.toUpperCase()
// const tmp = new String(str); // 임시 래퍼 객체 생성
// const result = tmp.toUpperCase(); // String.prototype의 메서드 실행
// return result;
```

length나 toUpperCase는 문자열에 있는 게 아니라 String.prototype에 있다. 원시 값이 객체처럼 보이는 건 이 임시 객체 덕분이다.

str[0] = 'S'가 무시되는 이유

1. 임시 String 객체 생성
2. 임시 객체의 0번 프로퍼티에 'S' 할당 시도
   문자열 래퍼의 인덱스 프로퍼티는 읽기 전용이라 strict mode에서는 TypeError, 비 strict mode에서는 조용히 실패
3. 임시 객체 폐기
4. str은 원래 'string' 그대로

**new String()과의 차이**

```javaScript
const s1 = 'abc';
const s2 = new String('abc');

typeof s1; // 'string'
typeof s2; // 'object'
s1 === s2; // false
```

new String()은 임시가 아닌 진짜 객체를 만든다. 그래서 타입이 다르고, === 비교가 실패하며, if (new String(''))은 빈 문자열인데도 참으로 평가된다. 이런 혼란 때문에 래퍼 생성자를 new와 함께 직접 쓰는 것은 권장되지 않는다. 엔진이 알아서 임시로 만들어 주는 것으로 충분하다.

**결론**
문자열은 원시 값이고 변경 불가능하다. 메서드가 동작하는 것은 문자열 자체가 객체여서가 아니라, 접근 순간 엔진이 임시 래퍼 객체를 만들어 String.prototype을 빌려 쓰기 때문이다. 이 임시 객체는 바로 버려지므로, 문자열에 무언가를 할당하거나 추가하려는 시도는 전부 사라진다. Number, Boolean, Symbol, BigInt도 같은 방식으로 동작하며, null과 undefined만 래퍼 객체가 없어서 프로퍼티 접근 시 TypeError가 발생한다.
