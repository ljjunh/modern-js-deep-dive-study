### 객체란

- 원시 값을 뺀 모든 것(함수, 배열, 정규식,...)은 객체. 0개 이상의 프로퍼티 집합
- 원시 값은 변경 불가, 객체는 변경 가능
- 값이 함수인 프로퍼티를 메서드라 부름. 프로퍼티는 상태, 메서드는 동작

### 객체 리터럴

- { ... }로 생성. 변수에 할당되는 시점에 엔진이 평가해서 객체를 만든다
- 코드 블록이 아니라 값으로 평가되는 표현식이라 닫는 중괄호 뒤에 세미콜론
- 클래스 선언이나 new 없이 바로 만들 수 있어 유연함

### 프로퍼티 키 규칙

- 키는 문자열 또는 심볼. 그 외의 값은 암묵적으로 문자열로 변환
- 식별자 네이밍 규칙을 지키면 따옴표 생략 가능
- [expr]로 동적 키 생성. 빈 문자열, 예약어도 키로 되지만 권장 하지 않음
- 중복 키는 에러 없이 뒤의 것이 덮어씀

### 프로퍼티 접근

- 마침표 표기법 obj.key, 대괄호 표기법 obj['key']
- 대괄호 안은 반드시 따옴표로 감싼 문자열. 안 감싸면 식별자로 평가 -> ReferenceError
- 숫자 키만 예외로 obj[1]가능(내부에서 '1'로 변환)
- 없는 프로퍼티 접근은 undefined, 에러 아님

```javaScript
const key = 'name';
const obj = { name: 'Lee', key: 'X' };

obj.name    // 'Lee' <- 글자 그대로 'name' 키
obj['name'] // 'Lee' <- 글자 그대로 'name' 키
obj[key]    // 'Lee' <- key 변수의 "값" 'name'을 키로 사용
obj.key     // 'X' <- 글자 그대로 'key'키. 변수 key와 무관
```

### 갱신, 동적 생성, 삭제

- 있는 키에 할당 = 갱신, 없는 키에 할당 = 동적 생성
- delete obj.key 없는 키를 지워도 에러 없음

### 없는 프로퍼티는 undefined을 반환한다

JS는 존재하지 않는 프로퍼티를 읽어도 에러를 내지 않고 undefined를 반환한다. Python은 없는 키에 접근하면 KeyError로 중단된다. JS는 에러 대신 값을 반환하고 실행을 계속한다.

장점: 존재 여부를 확인하지 않고 읽을 수 있다

```javaScript
const config = { theme: 'dark' };
const size = config.fontSize; // undefined, 중단 없음
```

있을 수도 없을 수도 있는 키를 다룰 때 사전 검사 코드가 필요 없다.

단점 1: 중첩 접근은 안전하지 않다

```javaScript
const user = {};
user.profile; // undefined
user.profile.name; // TypeError: Cannot read properties of undefined
```

- 현상: 없는 프로퍼티는 undefined지만, undefined에서 다시 프로퍼티를 읽으면 에러가 발생한다.
- 원인: user.profile.name은 왼쪽부터 평가된다. user.profile이 undefined가 된 뒤 undefined.name을 시도한다. undefined는 객체가 아니므로 프로퍼티를 가질 수 없다.
- 대응: 과거에는 user && user.profile && user.profile.name처럼 단계마다 확인했다. ES2020의 옵셔널 체이닝 user.profile?.name이 이를 문법으로 해결했다. 왼쪽이 null 또는 undefined면 평가를 중단하고 전체 결과가 undefined가 된다.

단점 2: 프로퍼티가 없는 경우와 값이 undefined인 경우를 구분할 수 없다

```javaScript
const a = {}; // x 프로퍼티가 없다
const b = { x: undefined }; // x 프로퍼티가 있고 값이 undefined다
a.x; // undefined
b.x; // undefined
```

- 현상: 읽기 결과가 동일하다.
- 원인: "프로퍼티 없음"을 undefined라는 일반 값으로 표현하기 때문에, 그 값이 실제로 저장된 경우와 구분되지 않는다.
- 대응: 읽기 대신 존재 확인 연산자를 사용한다. 'x' in a는 false, 'x' in b는 true다. in은 프로토타입 체인까지 탐색하고, Object.hasOwn(b, 'x')는 해당 객체 자신의 프로퍼티만 확인한다.

단점 3: 프로퍼티 이름 오타가 에러로 드러나지 않는다

```javaScript
const user = { userName: 'Lee' };
user.username; // undefined
```

- 현상: userName을 username으로 잘못 썼지만 에러가 없다.
- 원인: 오타 난 키도 "없는 프로퍼티"이므로 단점 1과 같은 규칙으로 undefined가 된다. 프로그램은 계속 실행되고, 화면에 빈 값이 표시되거나 계산 결과가 NaN이 되어서야 문 한 위치와 발견되는 위치가 멀어진다.
- 대응: 런타임에서는 잡을 수 없으므로 실행 전 검사가 필요하다. TypeScript는 컴파일 시점에 존재하지 않는 프로퍼티 접근을
  에러로 보고한다.

없는 프로퍼티에 undefined를 반환하는 설계는 코드를 간결하게 만들었지만 그 부작용을 보완하기 위해 옵셔널 체이닝, in연산자, TypeScript 같은 도구가 추가됐다.
