### 타입 변환이란

- 모든 값은 타입이 있고, 다른 타입으로 바꿀 수 있다. 개발자가 의도적으로 바꾸면 명시적 변환(타입 캐스팅), 엔진이 표현식을 평가하면서 문맥에 맞춰 바꾸면 암묵적 타입 변환(타입 강제 변환)
- 어느 쪽이든 기존 값을 바꾸는 게 아니라 새 값을 만든다. x + ''를 평가하면 x의 숫자 10으로 새 문자열 "10"을 만들어 한 번 쓰고 버린다. x는 그대로 숫자다. 원시 값은 변경 불가능하기 때문이다.
- 암묵적 변환을 피하라는 뜻이 아니다. (10).toString()보다 10 + ''가 더 읽기 쉬울 때도 있다. 중요한 것은 자기 코드에서 어떤 변환이 일어나 어떤 값이 되는지 예측할 수 있는 것이다.

### 암묵적 타입 변환

엔진은 문맥이 요구하는 타입으로 바꾼다.

### 명시적 타입 변환

표준 빌트인 생성자 함수를 new 없이 호출하거나, 빌트인 메서드를 쓰거나, 암묵적 변환을 이용한다.

<b>문자열로</b>

1. 빌트인 생성자 함수를 new 없이 호출: String(1) -> "1", String(NaN) -> "NaN", String(true) -> "true"
2. 빌트인 메서드: (1).toSTring(), (true).toString()
   책은 "Object.prototype.toString을 사용한다고 하지만, 실제로 호출되는 것은 Number.prototype.toString, Boolean.prototype.toString이다. 각 타입의 래퍼 객체가 자기 toString을 갖고 있고, Object.prototype.toString은 Object.prototype.toString.call(1) -> "[object Number]" 처럼 타입 태그를 돌려주는 전혀 다른 함수다.
3. 암묵적 변환: 1 + ''

<b>숫자로</b>

1. Number('0') -> 0, Number('10.53') -> 10.53, Number(true) -> 1
2. parseInt('0'), parseFloat('10.53'). 문자열만 받는다
3. +'0', +true
4. '0' \* 1, true \* 1

   Number()는 문자열 전체가 사양의 StringNumericLiteral 문법(공백만 있거나 아무것도 없는 문자열은 +0)에 맞아야 한다. 이 문법은 앞뒤 공백을 허용하고, 빈 문자열이나 공백만 있는 문자열을 0으로 정의한다. 그 외에 문법에 맞지 않는 글자가 하나라도 있으면 NaN이다.
   parseInt()는 앞에서부터 읽을 수 있는 숫자까지만 읽고 멈추며 읽을 숫자가 하나도 없으면 NaN이다.

```javaScript
Number('10px') // NaN
parseInt('10px') // 10
Number('') // 0
parseInt('') // NaN
Number(null) // 0
parseInt(null) // NaN
```

### 단축평가

||와 &&는 불리언이 아니라 결과를 결정한 피연산자를 그대로 돌려준다. 평가 결과가 확정되면 나머지 피연산자를 평가하지 않는다.

### 옵셔널 체이닝 ?.

좌항이 null 또는 undefined일 때만 undefined를 돌려주고, 아니면 프로퍼티 참조를 이어간다.

### null 병합 연산자 ??

좌항이 null 또는 undefined일 때만 우항을 돌려준다.

### -1 + ''는 "-1"인데, -0 + ''는 왜 "0"인가?

숫자를 문자열로 바꾸는 사양 알고리즘 때문이다

1. x가 NaN이면 "NaN"
2. x가 +0 또는 -0이면 "0" <- 명시적으로 "0"에 묶음
3. x < -0이면 "-" + toString(-x) <- 음수 부호는 여기서 붙음

### [], {}는 왜 false가 아닌가

ToBoolean 알고리즘

1. Boolean이면 그대로
2. undefined, null, +0, -0, NaN, 0n, 빈 문자열이면 false
3. 그 외 전부 true
   객체는 내용과 무관하게 3단계에서 무조건 true.

참/거짓을 판단할 때 자바스크립트는 "거짓인 값 목록"을 정해두고, 그 목록에 없으면 전부 참으로 본다.
false, 0, -0, 0n, "", null, undefined, NaN
이 8개가 전부다. 배열이 비었는지, 객체에 프로퍼티가 있는지는 아예 보지 않는다.
왜 안볼까?
"비어 있다"의 뜻이 객체마다 다르다. 배열은 길이가 0이면 빈 것이고, {}는 프로퍼티가 없으면 빈 것이고, Map은 size가 0이면 빈 것이다. Date나 함수는 뭐가 "빈"것인지 말할 수 없다. 객체 종류마다 다른 기준을 언어가 다 알 수는 없으니, 자바스크립트는 "객체는 무조건 참"으로 통일했다. 파이썬은 반대로 객체마다 "나는 비었을 때 거짓이다"를 직접 정의하게 해서 if []가 거짓인데, 그건 그 언어의 선택이다.

그래서 이런 결과가 나온다.

```javaScript
if ([]) // 참. 빈 배열이어도
if ({}) // 참. 빈 객체여도
if (new Boolean(false)) // 참. false를 감싼 객체도 객체니까
if ("0") // 참. 비어있지 않은 문자열
if ("") // 거짓. 목록에 있음
```

### +[]는 0인데 +{}는 왜 NaN인가

+는 "이걸 숫자로 바꿔라"다. 그런데 배열이나 객체는 숫자로 바로 못 바꾸니까, 엔진은 먼저 문자열로 바꾼 다음 그 문자열을 숫자로 읽는다

```javaScript
String([]) // "" (빈 배열 -> 원소를 쉼표로 이은 것 -> 아무것도 없음)
String({}) // "[object Object]" (객체 -> 항상 이 글자)
Number("") // 0 (빈 문자열은 0으로 읽기로 되어 있음)
Number("[object Object]") // NaN (숫자로 읽을 수 없음)
```

### 명시적 변환에서 왜 new 없이 호출하나

new 없이 부르면 변환 함수, new를 붙이면 래퍼 객체 생성자로 쓰임.

```javaScript
typeof Number(1) // "number"
typeof new Number(1) // "object"
new Number(1) === 1 // false (객체와 원시 값)
new String("a") === "a" // false
if (new Boolean(false)) {...} // 객체라 truthy, 실행됨
```

마지막 줄이 new를 쓰면 안 되는 이유. new Boolean(false)는 false를 감싼 객체인데 객체는 무조건 truthy라, false를 만들려다 참으로 평가되는 값을 만들게 된다. 래퍼 객체를 직접 만들 일은 실무에서 없고, 사양이 원시 값 프로퍼티 접근을 할 때 알아서 임시로 만들어 씀

### 단축평가에서 'Cat' && 'Dog'는 'Dog'다. 그럼 React의 {isSomething && <Component />}에서 isSomething이 falsy면 그 falsy 값이 DOM에 올라가는 건가? 컴포넌트가 아니라서 안 보일 뿐인가?

값은 React에게 넘어간다. 그 값을 DOM에 넣을지는 React가 타입을 보고 정한다.
&&는 그냥 연산자라 React가 받는 것은 식의 결과값이고, isSomething이 falsy면 그 값이 isSomething 자체다. React는 자식으로 받은 값이 Boolean, null, undefined, 빈 문자열이면 아무것도 안 그리고, 숫자나 문자열이면 텍스트로 그린다.

| isSomething      | 식의 결과       | 화면              |
| ---------------- | --------------- | ----------------- |
| true             | `<Component />` | 컴포넌트          |
| false            | false           | 없음              |
| null / undefined | 그대로          | 없음              |
| ""               | ""              | 없음              |
| 0                | 0               | 글자 "0"이 보임   |
| NaN              | NaN             | 글자 "NaN"이 보임 |

```javaScript
{items.length && <List items={items} />}
// items가 빈 배열이면 items.length는 0 -> 화면에 "0"이 찍힘
```

빈 장바구니 자리에 "0"이 보이고, flex나 grid면 그 텍스트가 아이템 하나로 잡혀 레이아웃도 밀린다.
