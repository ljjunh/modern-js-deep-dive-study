### 클래스는 프로토타입의 문법적 설탕인가

- ES6 클래스도 결국 프로토타입 기반으로 객체를 만드는 함수
- 생성자 함수와 겨로가는 비슷하지만 동작이 더 엄격하고 기능이 더 많아서, 책은 "새로운 객체 생성 메커니즘"으로 봄
  | 차이점 | 클래스 | 생성자 함수 |
  | -- | -- | -- |
  |new 없이 호출 | TypeError | 일반 함수로 호출됨 |
  | 상속 문법 | extends, super | 없음 |
  | 호이스팅 | TDZ 때문에 선언 전에 못 씀 | 함수 호이스팅 또는 변수 호이스팅 |
  | strict mode | 클래스 안은 항상 적용, 해제 불가 | 직접 지정해야 함 |
  | 메서드 열거 | [[Enumerable]]이 false라 열거 안됨 | 직접 추가하면 열거됨 |

### 클래스 정의

- 선언문과 표현식 둘 다 가능하고 값으로 다룰 수 있는 일급 객체
- 클래스 몸체에 정의하는 메서드는 constructor, 프로토타입 메서드, 정적 메서드 세 가지
- 책은 "몸체에는 메서드만 정의 가능"이라고 했지만, ES2022부터는 필드와 static 블록도 정의할 수 있음

```js
class Person {
    // 인스턴스 필드(ES2022)
    name = 'Lee';
    // private 필드(ES2022)
    #password = '1234';

    // 원래부터 가능했던 것들(ES2015)
    constructor(age){...}
    sayHi(){...}
}
```

### 클래스 호이스팅

- 클래스는 평가되면 함수 객체가 되고, 이때 prototype 객체도 같이 생김
- 호이스팅은 되지만 let/const처럼 초기화 전까지 TDZ에 있음. 그래서 호이스팅이 없는 것처럼 보임

### 인스턴스 생성

- 반드시 new로 호출해야 함
  - 사양: 클래스 생성자의 [[Call]]은 [[IsClassConstructor]]가 true면 무조건 TypeError를 던짐
- 기명 클래스 표현식의 이름은 클래스 안에서만 쓸 수 있는 식별자

```js
const Person = class MyClass {
  whoAmI() {
    return MyClass; // 클래스 안에서는 MyClass 사용 가능
  }
};
```

### constructor

- 인스턴스를 만들고 초기화하는 메서드. 클래스 안에 최대 1개만 만들 수 있음
- 클래스를 평가하면 constructor 코드가 곧 클래스 함수 객체 자체가 됨 그래서 prototype에도 인스턴스에도 constructor 메서드는 보이지 않음
- 프로토타입의 constructor 프로퍼티와 이름만 같고 직접적인 관계는 없음
- 생략하면 빈 constructor가 자동으로 들어감
- 반환:
  - 반환문이 없으면 this를 암묵적으로 반환
  - 객체를 명시적으로 반환하면 그 객체가 반환
  - 원시값을 반환하면 무시되고 this 반환

### 프로토타입 메서드

- 클래스 몸체에 정의하면 자동으로 클래스.prototype의 메서드가 됨
- 인스턴스의 프로토타입 체인 구조는 생성자 함수 때와 똑같음

### 정적 메서드

- static을 붙이면 클래스 함수 객체 자신의 메서드가 됨
- 인스턴스의 프로토타입 체인에는 클래스 자신이 없음. 그래서 인스턴스로는 정적 메서드를 호출할 수 없음

### 정적 메서드 vs 프로토타입 메서드

|           | 정적                             | 프로토타입                |
| --------- | -------------------------------- | ------------------------- |
| 체인      | 클래스의 체인                    | 인스턴스의 체인           |
| 호출 주체 | 클래스                           | 인스턴스                  |
| this      | 클래스                           | 인스턴스                  |
| 언제 쓰나 | 인스턴스 프로퍼티를 쓰지 않을 때 | 인스턴스 프로퍼티를 쓸 때 |

-Math, Number.isNaN, JSON. Object, Reflect가 대표적인 정적 메서드 묶음

### 클래스메서드의 특징

- 메서드 축약 표현을 쓰고, 메서드 사이에 콤마가 없음
- 암묵적으로 strict mode, 열거x, non-constructor

### 클래스의 인스턴스 생성 과정

1. [[Construct]]가 호출되면 빈 객체가 만들어짐. 이 객체의 프로토타입은 클래스.prototype이고, 이 객체가 this에 바인딩됨
2. constructor 코드가 실행되면서 this에 프로퍼티를 추가해 초기화 함
3. this가 암묵적으로 반환됨

### 인스턴스 프로퍼티

- constructor 안에서 this에 추가. 항상 public

### 접근자 프로퍼티

- get/set으로 정의하고, 프로퍼티처럼 읽고 대입하면 내부적으로 함수가 호출됨
- getter는 반드시 값을 반환해야 하고, setter는 매개변수가 정확히 1개여야 함
- 클래스에 정의한 접근자는 인스턴스가 아니라 프로토타입의 프로퍼티이고, 열거되지 않음

### 클래스 필드

- 몸체에 name = 값 처럼 쓰며 this는 붙이지 않음. 참조할 때는 this가 필요함
- 초기값이 없으면 undefined가 됨
- 외부 값으로 초기화해야 하면 constructor에서 함
- 필드에 함수를 넣으면 프로토타입 메서드가 아니라 인스턴스마다 생기는 메서드가 됨

### private 필드

- 클래스 몸체에서 선언해야 함
- 클래스 내부에서만 접근 가능 대신 접근자로 간접 노출할 수 있음

### static 필드

- static public과 static private 필드 모두 가능

### 상속에 의한 클래스 확장

1. 개념

- 프로토타입 상속은 객체가 다른 객체의 자산을 물려받는 것
- 클래스 확장은 기존 클래스를 물려받아 새 클래스를 정의하는 것
- 생성자 함수로는 의사 클래스 상속 패턴을 직접 짜야 했지만, 이제는 필요 없음

2. extends

- 프로타타입 체인이 두 줄로 생김
  - 클래스끼리: Derived -> Base(그래서 정적 메서드도 상속됨)
  - 인스턴스 쪽: Derived.prototype -> Base.prototype

3. 동적 상속

- extends 뒤에는 [[Construct]]를 가진 함수로 평가되는 모든 표현식이 올 수 있음

4. 서브클래스 constructor

- 생략하면 constructor(...args) { super(...args)}가 자동으로 들어감

5. super

- 호출할 때
  - 수퍼 클래스의 constructor를 실행
  - 서브클래스의 constructor를 직접 썼다면 반드시 super를 호출해야 함
  - super를 호출하기 전에는 this를 참조할 수 없음
  - 서브클래스의 constructor에서만 호출할 수 있음
- 참조할 때
  - 메서드의 [[HomeObject]]가 가리키는 객체의 프로토타입을 찾아감
  - 프로토타입 메서드 안에서 super는 Base.prototype, 정적 메서드 안에서 super는 Base를 가리킴
  - [[HomeObject]]는 메서드 축약 표현에만 있음. 그래서 객체 리터럴에서도 축약 메서드라면 super를 쓸 수 있음

6. 상속 클래스의 인스턴스 생성 과정

- 클래스에는 내부 슬롯 [[ConstructorKind]]가 있고 값은 "base" 또는 "derived"
- derived 클래스는 인스턴스를 직접 만들지 않고 수퍼클래스에 위임함. 그래서 super를 반드시 호출해야 함
- 순서
  a. 서브 클래스에서 super 호출
  b. 수퍼클래스가 빈 객체를 만들고 this에 바인딩. 이때 프로토타입은 new.target.prototype, 즉 서브클래스의 prototype으로 정해짐
  c. 수퍼클래스 constructor가 인스턴스를 초기화
  d. 서브클래스로 돌아와서 super가 반환한 인스턴스를 this에 바인딩
  e. 서브클래스가 자기 쪽 초기화
  f. this반환

7. 표준 빌트인 생성자 확장

- Array, String 같은 빌트인도 extends로 확장할 수 있음
- map이나 filter는 서브클래스의 인스턴스를 반환함. 그래서 메서드 체이닝이 가능

```js
// filter, map, slice처럼 새 배열을 만들어서 반환하는 메서드
class MyArray extends Array {
  uniq() {
    return this.filter((v, i, self) => self.indexOf(v) === i);
  }
}

const arr = new MyArray(1, 1, 2, 3);

arr.push(4); // Array.prototype 메서드 사용 가능
arr.uniq(); // 내가 추가한 메서드 사용 가능

const result = arr.filter((v) => v > 1);

result instanceof MyArray; // true

// filter가 MyArray를 반환하므로 체이닝 가능
arr.filter((v) => v > 1).uniq();
```
