### 함수의 구분

- ES6 이전에는 모든 함수가 callable이면서 constructor였음
  - 객체에 넣은 메서드나 콜백도 new로 호출할 수 있었음
  - constructor라서 쓰지도 않는 prototype 객체가 함수마다 생겼고, 이게 성능 손해였음
- ES6는 사용 목적에 따라 함수를 세 종류로 나눔
  | 구분 | constructor | prototype | super | arguments |
  | - | - | - | - | - |
  | 일반 함수 | O | O | X | O |
  | 메서드 | X | X | O | O |
  | 화살표 함수 | X | X | X | X |

### 메서드

- ES6 사양에서 메서드는 메서드 축약 표현으로 정의한 함수
  - foo(){}는 메서드고, bar: function(){}는 일반 함수
- non-constructor임. new로 호출할 수 없고 prototype도 없음
- 내부 슬롯 [[HomeObject]]를 가져서 super를 쓸 수 있음
- 빌트인 객체의 프로토타입 메서드와 정적 메서드도 모두 non-constructor
- 정리하면, 메서드는 꼭 필요한 기능(super)은 더하고 의미에 맞지 않는 기능(constructor)은 뺀 것

### 화살표 함수

1. 정의

- 함수 표현식으로만 만들 수 있고, 선언문으로는 못 만듦
- 매개변수가 하나면 소괄호를 생략할 수 있고, 매개변수가 없으면 소괄호를 생략할 수 없음
- 몸체가 표현식 하나면 중괄호를 생략할 수 있고, 그 값이 암묵적으로 반환됨
  - 몸체가 문이면 중괄호를 생략할 수 없음
- 객체 리터럴을 반환하려면 ({ ... })처럼 소괄호로 감싸야 함 감싸지 않으면 중괄호를 함수 몸체로 해석
- 즉시 실행 함수로도 쓸 수 있고, 고차 함수의 콜백으로 쓰기 좋음

2. 일반 함수와의 차이

- non-constructor. new로 호출할 수 없고 prototype도 없음
- 중복된 매개변수 이름을 쓰면 항상 SyntaxError
- 함수 자체의 this, arguments, super, new.target 바인딩이 없음

3. this

- 화살표 함수는 lexical this. 자기 this가 없어서 함수를 정의한 위치의 상위 스코프 this를 그대로 씀
- 화살표 함수가 중첩되면, 가장 가까운 상위 함수 중 화살표 함수가 아닌 함수의 this를 씀
- call, apply, bind로 this를 바꿀 수 없음. 호출은 되지만 this는 무시됨
- 메서드를 화살표 함수로 정의하면 안 됨. this가 객체가 아니라 상위 스코프를 가리킴 prototype에 화살표 함수를 넣는 것도 같은 문제

4. super

- 화살표 함수는 super 바인딩이 없어서 상위 스코프의 super를 씀
- 클래스 필드의 화살표 함수에서 super를 쓰면 에러 없이 수퍼클래스 메서드를 참조

5. arguments

- 화살표 함수는 arguments 바인딩이 없어서 상위 스코프의 arguments를 씀 그래서 자기에게 전달된 인수 목록은 볼 수 없고 가변 인자 함수는 반드시 rest 파라미터로 만들어야 함

### Rest 파라미터

- 매개변수 이름 앞에 ...를 붙이면 넘어온 인수 중 앞의 매개변수가 받고 남은 것들을 배열로 받음
- 반드시 마지막 매개변수여야 하고, 하나만 쓸 수 있으며, 기본값을 줄 수 없음

### 매개변수 기본값

- 인수를 안 넘겼거나 undefined를 넘겼을 때만 기본값이 적용됨. null은 적용 x
- rest 파라미터에는 기본값을 줄 수 없음
