### 함수의 구분

- ES6 이전의 함수는 **별다른 구분 없이 다양한 목적으로 사용**되었다.
  - 같은 함수라도 **일반 함수로서 호출**할 수도 있고, **생성자 함수로서 호출**할 수도 있고, **메서드로서 호출**할 수도 있다.
  - ```javascript
    var foo = function () {
      return 1;
    };

    // 일반적인 함수로서 호출
    foo(); // 1

    // 생성자 함수로서 호출
    new foo(); // foo {}

    // 메서드로서 호출
    var obj = { foo: foo };
    obj.foo(); // 1
    ```
  - 즉 ES6 이전의 모든 함수는 **일반 함수로서 호출할 수 있는 것은 물론 생성자 함수로서 호출할 수 있다**.
    - 함수 객체가 `callable`이면서 `constructor`이기 때문이다. ([18장](../../week05/윤홍비/18.함수와_일급_객체.md), [19장](../../week07/윤홍비/19.프로토타입.md))
- 이는 **혼란을 일으킬 수 있으며 실수를 유발할 가능성도 높다**.
  - 또한 **성능 면에서도 문제**가 있다.
    - 객체에 바인딩된 메서드가 `constructor`이면 불필요한 `prototype` 프로퍼티와 프로토타입 객체를 생성한다.
  - ```javascript
    var obj = {
      x: 10,
      f: function () {
        return this.x;
      },
    };

    // 프로퍼티 f에 바인딩된 함수를 일반 함수로서 호출
    console.log(obj.f()); // 10

    // 프로퍼티 f에 바인딩된 함수를 생성자 함수로서 호출
    console.log(new obj.f()); // f {}
    ```
- 이를 해결하기 위해 ES6에서는 **함수를 사용 목적에 따라 세 가지 종류로 명확히 구분**했다.

| ES6 함수의 구분    | `constructor` | `prototype` | `super` | `arguments` |
| ------------------ | :-----------: | :---------: | :-----: | :---------: |
| 일반 함수 (Normal) |      ○        |     ○       |   ✕     |     ○       |
| 메서드 (Method)    |      ✕        |     ✕       |   ○     |     ○       |
| 화살표 함수 (Arrow) |     ✕        |     ✕       |   ✕     |     ✕       |

- **일반 함수**는 함수 선언문이나 함수 표현식으로 정의한 함수를 말하며, ES6 이전의 함수와 차이가 없다.
- **메서드**와 **화살표 함수**는 ES6부터 `constructor`가 **아닌 함수**(non-constructor)다.
  - ```javascript
    // 일반 함수 정의: 함수 선언문, 함수 표현식
    function foo() {}
    const bar = function () {};

    // 프로퍼티 x의 값으로 할당된 것은 일반 함수로 정의된 함수다 (메서드로 인정하지 않는다)
    const baz = {
      x: function () {},
    };

    // 일반 함수로 정의된 함수만이 constructor다
    new foo(); // foo {}
    new bar(); // bar {}
    new baz.x(); // x {}

    // 화살표 함수 정의
    const arrow = () => {};

    new arrow(); // TypeError: arrow is not a constructor

    // 메서드 정의: ES6의 메서드 축약 표현만 메서드로 인정한다
    const obj = {
      x() {},
    };

    new obj.x(); // TypeError: obj.x is not a constructor
    ```
- 따라서 **함수의 종류에 따라 `new`로 호출할 수 있는지가 결정**된다.
  - 이때 `[[Construct]]` 내부 메서드의 유무로 구분한다. ([25장](./25.클래스.md#클래스에서-정의한-메서드의-특징))
  - 일반 함수는 `[[Call]]`과 `[[Construct]]`를 모두 가지지만, 메서드와 화살표 함수는 **`[[Call]]`만 갖는다**.

### 메서드

- ES6 사양에서 **메서드는 메서드 축약 표현으로 정의된 함수만을 의미**한다.
  - ```javascript
    const obj = {
      x: 1,
      // foo는 메서드다
      foo() {
        return this.x;
      },
      // bar에 바인딩된 함수는 메서드가 아닌 일반 함수다
      bar: function () {
        return this.x;
      },
    };

    console.log(obj.foo()); // 1
    console.log(obj.bar()); // 1
    ```
- ES6 메서드는 **인스턴스를 생성할 수 없다**.
  - 따라서 **`prototype` 프로퍼티가 없고 프로토타입도 생성하지 않는다**.
  - ```javascript
    new obj.foo(); // TypeError: obj.foo is not a constructor
    new obj.bar(); // bar {}

    // obj.foo는 constructor가 아닌 ES6 메서드이므로 prototype 프로퍼티가 없다
    obj.foo.hasOwnProperty("prototype"); // false

    // obj.bar는 constructor인 일반 함수이므로 prototype 프로퍼티가 있다
    obj.bar.hasOwnProperty("prototype"); // true
    ```
  - **불필요한 `prototype` 객체를 생성하지 않으므로** 메모리 면에서도 이점이 있다.
- 표준 빌트인 객체가 제공하는 프로토타입 메서드와 정적 메서드도 **모두 non-constructor**다.
  - ```javascript
    new String.prototype.toUpperCase(); // TypeError: String.prototype.toUpperCase is not a constructor
    new Number.isInteger(1); // TypeError: Number.isInteger is not a constructor
    ```
- ES6 메서드는 자신을 바인딩한 객체를 가리키는 **내부 슬롯 `[[HomeObject]]`를 갖는다**.
  - `super` 참조는 `[[HomeObject]]`를 사용하여 **수퍼클래스의 메서드를 찾는다**. ([25장](./25.클래스.md#super-참조))
  - 따라서 **ES6 메서드는 `super` 키워드를 사용할 수 있다**.
  - ```javascript
    const base = {
      name: "Lee",
      sayHi() {
        return `Hi! ${this.name}`;
      },
    };

    const derived = {
      __proto__: base,
      // ES6 메서드이므로 [[HomeObject]]를 갖는다
      sayHi() {
        return `${super.sayHi()}. how are you doing?`;
      },
    };

    console.log(derived.sayHi()); // Hi! Lee. how are you doing?
    ```
  - 반면 **ES6 메서드가 아닌 함수는 `[[HomeObject]]`를 갖지 않으므로 `super`를 사용할 수 없다**.
  - ```javascript
    const derived = {
      __proto__: base,
      // ES6 메서드가 아니므로 [[HomeObject]]가 없다
      sayHi: function () {
        return `${super.sayHi()}. how are you doing?`; // SyntaxError: 'super' keyword unexpected here
      },
    };
    ```

### 화살표 함수

- **화살표 함수(arrow function)** 는 `function` 키워드 대신 **화살표 `=>`** 를 사용하여 기존의 함수 정의 방식보다 간략하게 함수를 정의할 수 있다.
  - 표현만 간략한 것이 아니라 **내부 동작도 기존의 함수보다 간략**하다.
  - 특히 **콜백 함수 내부에서 `this`가 전역 객체를 가리키는 문제를 해결**하기 위한 대안으로 유용하다.

#### 화살표 함수 정의

##### 함수 정의

- 화살표 함수는 **함수 선언문으로 정의할 수 없고 함수 표현식으로 정의**해야 한다.
  - 호출 방식은 기존 함수와 동일하다.
  - ```javascript
    const multiply = (x, y) => x * y;
    multiply(2, 3); // 6
    ```

##### 매개변수 선언

- 매개변수가 여러 개인 경우 **소괄호 `()` 안에 매개변수를 선언**한다.
  - ```javascript
    const arrow = (x, y) => { ... };
    ```
- 매개변수가 **한 개인 경우 소괄호를 생략**할 수 있다.
  - ```javascript
    const arrow = (x) => { ... };
    const arrow2 = x => { ... };
    ```
- 매개변수가 **없는 경우 소괄호를 생략할 수 없다**.
  - ```javascript
    const arrow = () => { ... };
    ```

##### 함수 몸체 정의

- 함수 몸체가 **하나의 문으로 구성**된다면 함수 몸체를 감싸는 중괄호 `{}`를 생략할 수 있다.
  - 이때 함수 몸체 내부의 문이 **값으로 평가될 수 있는 표현식인 문**이라면 암묵적으로 반환된다.
  - ```javascript
    // concise body
    const power = (x) => x ** 2;
    power(2); // 4

    // 위 표현은 다음과 같다
    // block body
    const power2 = (x) => {
      return x ** 2;
    };
    ```
- 함수 몸체를 감싸는 중괄호 `{}`를 생략한 경우 **함수 몸체 내부의 문이 표현식이 아닌 문이라면 에러**가 발생한다.
  - 표현식이 아닌 문은 반환할 수 없기 때문이다.
  - ```javascript
    const arrow = () => const x = 1; // SyntaxError: Unexpected token 'const'

    // 위 표현은 다음과 같이 해석된다
    const arrow2 = () => {
      return const x = 1;
    };
    ```
  - 따라서 **함수 몸체가 하나의 문으로 구성된다 해도 표현식이 아닌 문이라면 중괄호를 생략할 수 없다**.
- **객체 리터럴을 반환**하는 경우 객체 리터럴을 **소괄호 `()`로 감싸 주어야** 한다.
  - ```javascript
    const create = (id, content) => ({ id, content });
    create(1, "JavaScript"); // {id: 1, content: "JavaScript"}

    // 위 표현은 다음과 동일하다
    const create2 = (id, content) => {
      return { id, content };
    };
    ```
  - 소괄호로 감싸지 않으면 **객체 리터럴의 중괄호를 코드 블록으로 해석**한다.
  - ```javascript
    // { id, content }를 함수 몸체 내의 쉼표 연산자문으로 해석한다
    const create = (id, content) => {
      id, content;
    };
    create(1, "JavaScript"); // undefined
    ```
- 함수 몸체가 **여러 개의 문으로 구성**된다면 중괄호를 생략할 수 없고 **반환값이 있다면 명시적으로 반환**해야 한다.
  - ```javascript
    const sum = (a, b) => {
      const result = a + b;
      return result;
    };
    ```
- **즉시 실행 함수**도 화살표 함수로 사용할 수 있다. ([12장](../../week05/윤홍비/12.함수.md#즉시-실행-함수))
  - ```javascript
    const person = ((name) => ({
      sayHi() {
        return `Hi? My name is ${name}.`;
      },
    }))("Lee");

    console.log(person.sayHi()); // Hi? My name is Lee.
    ```
- **고차 함수에 인수로 전달**하는 콜백 함수로 사용하면 **가독성이 좋다**.
  - ```javascript
    // ES5
    [1, 2, 3].map(function (v) {
      return v * 2;
    });

    // ES6
    [1, 2, 3].map((v) => v * 2); // [2, 4, 6]
    ```

#### 화살표 함수와 일반 함수의 차이

1. 화살표 함수는 **인스턴스를 생성할 수 없는 non-constructor**다.
2. **중복된 매개변수 이름을 선언할 수 없다**.
3. 화살표 함수는 **함수 자체의 `this`, `arguments`, `super`, `new.target` 바인딩을 갖지 않는다**.
   - 따라서 화살표 함수 내부에서 이를 참조하면 **스코프 체인을 통해 상위 스코프의 것을 참조**한다.

##### 1. non-constructor

- 화살표 함수는 **`[[Construct]]` 내부 메서드를 갖지 않는다**.
  - 따라서 `new`로 호출하면 에러가 발생하고 **`prototype` 프로퍼티도 없다**.
  - ```javascript
    const Foo = () => {};

    // 화살표 함수는 constructor가 아니다
    new Foo(); // TypeError: Foo is not a constructor

    // 화살표 함수는 prototype 프로퍼티가 없다
    Foo.hasOwnProperty("prototype"); // false
    ```

##### 2. 중복된 매개변수 이름 선언 불가

- 일반 함수는 **중복된 매개변수 이름을 선언해도 에러가 발생하지 않는다**. (non-strict mode)
  - ```javascript
    function normal(a, a) {
      return a + a;
    }
    console.log(normal(1, 2)); // 4
    ```
  - 단 strict mode에서는 에러가 발생한다. ([20장](../../week08/윤홍비/20.strict_mode.md))
- 반면 **화살표 함수에서는 중복된 매개변수 이름을 선언하면 에러가 발생**한다.
  - ```javascript
    const arrow = (a, a) => a + a;
    // SyntaxError: Duplicate parameter name not allowed in this context
    ```

##### 3. 함수 자체의 this, arguments, super, new.target 바인딩이 없다

- 화살표 함수는 **함수 자체의 `this`, `arguments`, `super`, `new.target` 바인딩을 갖지 않는다**.
  - 화살표 함수 내부에서 이들을 참조하면 **스코프 체인을 통해 상위 스코프의 `this`, `arguments`, `super`, `new.target`을 참조**한다.
  - 이는 **식별자를 검색하는 것과 같은 방식**이다. ([13장](../../week05/윤홍비/13.스코프.md#스코프-체인))
  - 만약 화살표 함수와 화살표 함수가 중첩되어 있다면 **상위 화살표 함수에도 없으므로 한 단계 더 올라간다**.

    ```mermaid
    flowchart LR
        INNER["화살표 함수<br/>this 바인딩 없음"]
        OUTER["상위 화살표 함수<br/>this 바인딩 없음"]
        FUNC["일반 함수<br/>this 바인딩 있다"]

        INNER ==>|"스코프 체인"| OUTER ==>|"스코프 체인"| FUNC
    ```

### 화살표 함수의 this

- 화살표 함수가 일반 함수와 구별되는 가장 큰 특징은 **`this`**다.
  - 화살표 함수의 `this`는 **일반 함수의 `this`와 다르게 동작**한다.
  - **콜백 함수 내부의 `this` 문제**를 해결하기 위해 의도적으로 설계되었다.
- 먼저 **콜백 함수 내부의 `this` 문제**를 살펴보자. ([22장](../../week08/윤홍비/22.this.md#함수-호출-방식과-this-바인딩))
  - ```javascript
    class Prefixer {
      constructor(prefix) {
        this.prefix = prefix;
      }

      add(arr) {
        // add 메서드는 인수로 전달된 배열 arr을 순회하며 배열의 모든 요소에 prefix를 추가한다
        return arr.map(function (item) {
          return this.prefix + item; // TypeError: Cannot read properties of undefined (reading 'prefix')
        });
      }
    }

    const prefixer = new Prefixer("-webkit-");
    console.log(prefixer.add(["transition", "user-select"]));
    ```
  - `add` 메서드가 호출되면 `this`는 `prefixer`를 가리킨다.
  - 하지만 `map`의 **콜백 함수는 일반 함수로 호출**되므로 **콜백 함수 내부의 `this`는 `undefined`**를 가리킨다.
    - 클래스 내부의 모든 코드에는 **strict mode가 암묵적으로 적용**되기 때문이다. ([25장](./25.클래스.md#클래스에서-정의한-메서드의-특징))
    - 일반 함수로서 호출된 모든 함수 내부의 `this`에는 strict mode에서 `undefined`가 바인딩된다. ([20장](../../week08/윤홍비/20.strict_mode.md#일반-함수의-this))
  - 즉 **콜백 함수의 `this`와 `add` 메서드의 `this`가 일치하지 않는다**.
- ES6 이전에는 이를 해결하기 위해 **세 가지 방법**을 사용했다.
  - ```javascript
    // 1. this를 회피시킨 후 콜백 함수 내부에서 사용한다
    add(arr) {
      const that = this;
      return arr.map(function (item) {
        return that.prefix + item;
      });
    }

    // 2. map의 두 번째 인수로 콜백 함수 내부의 this로 사용할 객체를 전달한다
    add(arr) {
      return arr.map(function (item) {
        return this.prefix + item;
      }, this);
    }

    // 3. bind 메서드로 this를 바인딩한다
    add(arr) {
      return arr.map(function (item) {
        return this.prefix + item;
      }.bind(this));
    }
    ```
- ES6에서는 **화살표 함수로 간단하게 해결**할 수 있다.
  - ```javascript
    class Prefixer {
      constructor(prefix) {
        this.prefix = prefix;
      }

      add(arr) {
        return arr.map((item) => this.prefix + item);
      }
    }

    const prefixer = new Prefixer("-webkit-");
    console.log(prefixer.add(["transition", "user-select"]));
    // ['-webkit-transition', '-webkit-user-select']
    ```
- 화살표 함수는 **함수 자체의 `this` 바인딩을 갖지 않는다**.
  - 따라서 화살표 함수 내부에서 `this`를 참조하면 **상위 스코프의 `this`를 그대로 참조**한다.
  - 이를 **lexical this**라 한다. ([24장](../../week09/윤홍비/24.클로저.md#렉시컬-스코프))
  - 화살표 함수는 **마치 렉시컬 스코프처럼 `this`가 함수가 정의된 위치에 의해 결정**된다.

    ```mermaid
    flowchart TB
        subgraph NORMAL["일반 함수의 this"]
            direction LR
            N1["함수 호출 방식에 따라 결정된다<br/>(동적)"]
        end

        subgraph ARROW["화살표 함수의 this"]
            direction LR
            A1["함수가 정의된 위치의 상위 스코프 this<br/>(정적, 렉시컬)"]
        end
    ```

- 화살표 함수 내부에서 `this`를 참조하면 **상위 스코프의 `this`를 참조**하므로 다음과 같이 동작한다.
  - ```javascript
    // 중첩 관계에 의해 외부 함수의 this를 참조한다
    function outer() {
      const arrow = () => this; // 상위 스코프 outer의 this
      return arrow();
    }

    const obj = { outer };
    console.log(obj.outer() === obj); // true
    ```
- **화살표 함수는 함수 자체의 `this` 바인딩이 없으므로 `call`, `apply`, `bind` 메서드를 사용해도 `this`를 교체할 수 없다**.
  - ```javascript
    window.x = 1;

    const normal = function () {
      return this.x;
    };
    const arrow = () => this.x;

    console.log(normal.call({ x: 10 })); // 10
    console.log(arrow.call({ x: 10 })); // 1 (this를 교체할 수 없다)
    ```
  - 화살표 함수는 `call`, `apply`, `bind`를 호출할 수는 있지만 **`this`를 교체할 수는 없고 인수만 전달**할 수 있다.
- 따라서 **메서드를 화살표 함수로 정의하는 것은 피해야 한다**.
  - ```javascript
    // Bad
    const person = {
      name: "Lee",
      sayHi: () => console.log(`Hi ${this.name}`),
    };

    // sayHi 프로퍼티에 할당된 화살표 함수 내부의 this는 상위 스코프인 전역의 this가 가리키는 객체
    // 즉 window를 가리킨다 (전역 객체 window에는 name 프로퍼티가 없다)
    person.sayHi(); // Hi undefined
    ```
  - **ES6 메서드 축약 표현**으로 정의한 ES6 메서드를 사용하는 것이 좋다.
  - ```javascript
    // Good
    const person = {
      name: "Lee",
      sayHi() {
        console.log(`Hi ${this.name}`);
      },
    };

    person.sayHi(); // Hi Lee
    ```
- 프로토타입 객체의 프로퍼티에 화살표 함수를 할당하는 경우도 **같은 문제가 발생**한다.
  - ```javascript
    // Bad
    function Person(name) {
      this.name = name;
    }

    Person.prototype.sayHi = () => console.log(`Hi ${this.name}`);

    const person = new Person("Lee");
    // 상위 스코프인 전역의 this가 가리키는 전역 객체를 가리키므로 name이 없다
    person.sayHi(); // Hi undefined

    // Good
    Person.prototype.sayHi = function () {
      console.log(`Hi ${this.name}`);
    };
    ```
  - 일반 함수가 아닌 **ES6 메서드를 동적으로 추가**하고 싶다면 **객체 리터럴을 바인딩하고 프로토타입의 `constructor` 프로퍼티와 생성자 함수 간의 연결을 재설정**해야 한다.
- **클래스 필드에 할당한 화살표 함수**는 다르게 동작한다.
  - ```javascript
    class Person {
      name = "Lee";

      // 클래스 필드의 화살표 함수는 인스턴스 메서드가 된다
      sayHi = () => console.log(`Hi ${this.name}`);
    }

    const person = new Person();
    person.sayHi(); // Hi Lee
    ```
  - 클래스 필드에 할당한 화살표 함수는 **`constructor` 내부에서 `this`를 참조하는 것과 같은 상위 스코프**를 갖는다.
    - 따라서 `this`는 **클래스가 생성할 인스턴스**를 가리킨다. ([25장](./25.클래스.md#클래스-필드-정의))
  - 다만 **인스턴스마다 함수 객체가 생성**되고 프로토타입 메서드가 아니므로 상속 시 `super`로 호출할 수도 없다. 꼭 `this`를 고정해야 하는 경우(이벤트 핸들러 등)에만 사용하는 것이 좋다.

#### super

- 화살표 함수는 **함수 자체의 `super` 바인딩을 갖지 않는다**.
  - 따라서 화살표 함수 내부에서 `super`를 참조하면 **상위 스코프의 `super`를 참조**한다.
  - ```javascript
    class Base {
      constructor(name) {
        this.name = name;
      }

      sayHi() {
        return `Hi! ${this.name}`;
      }
    }

    class Derived extends Base {
      // 화살표 함수의 super는 상위 스코프인 sayHi 메서드의 super를 가리킨다
      sayHi = () => `${super.sayHi()} how are you doing?`;
    }

    const derived = new Derived("Lee");
    console.log(derived.sayHi()); // Hi! Lee how are you doing?
    ```
  - `Derived`의 `sayHi`는 클래스 필드이므로 **`constructor`와 같은 스코프**이고, 이곳의 `super`는 `Base.prototype`을 가리킨다.

#### arguments

- 화살표 함수는 **함수 자체의 `arguments` 바인딩을 갖지 않는다**.
  - 따라서 화살표 함수 내부에서 `arguments`를 참조하면 **상위 스코프의 `arguments`를 참조**한다.
  - ```javascript
    (function () {
      // 화살표 함수 foo의 arguments는 상위 스코프인 즉시 실행 함수의 arguments를 가리킨다
      const foo = () => console.log(arguments); // [Arguments] {'0': 1, '1': 2}
      foo(3, 4);
    })(1, 2);

    // 화살표 함수 foo의 arguments는 상위 스코프인 전역의 arguments를 가리킨다
    // 하지만 전역에는 arguments 객체가 없다
    const foo = () => console.log(arguments);
    foo(1, 2); // ReferenceError: arguments is not defined
    ```
  - `arguments` 객체는 **함수와 함수 내부에서만 유효**하며 **전역에는 존재하지 않는다**. ([18장](../../week05/윤홍비/18.함수와_일급_객체.md#arguments-프로퍼티))
- 따라서 **화살표 함수로 가변 인자 함수를 구현해야 할 때는 반드시 Rest 파라미터를 사용**해야 한다.

### Rest 파라미터

#### 기본 문법

- **Rest 파라미터(나머지 매개변수)** 는 **매개변수 이름 앞에 세개의 점 `...`을 붙여서 정의한 매개변수**를 의미한다.
  - Rest 파라미터는 **함수에 전달된 인수들의 목록을 배열로 전달**받는다.
  - ```javascript
    function foo(...rest) {
      console.log(rest); // [1, 2, 3, 4, 5]
    }

    foo(1, 2, 3, 4, 5);
    ```
- 일반 매개변수와 Rest 파라미터는 함께 사용할 수 있다.
  - 이때 **먼저 선언된 매개변수에 인수가 할당**되고 **나머지 인수들은 Rest 파라미터에 배열로 할당**된다.
  - ```javascript
    function foo(param, ...rest) {
      console.log(param); // 1
      console.log(rest); // [2, 3, 4, 5]
    }

    foo(1, 2, 3, 4, 5);

    function bar(param1, param2, ...rest) {
      console.log(param1); // 1
      console.log(param2); // 2
      console.log(rest); // [3, 4, 5]
    }

    bar(1, 2, 3, 4, 5);
    ```
- Rest 파라미터는 **반드시 마지막 파라미터**이어야 한다.
  - ```javascript
    function foo(...rest, param1, param2) {}
    // SyntaxError: Rest parameter must be last formal parameter
    ```
- Rest 파라미터는 **단 하나만 선언**할 수 있다.
  - ```javascript
    function foo(...rest1, ...rest2) {}
    // SyntaxError: Rest parameter must be last formal parameter
    ```
- Rest 파라미터는 **함수 객체의 `length` 프로퍼티에 영향을 주지 않는다**.
  - ```javascript
    function foo(...rest) {}
    console.log(foo.length); // 0

    function bar(x, ...rest) {}
    console.log(bar.length); // 1

    function baz(x, y, ...rest) {}
    console.log(baz.length); // 2
    ```

#### Rest 파라미터와 arguments 객체

- ES5에서는 **인수의 개수를 확정할 수 없는 가변 인자 함수**의 경우 `arguments` 객체를 사용하여 인수를 확인했다.
  - `arguments` 객체는 **함수 호출 시 전달된 인수들의 정보를 담고 있는 순회 가능한 유사 배열 객체**이며 함수 내부에서 지역 변수처럼 사용할 수 있다. ([18장](../../week05/윤홍비/18.함수와_일급_객체.md#arguments-프로퍼티))
  - ```javascript
    // ES5
    function sum() {
      // 유사 배열 객체인 arguments 객체를 배열로 변환한다
      var array = Array.prototype.slice.call(arguments);

      return array.reduce(function (pre, cur) {
        return pre + cur;
      }, 0);
    }

    console.log(sum(1, 2, 3, 4, 5)); // 15
    ```
  - `arguments` 객체는 **배열이 아닌 유사 배열 객체**이므로 배열 메서드를 사용하려면 **번거로운 변환 과정**이 필요하다.
- ES6에서는 **Rest 파라미터를 사용하여 가변 인자 함수의 인수 목록을 배열로 직접 전달**받을 수 있다.
  - ```javascript
    // ES6
    function sum(...args) {
      // Rest 파라미터 args에는 배열 [1, 2, 3, 4, 5]가 할당된다
      return args.reduce((pre, cur) => pre + cur, 0);
    }

    console.log(sum(1, 2, 3, 4, 5)); // 15
    ```
- 화살표 함수는 **`arguments` 객체를 갖지 않으므로** 가변 인자 함수를 구현하려면 **반드시 Rest 파라미터를 사용**해야 한다.
  - ```javascript
    const sum = (...args) => args.reduce((pre, cur) => pre + cur, 0);
    ```
- 함수와 ES6 메서드는 `arguments` 객체를 갖고 있지만, **Rest 파라미터를 사용하는 편이 더 명확하고 간결하다**.

| 구분       | `arguments` 객체                 | Rest 파라미터                   |
| ---------- | -------------------------------- | ------------------------------- |
| 타입       | **유사 배열 객체**               | **배열**                        |
| 배열 메서드 | 변환 후에 사용할 수 있다         | 바로 사용할 수 있다             |
| 화살표 함수 | 사용할 수 없다                   | 사용할 수 있다                  |
| 선언       | 암묵적으로 제공된다              | 명시적으로 선언한다             |

### 매개변수 기본값

- 함수를 호출할 때 **매개변수의 개수만큼 인수를 전달하는 것이 바람직**하지만 그렇지 않은 경우에도 에러가 발생하지 않는다.
  - 자바스크립트 엔진이 **매개변수의 개수와 인수의 개수를 체크하지 않기 때문**이다. ([12장](../../week05/윤홍비/12.함수.md))
  - 인수가 전달되지 않은 매개변수의 값은 `undefined`다.
  - ```javascript
    function sum(x, y) {
      return x + y;
    }

    console.log(sum(1)); // NaN
    ```
- 따라서 **매개변수에 인수가 전달되었는지 확인**하여 인수가 전달되지 않은 경우 **매개변수에 기본값을 할당할 필요**가 있다.
  - ```javascript
    // ES5
    function sum(x, y) {
      // 인수가 전달되지 않아 매개변수의 값이 undefined인 경우 기본값을 할당한다
      x = x || 0;
      y = y || 0;

      return x + y;
    }

    console.log(sum(1, 2)); // 3
    console.log(sum(1)); // 1
    ```
- ES6에서 도입된 **매개변수 기본값**을 사용하면 **함수 내에서 수행하던 인수 체크 및 초기화를 간소화**할 수 있다.
  - ```javascript
    // ES6
    function sum(x = 0, y = 0) {
      return x + y;
    }

    console.log(sum(1, 2)); // 3
    console.log(sum(1)); // 1
    ```
- 매개변수 기본값은 **인수를 전달하지 않았을 경우와 `undefined`를 전달한 경우에만 유효**하다.
  - ```javascript
    function logName(name = "Lee") {
      console.log(name);
    }

    logName(); // Lee
    logName(undefined); // Lee
    logName(null); // null (null은 기본값이 적용되지 않는다)
    ```
  - ES5의 `||` 방식은 **`0`, `""`, `false`처럼 falsy한 값도 기본값으로 덮어쓴다**는 문제가 있다.
  - ```javascript
    function sumEs5(x, y) {
      x = x || 10;
      return x + y;
    }
    console.log(sumEs5(0, 1)); // 11 (의도는 1)

    function sumEs6(x = 10, y) {
      return x + y;
    }
    console.log(sumEs6(0, 1)); // 1
    ```
  - 따라서 `||`보다 **기본값 문법이 더 정확하게 동작**한다.
- Rest 파라미터에는 **기본값을 지정할 수 없다**.
  - ```javascript
    function foo(...rest = []) {}
    // SyntaxError: Rest parameter may not have a default initializer
    ```
- 매개변수 기본값은 **함수 객체의 `length` 프로퍼티와 `arguments` 객체에 영향을 주지 않는다**.
  - ```javascript
    function sum(x, y = 0) {
      console.log(arguments);
    }

    console.log(sum.length); // 1

    sum(1); // Arguments { '0': 1 }
    sum(1, 2); // Arguments { '0': 1, '1': 2 }
    ```
  - `length`는 **기본값이 지정된 매개변수 이전까지만** 센다.
  - `arguments`에는 **실제로 전달한 인수만** 담긴다. (기본값은 반영되지 않는다)

### 정리

| 개념                | 설명                                                                         |
| ------------------- | ---------------------------------------------------------------------------- |
| 함수의 구분         | ES6부터 **일반 함수 / 메서드 / 화살표 함수**로 구분하며, 일반 함수만 `constructor`다 |
| 메서드              | **메서드 축약 표현**으로 정의한 함수. `[[HomeObject]]`를 가져 **`super`를 사용**할 수 있다 |
| 화살표 함수         | `this`, `arguments`, `super`, `new.target` 바인딩이 **없고 상위 스코프를 참조**한다 |
| Rest 파라미터       | 인수 목록을 **배열**로 전달받는다 (마지막에 단 하나만 선언)                  |
| 매개변수 기본값     | 인수가 없거나 `undefined`일 때만 적용된다                                    |

- ES6에서는 함수를 **사용 목적에 따라 구분**하여 불필요한 기능(`prototype`, `[[Construct]]`)을 제거했다.
  - 메서드는 `super`를 위해 `[[HomeObject]]`를 갖고, 화살표 함수는 `this` 등을 **상위 스코프에서 가져온다**.
- 화살표 함수는 **콜백 함수 내부의 `this` 불일치 문제를 해결**하기 위해 도입되었다.
  - `this`가 **호출 방식이 아니라 정의된 위치**로 결정되므로 렉시컬 스코프와 같은 방식으로 동작한다. ([24장](../../week09/윤홍비/24.클로저.md#렉시컬-스코프))
  - 대신 **메서드, 프로토타입 메서드, 생성자 함수**로는 사용하지 않는다.
- 가변 인자 함수는 `arguments` 대신 **Rest 파라미터**를 사용하는 것이 좋다.
  - 유사 배열 객체가 아닌 **배열**로 받을 수 있고 **화살표 함수에서도 사용**할 수 있다.
- 매개변수 기본값은 `||` 방식보다 **정확하고 간결**하다.
  - `undefined`가 전달되는 경우에만 동작하므로 `0`, `""`, `false`를 인수로 전달해도 안전하다.
- 지금까지 ES6에서 **함수와 클래스**를 살펴보았다.
  - 클래스의 **메서드와 클래스 필드**는 이 장의 함수 구분과 `this` 규칙 위에서 동작한다. ([25장](./25.클래스.md))
