### 클래스는 프로토타입의 문법적 설탕인가

- 자바스크립트는 **프로토타입 기반 객체지향 언어**다. ([19장](../../week07/윤홍비/19.프로토타입.md))
  - 클래스가 없어도 생성자 함수와 프로토타입으로 상속을 구현할 수 있다.
  - ```javascript
    // ES5: 생성자 함수와 프로토타입
    var Person = (function () {
      function Person(name) {
        this.name = name;
      }

      Person.prototype.sayHi = function () {
        console.log("Hi! My name is " + this.name);
      };

      return Person;
    })();

    var me = new Person("Lee");
    me.sayHi(); // Hi! My name is Lee
    ```
- ES6에서 도입된 클래스는 **같은 일을 더 명확하게 표현**한다.
  - ```javascript
    // ES6: 클래스
    class Person {
      constructor(name) {
        this.name = name;
      }

      sayHi() {
        console.log(`Hi! My name is ${this.name}`);
      }
    }

    const me = new Person("Lee");
    me.sayHi(); // Hi! My name is Lee
    ```
- 클래스는 생성자 함수와 **비슷하게 동작하지만 다르다**.

| 구분                   | 생성자 함수                              | 클래스                                              |
| ---------------------- | ---------------------------------------- | --------------------------------------------------- |
| `new` 연산자           | 없이 호출해도 **일반 함수로 실행**된다   | 없이 호출하면 **TypeError**가 발생한다              |
| 상속                   | 프로토타입 기반으로 직접 구현해야 한다   | `extends`와 `super`를 제공한다                      |
| 호이스팅               | 함수 선언문은 **함수 호이스팅**된다      | 호이스팅은 되지만 **TDZ**에 걸린다                  |
| strict mode            | 기본으로 적용되지 않는다                 | **클래스 몸체**에 암묵적으로 적용된다                 |
| 프로퍼티 열거          | 프로토타입 메서드는 열거될 수 있다       | `[[Enumerable]]`이 `false`이므로 열거되지 않는다    |

- 표에서 **호이스팅**은 다음 예제로 확인할 수 있다.
  - ```javascript
    // 호이스팅: 함수 선언문은 선언 전에 호출할 수 있다
    foo(); // 정상
    function foo() {}

    // 클래스는 호이스팅되지만 선언문 도달 전까지 초기화되지 않는다 (TDZ)
    new Bar(); // ReferenceError: Cannot access 'Bar' before initialization
    class Bar {}
    ```

- 따라서 **클래스를 단순한 문법적 설탕이라고 보기는 어렵다**.
  - 다만 클래스도 **생성자 함수와 마찬가지로 프로토타입 기반의 객체 생성 메커니즘**이다.
  - 클래스는 생성자 함수보다 **엄격하며** 생성자 함수에서는 제공하지 않는 기능도 제공한다.

### 클래스 정의

- 클래스는 `class` 키워드를 사용하여 정의한다.
  - ```javascript
    // 클래스 선언문
    class Person {}
    ```
  - 클래스 이름은 **파스칼 케이스**를 사용하는 것이 일반적이다.
- 클래스는 **일급 객체**이므로 표현식으로도 정의할 수 있다. ([18장](../../week05/윤홍비/18.함수와_일급_객체.md))
  - ```javascript
    // 익명 클래스 표현식
    const Person = class {};

    // 기명 클래스 표현식
    const Person2 = class MyClass {};
    ```
  - 이름 없이 값처럼 생성(리터럴)할 수 있고, 변수나 객체에 저장할 수 있으며, 함수의 인수로 전달하거나 반환값으로 사용할 수 있다.
- 사실 클래스는 **함수다**.
  - ```javascript
    class Person {}

    console.log(typeof Person); // function
    ```
  - 따라서 클래스는 값처럼 사용할 수 있는 일급 객체다.
- 클래스 몸체에는 **메서드만 선언**할 수 있다.
  - 클래스 몸체에 정의할 수 있는 메서드는 `constructor`, 프로토타입 메서드, 정적 메서드 세 가지다.
  - ```javascript
    class Person {
      // 생성자
      constructor(name) {
        this.name = name; // 인스턴스 프로퍼티
      }

      // 프로토타입 메서드
      sayHi() {
        console.log(`Hi! My name is ${this.name}`);
      }

      // 정적 메서드
      static sayHello() {
        console.log("Hello!");
      }
    }
    ```

### 클래스 호이스팅

- 클래스 선언문도 호이스팅이 발생한다.
  - 하지만 **let, const와 같이 TDZ에 빠지기 때문에** 호이스팅이 발생하지 않는 것처럼 동작한다. ([15장](../../week06/윤홍비/15.let,const키워드와_블록레벨스코프.md#변수-호이스팅))
  - ```javascript
    console.log(Person); // ReferenceError: Cannot access 'Person' before initialization

    class Person {}
    ```
- 클래스는 `typeof`가 `function`이지만 **함수 선언문과 호이스팅 방식이 다르다**.
  - 함수 선언문은 평가 단계에서 **식별자 등록과 함수 객체 생성이 한꺼번에** 이루어진다.
  - 반면 클래스 선언문은 식별자만 등록하고 **선언문이 실행되기 전까지 초기화하지 않는다**.
  - 클래스 정의에는 `extends` 표현식, 계산된 메서드 이름, static 필드처럼 **실행 시점에 평가되어야 하는 코드**가 포함되기 때문이다.
  - 따라서 선언문 이전에 참조하면 에러가 발생한다.
- 이는 `let`, `const`와 같은 동작이다. ([23장](../../week09/윤홍비/23.실행컨텍스트.md#212-선언적-환경-레코드-생성))
  - 환경 레코드에는 등록되어 있으므로 상위 스코프의 변수를 찾지 않고 에러가 발생한다.

### 인스턴스 생성

- 클래스는 **생성자 함수**이며 `new` 연산자와 함께 호출되어 인스턴스를 생성한다.
  - ```javascript
    class Person {}

    const me = new Person();
    console.log(me); // Person {}
    ```
- 클래스는 **반드시 `new` 연산자와 함께 호출**해야 한다.
  - ```javascript
    class Person {}

    const me = Person(); // TypeError: Class constructor Person cannot be invoked without 'new'
    ```
- 기명 클래스 표현식으로 정의한 클래스의 **이름은 클래스 몸체 내부에서만 유효**하다.
  - ```javascript
    const Person = class MyClass {};

    const me = new Person(); // 정상
    console.log(MyClass); // ReferenceError: MyClass is not defined
    const you = new MyClass(); // ReferenceError: MyClass is not defined
    ```
  - 클래스 객체는 **힙에 하나만 생성**되고, 이름이 서로 다른 렉시컬 환경에 등록된다.
    - `Person`은 **전역 렉시컬 환경**, `MyClass`는 **클래스 몸체 전용 렉시컬 환경**에 등록된다.
    - 둘은 **같은 클래스 객체를 가리키는 두 식별자**다.

  - 식별자는 **바깥쪽으로만** 검색하므로 전역에서는 몸체 전용 환경의 `MyClass`를 찾을 수 없다. ([13장](../../week05/윤홍비/13.스코프.md#스코프-체인))
    - 반면 클래스 몸체 내부에서는 `MyClass`를 참조할 수 있다.

### 메서드

- 클래스 몸체에서 정의할 수 있는 메서드는 3가지다.
  - `constructor`
  - 프로토타입 메서드
  - 정적 메서드

#### constructor

- `constructor`는 **인스턴스를 생성하고 초기화하기 위한 특수한 메서드**다.
  - ```javascript
    class Person {
      constructor(name) {
        // 인스턴스 생성 및 초기화
        this.name = name;
      }
    }
    ```
- 클래스는 함수이고 **`constructor`는 클래스가 평가되어 생성한 함수 객체의 몸체**가 된다.
  - ```javascript
    console.log(typeof Person); // function


    // 프로토타입의 constructor 프로퍼티가 가리키는 것은 별도의 메서드가 아니라 클래스 자신이다
    console.log(Person.prototype.constructor === Person); // true
    ```
  - 즉 `constructor`는 **메서드가 아니라 클래스 자신**이다.
- `constructor`는 **생략할 수 있다**.
  - 생략하면 **빈 `constructor`가 암묵적으로 정의**된다.
  - ```javascript
    class Person {
      // constructor() {}  ← 암묵적으로 정의된다
    }

    const me = new Person();
    console.log(me); // Person {}
    ```
- 프로퍼티가 추가되어 초기화된 인스턴스를 생성하려면 `constructor` 내부에서 `this`에 인스턴스 프로퍼티를 추가한다.
  - ```javascript
    class Person {
      constructor() {
        this.name = "Lee";
        this.address = "Seoul";
      }
    }

    const me = new Person();
    console.log(me); // Person {name: "Lee", address: "Seoul"}
    ```
  - 인스턴스를 생성할 때 **클래스 외부에서 초기값을 전달**하려면 매개변수를 선언한다.
  - ```javascript
    class Person {
      constructor(name, address) {
        this.name = name;
        this.address = address;
      }
    }

    const me = new Person("Lee", "Seoul");
    console.log(me); // Person {name: "Lee", address: "Seoul"}
    ```
- `constructor`는 **클래스 내에 최대 한 개만 존재**할 수 있다.
  - 2개 이상 포함하면 문법 에러(SyntaxError)가 발생한다.
- `constructor`는 별도의 반환문을 갖지 않아야 한다.
  - `new` 연산자와 함께 클래스가 호출되면 **암묵적으로 `this`, 즉 인스턴스를 반환**한다. ([17장](../../week07/윤홍비/17.생성자함수에_의한_객체생성.md))
  - ```javascript
    class Person {
      constructor(name) {
        this.name = name;

        // 명시적으로 객체를 반환하면 암묵적인 this 반환이 무시된다
        return {};
      }
    }

    const me = new Person("Lee");
    console.log(me); // {}
    ```
  - 원시값을 반환하면 무시되고 `this`가 반환된다.
  - 이처럼 **`return`을 명시하면 클래스의 기본 동작이 훼손**되므로 `constructor` 내부에서 `return`은 반드시 생략해야 한다.

#### 프로토타입 메서드

- 생성자 함수에서는 프로토타입 메서드를 명시적으로 추가해야 한다.
  - ```javascript
    function Person(name) {
      this.name = name;
    }

    Person.prototype.sayHi = function () {
      console.log(`Hi! My name is ${this.name}`);
    };
    ```
- 클래스 몸체에서 정의한 메서드는 **기본적으로 프로토타입 메서드가 된다**.
  - ```javascript
    class Person {
      constructor(name) {
        this.name = name;
      }

      // 프로토타입 메서드
      sayHi() {
        console.log(`Hi! My name is ${this.name}`);
      }
    }

    const me = new Person("Lee");
    me.sayHi(); // Hi! My name is Lee
    ```
- 생성자 함수와 마찬가지로 클래스가 생성한 인스턴스는 **프로토타입 체인의 일원**이 된다. ([19장](../../week07/윤홍비/19.프로토타입.md#프로토타입-체인))

    ```mermaid
    flowchart LR
        ME["me 인스턴스<br/>name: 'Lee'"]
        PROTO["Person.prototype<br/>constructor<br/>sayHi"]
        OBJ["Object.prototype<br/>hasOwnProperty ..."]
        NULL["null"]
        CLS["Person (클래스)"]

        ME ==>|"[[Prototype]]"| PROTO
        PROTO ==>|"[[Prototype]]"| OBJ
        OBJ ==>|"[[Prototype]]"| NULL
        PROTO -.->|"constructor"| CLS
        CLS -.->|"prototype"| PROTO
    ```

  - 따라서 `me`에서 `sayHi`를 찾지 못하면 **프로토타입 체인을 따라 `Person.prototype`에서 찾는다**.
  - 또한 `Object.prototype`의 메서드(`hasOwnProperty` 등)도 상속받아 사용할 수 있다.
- 클래스가 정의한 메서드는 **생성자 함수와 달리 열거되지 않는다**.
  - ```javascript
    class Person {
      sayHi() {}
    }

    const me = new Person();

    for (const key in me) {
      console.log(key); // (아무것도 출력되지 않는다)
    }
    ```
  - 클래스의 메서드는 `[[Enumerable]]`이 `false`이기 때문이다. ([16장](../../week06/윤홍비/16.프로퍼티_어트리뷰트.md))

#### 정적 메서드

- **정적(static) 메서드**는 인스턴스를 생성하지 않아도 호출할 수 있는 메서드다.
  - 생성자 함수에서는 **명시적으로 생성자 함수에 메서드를 추가**한다.
  - ```javascript
    function Person(name) {
      this.name = name;
    }

    // 정적 메서드
    Person.sayHello = function () {
      console.log("Hello!");
    };

    Person.sayHello(); // Hello!
    ```
- 클래스에서는 메서드에 `static` 키워드를 붙이면 정적 메서드가 된다.
  - ```javascript
    class Person {
      // 정적 메서드
      static sayHello() {
        console.log("Hello!");
      }
    }

    Person.sayHello(); // Hello!
    ```
  - 정적 메서드는 **클래스에 바인딩된 메서드**이므로 클래스로 호출한다.
  - 클래스는 클래스 정의가 평가되는 시점에 **함수 객체가 되므로 인스턴스와 달리 별도의 생성 과정이 필요 없다**.
- 정적 메서드는 **인스턴스로 호출할 수 없다**.
  - `Person`(클래스)과 `Person.prototype`(프로토타입 객체)은 서로 다른 객체이기 때문이다.
  - ```javascript
    const me = new Person();
    me.sayHello(); // TypeError: me.sayHello is not a function
    ```

    ```mermaid
    flowchart LR

            direction TB
            ME["me 인스턴스"]
            PP["Person.prototype<br/>sayHi (프로토타입 메서드)"]
            OP["Object.prototype"]
            ME ==> PP ==> OP
        end

        subgraph CLASS["클래스 (함수 객체)"]

        ME -.->|"체인에 Person이 없다"| CLS

#### 정적 메서드와 프로토타입 메서드의 차이

- 둘의 차이는 다음과 같다.
  1. 정적 메서드와 프로토타입 메서드는 **자신이 속해 있는 프로토타입 체인이 다르다**.
  2. 정적 메서드는 **클래스로 호출**하고 프로토타입 메서드는 **인스턴스로 호출**한다.
  3. 정적 메서드는 **인스턴스 프로퍼티를 참조할 수 없지만** 프로토타입 메서드는 참조할 수 있다.
- 3번의 이유는 `this` 바인딩 때문이다. ([22장](../../week08/윤홍비/22.this.md#함수-호출-방식과-this-바인딩))
  - ```javascript
    class Square {
      // 정적 메서드
      static area(width, height) {
        return width * height;
      }
    }

    console.log(Square.area(10, 10)); // 100
    ```
  - 정적 메서드는 클래스로 호출하므로 **`this`는 클래스를 가리킨다**.
  - 인스턴스 프로퍼티를 참조하려면 인스턴스를 생성해야 하는데, **정적 메서드 내부에서는 인스턴스를 가리키는 `this`를 사용할 수 없다**.
  - ```javascript
    class Square {
      constructor(width, height) {
        this.width = width;
        this.height = height;
      }

      // 프로토타입 메서드: this는 인스턴스
      area() {
        return this.width * this.height;
      }
    }

    const square = new Square(10, 10);
    console.log(square.area()); // 100
    ```
- 따라서 **메서드 내부에서 `this`를 사용하지 않는다면 정적 메서드로 정의**할 수 있다.
  - 표준 빌트인 객체의 `Math`, `Number`, `JSON`, `Object`, `Reflect` 등도 다양한 정적 메서드를 가지고 있다. ([21장](../../week08/윤홍비/21.빌트인_객체.md))
  - 이들은 **애플리케이션 전역에서 사용할 유틸리티 함수**다.
  - ```javascript
    // 전역에서 사용하는 유틸리티 함수는 정적 메서드로 정의한다
    Math.max(1, 2, 3); // 3
    Number.isInteger(1); // true
    Object.keys({ a: 1 }); // ['a']
    ```

#### 클래스에서 정의한 메서드의 특징

1. `function` 키워드를 생략한 **메서드 축약 표현**을 사용한다.
2. 객체 리터럴과는 다르게 **클래스에 메서드를 정의할 때는 콤마가 필요 없다**.
3. **암묵적으로 strict mode**로 실행된다.
4. **`for...in` 문이나 `Object.keys` 등으로 열거할 수 없다**. (`[[Enumerable]]: false`)
5. **내부 메서드 `[[Construct]]`를 갖지 않는 non-constructor**다.
   - 따라서 `new` 연산자와 함께 호출할 수 없다.
   - ```javascript
     class Person {
       sayHi() {}
       static sayHello() {}
     }

     new Person().sayHi(); // 정상 (인스턴스 생성은 클래스 자체로 한다)
     new Person.prototype.sayHi(); // TypeError: Person.prototype.sayHi is not a constructor
     ```

### 클래스의 인스턴스 생성 과정

- `new` 연산자와 함께 클래스를 호출하면 **생성자 함수와 마찬가지로 다음 과정을 거쳐 인스턴스가 생성**된다.

#### 1. 인스턴스 생성과 this 바인딩

- `new` 연산자와 함께 클래스를 호출하면 `constructor`의 내부 코드가 실행되기에 앞서 **암묵적으로 빈 객체가 생성**된다.
  - 이 빈 객체가 바로 **클래스가 생성한 인스턴스**다.
  - 이때 클래스가 생성한 인스턴스의 프로토타입으로 **클래스의 `prototype` 프로퍼티가 가리키는 객체**가 설정된다.
- 그리고 인스턴스는 `this`에 바인딩된다.
  - 따라서 `constructor` 내부의 `this`는 **클래스가 생성한 인스턴스**를 가리킨다.

#### 2. 인스턴스 초기화

- `constructor`의 내부 코드가 실행되어 **`this`에 바인딩되어 있는 인스턴스를 초기화**한다.
  - 즉 `this`에 바인딩되어 있는 인스턴스에 프로퍼티를 추가하고 `constructor`가 인수로 전달받은 초기값으로 프로퍼티 값을 초기화한다.
  - `constructor`가 생략되었다면 이 과정도 생략된다.

#### 3. 인스턴스 반환

- 클래스의 모든 처리가 끝나면 **완성된 인스턴스가 바인딩된 `this`가 암묵적으로 반환**된다.
  - ```javascript
    class Person {
      constructor(name) {
        // 1. 암묵적으로 빈 객체가 생성되고 this에 바인딩된다
        console.log(this); // Person {}
        console.log(Object.getPrototypeOf(this) === Person.prototype); // true

        // 2. this에 바인딩되어 있는 인스턴스를 초기화한다
        this.name = name;

        // 3. 완성된 인스턴스가 바인딩된 this가 암묵적으로 반환된다
      }
    }
    ```

    ```mermaid
    flowchart LR
        NEW["new Person('Lee')"]
        S1["① 빈 객체 생성<br/>prototype 연결<br/>this에 바인딩"]
        S2["② constructor 실행<br/>this.name = 'Lee'"]
        S3["③ this 암묵적 반환"]

        NEW ==> S1 ==> S2 ==> S3
    ```

### 프로퍼티

#### 인스턴스 프로퍼티

- 인스턴스 프로퍼티는 **`constructor` 내부에서 정의**해야 한다.
  - ```javascript
    class Person {
      constructor(name) {
        // 인스턴스 프로퍼티
        this.name = name; // public
      }
    }

    const me = new Person("Lee");
    console.log(me); // Person {name: "Lee"}
    ```
- 접근 제한자를 지원하지 않으므로 **`constructor` 내부에서 정의한 인스턴스 프로퍼티는 언제나 public**하다.
  - ES2022에서 **private 필드**가 도입되었다. (아래 참고)

#### 접근자 프로퍼티

- **접근자 프로퍼티(accessor property)** 는 자체적으로는 값을 갖지 않고 **다른 데이터 프로퍼티의 값을 읽거나 저장할 때 사용하는 접근자 함수**로 구성된 프로퍼티다. ([16장](../../week06/윤홍비/16.프로퍼티_어트리뷰트.md))
  - ```javascript
    class Person {
      constructor(firstName, lastName) {
        this.firstName = firstName;
        this.lastName = lastName;
      }

      // getter: 프로퍼티처럼 참조하는 형식으로 사용한다
      get fullName() {
        return `${this.firstName} ${this.lastName}`;
      }

      // setter: 프로퍼티처럼 값을 할당하는 형식으로 사용한다
      set fullName(name) {
        [this.firstName, this.lastName] = name.split(" ");
      }
    }

    const me = new Person("Gildong", "Hong");

    console.log(`${me.firstName} ${me.lastName}`); // Gildong Hong

    me.fullName = "Heungmin Son"; // setter 호출
    console.log(me); // Person {firstName: "Heungmin", lastName: "Son"}

    console.log(me.fullName); // getter 호출 → Heungmin Son
    ```
  - `getter`는 호출하는 것이 아니라 **프로퍼티처럼 참조**하며, 반드시 무언가를 반환해야 한다.
  - `setter`는 **프로퍼티처럼 값을 할당**하며, 매개변수는 **반드시 하나**여야 한다.
- 접근자 프로퍼티는 **인스턴스 프로퍼티가 아니라 프로토타입의 프로퍼티**다.
  - ```javascript
    console.log(Object.getOwnPropertyNames(me)); // ['firstName', 'lastName']
    console.log(Object.getOwnPropertyNames(Object.getPrototypeOf(me)));
    // ['constructor', 'fullName']
    ```
  - `fullName`은 `Person.prototype`에 존재한다.

#### 클래스 필드 정의

- **클래스 필드(class field)** 는 클래스 기반 객체지향 언어에서 **클래스가 생성할 인스턴스의 프로퍼티**를 가리키는 용어다.
  - 자바에서는 다음과 같이 클래스 몸체에 직접 정의할 수 있다.
  - ```java
    public class Person {
      // 클래스 필드 정의
      private String firstName = "";
      private String lastName = "";

      Person(String firstName, String lastName) {
        this.firstName = firstName;
        this.lastName = lastName;
      }
    }
    ```
- 이전에는 클래스 몸체에서 메서드만 정의할 수 있었다.
  - ```javascript
    class Person {
      name = "Lee"; // ES2022 이전에는 SyntaxError
    }
    ```
  - 하지만 **ES2022부터 클래스 몸체에 인스턴스 프로퍼티를 직접 정의할 수 있다**.
  - ```javascript
    class Person {
      // 클래스 필드 정의
      name = "Lee";
    }

    const me = new Person();
    console.log(me); // Person {name: "Lee"}
    ```
- 클래스 필드를 정의하는 경우 **`this`에 클래스 필드를 바인딩해서는 안 된다**.
  - ```javascript
    class Person {
      this.name = ""; // SyntaxError
    }
    ```
  - `this`는 `constructor`와 메서드 내에서만 유효하다.
- 클래스 필드를 참조하는 경우에는 **반드시 `this`를 사용**해야 한다.
  - ```javascript
    class Person {
      name = "Lee";

      constructor() {
        console.log(name); // ReferenceError: name is not defined
        console.log(this.name); // Lee
      }
    }
    ```
- 초기값을 할당하지 않으면 **`undefined`를 갖는다**.
  - ```javascript
    class Person {
      name;
    }

    console.log(new Person()); // Person {name: undefined}
    ```
- 외부에서 초기값을 전달받아야 한다면 **`constructor`에서 초기화**해야 한다.
  - ```javascript
    class Person {
      name;

      constructor(name) {
        this.name = name; // 클래스 필드를 초기화한다
      }
    }

    const me = new Person("Lee");
    console.log(me); // Person {name: "Lee"}
    ```
  - 어차피 `constructor`에서 초기화해야 한다면 **클래스 필드를 굳이 정의할 필요가 없다**.
  - 다만 `constructor` 밖에서 선언해 두면 **어떤 프로퍼티를 갖는 클래스인지 한눈에 알 수 있다**는 장점이 있다.
- 함수는 일급 객체이므로 **클래스 필드에 할당할 수 있다**.
  - ```javascript
    class Person {
      name = "Lee";

      getName = function () {
        return this.name;
      };

      // 화살표 함수도 가능하다
      getName2 = () => this.name;
    }

    const me = new Person();
    console.log(me.getName()); // Lee
    ```
  - 이 경우 메서드가 **프로토타입 메서드가 아닌 인스턴스 메서드**가 된다.
    - 인스턴스마다 함수 객체가 생성되므로 **중복 생성**되는 문제가 있다. ([24장](../../week09/윤홍비/24.클로저.md#캡슐화와-정보-은닉))
    - 따라서 일반적으로는 **메서드는 프로토타입 메서드로 정의**하는 것이 좋다.
  - 다만 화살표 함수는 **상위 스코프의 `this`를 참조**하므로, 콜백으로 넘길 때 `this`가 유지되어야 하는 경우에 사용하기도 한다. (26장)

#### private 필드 정의

- 자바스크립트는 **public 필드를 외부에서 참조할 수 있는 것이 기본**이다.
  - ES2022에서 **`#` 접두사**를 사용하여 private 필드를 정의할 수 있게 되었다. ([24장](../../week09/윤홍비/24.클로저.md#캡슐화와-정보-은닉))
  - ```javascript
    class Person {
      // private 필드 정의
      #name = "";

      constructor(name) {
        // private 필드 참조
        this.#name = name;
      }
    }

    const me = new Person("Lee");

    // private 필드 #name은 클래스 외부에서 참조할 수 없다
    console.log(me.#name); // SyntaxError: Private field '#name' must be declared in an enclosing class
    ```
- private 필드의 접근 가능성을 정리하면 다음과 같다.

| 접근 위치              | public 필드 | private 필드 |
| ---------------------- | :---------: | :----------: |
| 클래스 내부            |     ○       |      ○       |
| 자식 클래스 내부       |     ○       |      ✕       |
| 클래스 인스턴스를 통한 외부 |  ○       |      ✕       |

- private 필드는 **클래스 내부에서만 참조**할 수 있다.
  - 자식 클래스에서도 참조할 수 없다.
  - 반드시 **클래스 몸체에 미리 선언**해야 한다. (`constructor`에서 `this.#x = ...`로 새로 만들 수 없다)
  - ```javascript
    class Person {
      constructor(name) {
        this.#name = name; // SyntaxError: 선언되지 않은 private 필드
      }
    }
    ```
- 외부에서 private 필드에 접근해야 한다면 **접근자 프로퍼티**를 사용한다.
  - ```javascript
    class Person {
      #name = "";

      constructor(name) {
        this.#name = name;
      }

      // name은 접근자 프로퍼티다
      get name() {
        return this.#name.trim();
      }
    }

    const me = new Person(" Lee ");
    console.log(me.name); // Lee
    ```
- 클로저로 구현했던 정보 은닉과 달리 **인스턴스별로 독립적인 private 상태**를 갖는다. ([24장](../../week09/윤홍비/24.클로저.md#캡슐화와-정보-은닉))
  - 프로토타입 메서드에서도 인스턴스마다 다른 `#age`를 참조할 수 있어 **24장에서 겪은 상태 공유 문제가 해결**된다.

#### static 필드 정의

- `static` 키워드를 사용하여 **정적 필드**를 정의할 수 있다.
  - ```javascript
    class MyMath {
      // static public 필드
      static PI = 22 / 7;

      // static private 필드
      static #num = 10;

      // static 메서드
      static increment() {
        return ++MyMath.#num;
      }
    }

    console.log(MyMath.PI); // 3.142857142857143
    console.log(MyMath.increment()); // 11
    ```

### 상속에 의한 클래스 확장

#### 클래스 상속과 생성자 함수 상속

- **상속에 의한 클래스 확장**은 지금까지 살펴본 프로토타입 기반 상속과 달리 **기존 클래스를 상속받아 새로운 클래스를 확장(extends)하여 정의**하는 것이다.
  - 클래스와 생성자 함수는 인스턴스를 생성할 수 있는 함수라는 점에서 유사하다.
  - 하지만 **클래스는 상속을 통해 기존 클래스를 확장할 수 있는 문법이 기본적으로 제공**된다.
  - 반면 생성자 함수는 그렇지 않다.
- 다음은 동물을 클래스로 표현한 예제다.
  - ```javascript
    class Animal {
      constructor(age, weight) {
        this.age = age;
        this.weight = weight;
      }

      eat() {
        return "eat";
      }

      move() {
        return "move";
      }
    }

    // 상속을 통해 Animal 클래스를 확장한 Bird 클래스
    class Bird extends Animal {
      fly() {
        return "fly";
      }
    }

    const bird = new Bird(1, 5);

    console.log(bird); // Bird {age: 1, weight: 5}
    console.log(bird instanceof Bird); // true
    console.log(bird instanceof Animal); // true

    console.log(bird.eat()); // eat
    console.log(bird.move()); // move
    console.log(bird.fly()); // fly
    ```
  - `Bird`는 `Animal`의 `eat`, `move`를 상속받고 `fly`를 추가로 갖는다.
- 상속에 의해 확장된 클래스를 **서브클래스(subclass)** 라 하고 상속된 클래스를 **슈퍼클래스(superclass)** 라 한다.
  - 서브클래스를 **파생 클래스(derived class)** 또는 **자식 클래스(child class)** 라 한다.
  - 슈퍼클래스를 **베이스 클래스(base class)** 또는 **부모 클래스(parent class)** 라 한다.
- 이 상속 관계는 **두 가지 프로토타입 체인으로 구현**된다.
  - 서브클래스의 `prototype`이 슈퍼클래스의 `prototype`을 가리킨다. (인스턴스 간 상속)
  - 서브클래스 자체의 `[[Prototype]]`이 슈퍼클래스를 가리킨다. (정적 메서드 상속)

    ```mermaid
    flowchart TB
        subgraph INSTANCE["인스턴스 프로토타입 체인"]
            direction LR
            BIRD_OBJ["bird 인스턴스"]
            BIRD_PROTO["Bird.prototype<br/>fly"]
            ANIMAL_PROTO["Animal.prototype<br/>eat, move"]
            OBJ_PROTO["Object.prototype"]

            BIRD_OBJ ==> BIRD_PROTO ==> ANIMAL_PROTO ==> OBJ_PROTO
        end

        subgraph STATIC["클래스(정적) 프로토타입 체인"]
            direction LR
            BIRD["Bird"]
            ANIMAL["Animal"]
            FUNC["Function.prototype"]

            BIRD ==> ANIMAL ==> FUNC
        end
    ```

  - 따라서 `Bird`는 `Animal`의 **정적 메서드도 상속**받는다.
  - ```javascript
    class Animal {
      static create() {
        return "created";
      }
    }
    class Bird extends Animal {}

    console.log(Bird.create()); // created
    console.log(Object.getPrototypeOf(Bird) === Animal); // true
    ```

#### extends 키워드

- 상속을 통해 클래스를 확장하려면 **`extends` 키워드**를 사용하여 상속받을 클래스를 정의한다.
  - ```javascript
    // 수퍼(베이스/부모) 클래스
    class Base {}

    // 서브(파생/자식) 클래스
    class Derived extends Base {}
    ```
- `extends` 키워드의 역할은 **수퍼클래스와 서브클래스 간의 상속 관계를 설정**하는 것이다.
  - 클래스도 프로토타입을 통해 상속 관계를 구현한다.
  - 이를 통해 **프로토타입 메서드, 정적 메서드 모두 상속**이 가능하다.

#### 동적 상속

- `extends` 키워드는 **클래스뿐만 아니라 생성자 함수를 상속받아 클래스를 확장**할 수도 있다.
  - 단 `extends` 키워드 앞에는 **반드시 클래스가 와야 한다**.
  - ```javascript
    // 생성자 함수
    function Base(a) {
      this.a = a;
    }

    // 생성자 함수를 상속받는 서브클래스
    class Derived extends Base {}

    const derived = new Derived(1);
    console.log(derived); // Derived {a: 1}
    ```
- `extends` 키워드 다음에는 **클래스뿐만 아니라 `[[Construct]]` 내부 메서드를 갖는 함수 객체로 평가될 수 있는 모든 표현식**을 사용할 수 있다.
  - 이를 통해 **동적으로 상속받을 대상을 결정**할 수 있다.
  - ```javascript
    function Base1() {}
    class Base2 {}

    let condition = true;

    // 조건에 따라 동적으로 상속 대상을 결정하는 서브클래스
    class Derived extends (condition ? Base1 : Base2) {}

    const derived = new Derived();
    console.log(derived); // Derived {}

    console.log(derived instanceof Base1); // true
    console.log(derived instanceof Base2); // false
    ```

#### 서브클래스의 constructor

- 서브클래스에서 `constructor`를 생략하면 **다음과 같은 `constructor`가 암묵적으로 정의**된다.
  - `args`는 `new` 연산자와 함께 클래스를 호출할 때 전달한 인수의 리스트다.
  - ```javascript
    constructor(...args) {
      super(...args);
    }
    ```
  - `super()`는 **슈퍼클래스의 `constructor`를 호출하여 인스턴스를 생성**한다.
  - ```javascript
    class Base {}
    class Derived extends Base {}

    // 암묵적으로 다음과 같은 constructor가 정의된다
    // class Derived extends Base {
    //   constructor(...args) { super(...args); }
    // }

    const derived = new Derived();
    console.log(derived); // Derived {}
    ```

#### super 키워드

- `super` 키워드는 **함수처럼 호출할 수도 있고 `this`와 같이 식별자처럼 참조할 수도 있는 특수한 키워드**다.
  - `super`를 호출하면 **슈퍼클래스의 `constructor`를 호출**한다.
  - `super`를 참조하면 **슈퍼클래스의 메서드를 호출**할 수 있다.

##### super 호출

- `super`를 호출하면 **슈퍼클래스의 `constructor`(super-constructor)를 호출**한다.
  - ```javascript
    class Base {
      constructor(a, b) {
        this.a = a;
        this.b = b;
      }
    }

    class Derived extends Base {
      // 서브클래스의 constructor를 생략하면 암묵적으로 정의된다
      // constructor(...args) { super(...args); }
    }

    const derived = new Derived(1, 2);
    console.log(derived); // Derived {a: 1, b: 2}
    ```
- 서브클래스에서 **추가한 프로퍼티가 있다면 `constructor`를 명시적으로 정의**해야 한다.
  - 이때는 `new` 연산자와 함께 서브클래스를 호출할 때 전달한 인수 중에서 **슈퍼클래스의 `constructor`에 전달할 인수를 직접 `super`로 전달**한다.
  - ```javascript
    class Base {
      constructor(a, b) {
        this.a = a;
        this.b = b;
      }
    }

    class Derived extends Base {
      constructor(a, b, c) {
        super(a, b);
        this.c = c;
      }
    }

    const derived = new Derived(1, 2, 3);
    console.log(derived); // Derived {a: 1, b: 2, c: 3}
    ```
- `super`를 호출할 때 **주의할 사항**은 다음과 같다.
  1. 서브클래스에서 `constructor`를 생략하지 않는 경우 **서브클래스의 `constructor`에서는 반드시 `super`를 호출**해야 한다.
  2. 서브클래스의 `constructor`에서 **`super`를 호출하기 전에는 `this`를 참조할 수 없다**.
  3. `super`는 **반드시 서브클래스의 `constructor`에서만 호출**한다.
  - ```javascript
    class Base {}

    class Derived extends Base {
      constructor() {
        // ReferenceError: Must call super constructor in derived class
        // before accessing 'this' or returning from derived constructor
        console.log("constructor call");
      }
    }

    new Derived();
    ```
  - ```javascript
    class Derived extends Base {
      constructor() {
        // ReferenceError: super 호출 전에 this를 참조할 수 없다
        this.a = 1;
        super();
      }
    }
    ```
  - 이유는 다음 절의 **인스턴스 생성 과정**에서 확인할 수 있다.

##### super 참조

- 메서드 내에서 `super`를 참조하면 **슈퍼클래스의 메서드를 호출**할 수 있다.

1. **서브클래스의 프로토타입 메서드 내에서 `super.sayHi`는 슈퍼클래스의 프로토타입 메서드 `sayHi`를 가리킨다**.
   - ```javascript
     class Base {
       constructor(name) {
         this.name = name;
       }

       sayHi() {
         return `Hi! ${this.name}`;
       }
     }

     class Derived extends Base {
       sayHi() {
         // super.sayHi는 Base.prototype.sayHi를 가리킨다
         return `${super.sayHi()}. how are you doing?`;
       }
     }

     const derived = new Derived("Lee");
     console.log(derived.sayHi()); // Hi! Lee. how are you doing?
     ```
   - `super` 참조를 통해 슈퍼클래스의 메서드를 참조하려면 **`super`가 슈퍼클래스의 메서드가 바인딩된 객체, 즉 `Base.prototype`을 가리켜야** 한다.
   - 이를 위해 메서드는 **내부 슬롯 `[[HomeObject]]`를 가지며** 자신을 바인딩하고 있는 객체를 가리킨다.
     - `super` 참조는 `[[HomeObject]]`의 프로토타입을 가리킨다.
     - 즉 `Derived.prototype.sayHi`의 `[[HomeObject]]`는 `Derived.prototype`이고, 그 프로토타입인 `Base.prototype`이 `super`가 된다.

     ```mermaid
     flowchart LR
         SAYHI["Derived.prototype.sayHi<br/>[[HomeObject]]"]
         DP["Derived.prototype"]
         BP["Base.prototype<br/>sayHi"]

         SAYHI ==>|"[[HomeObject]]"| DP
         DP ==>|"[[Prototype]] = super"| BP
     ```

   - **`super` 참조는 메서드 축약 표현으로 정의된 함수만 사용할 수 있다**. (`[[HomeObject]]`를 갖는 ES6 메서드)
     - ```javascript
       const obj = {
         foo: function () {
           return super.toString(); // SyntaxError: 'super' keyword unexpected here
         },
         bar() {
           return super.toString(); // 정상
         },
       };
       ```
2. **서브클래스의 정적 메서드 내에서 `super.sayHi`는 슈퍼클래스의 정적 메서드 `sayHi`를 가리킨다**.
   - ```javascript
     class Base {
       static sayHi() {
         return "Hi!";
       }
     }

     class Derived extends Base {
       static sayHi() {
         // super.sayHi는 Base.sayHi를 가리킨다
         return `${super.sayHi()} how are you doing?`;
       }
     }

     console.log(Derived.sayHi()); // Hi! how are you doing?
     ```

#### 상속 클래스의 인스턴스 생성 과정

- 다음 예제로 서브클래스가 인스턴스를 생성하는 과정을 살펴보자.
  - ```javascript
    class Rectangle {
      constructor(width, height) {
        this.width = width;
        this.height = height;
      }

      getArea() {
        return this.width * this.height;
      }

      toString() {
        return `width = ${this.width}, height = ${this.height}`;
      }
    }

    class ColorRectangle extends Rectangle {
      constructor(width, height, color) {
        super(width, height);
        this.color = color;
      }

      // 메서드 오버라이딩
      toString() {
        return super.toString() + `, color = ${this.color}`;
      }
    }

    const colorRectangle = new ColorRectangle(2, 4, "red");
    console.log(colorRectangle); // ColorRectangle {width: 2, height: 4, color: "red"}

    // 상속을 통해 getArea 메서드를 사용한다
    console.log(colorRectangle.getArea()); // 8

    // 오버라이딩된 toString 메서드를 호출한다
    console.log(colorRectangle.toString()); // width = 2, height = 4, color = red
    ```
- 서브클래스 `ColorRectangle`이 `new` 연산자와 함께 호출되면 다음 과정을 거쳐 인스턴스를 생성한다.

##### 1. 서브클래스의 super 호출

- 자바스크립트 엔진은 클래스를 평가할 때 **수퍼클래스와 서브클래스를 `constructor`의 `[[ConstructorKind]]` 내부 슬롯으로 구분**한다.
  - 수퍼클래스는 `base`, 서브클래스는 `derived`로 설정된다.
  - 이를 통해 `new` 연산자와 함께 호출되었을 때의 동작이 구분된다.
- 다른 클래스를 상속받지 않는 **베이스 클래스는 암묵적으로 빈 객체를 생성하고 `this`에 바인딩**한다. (앞서 살펴본 과정)
- 하지만 **서브클래스는 자신이 직접 인스턴스를 생성하지 않고 슈퍼클래스에게 인스턴스 생성을 위임**한다.
  - 이것이 바로 **서브클래스의 `constructor`에서 반드시 `super`를 호출해야 하는 이유**다.
  - 서브클래스가 `new` 연산자와 함께 호출되면 서브클래스는 **`super`를 호출하는 순간 슈퍼클래스의 `constructor`를 호출**한다.

##### 2. 슈퍼클래스의 인스턴스 생성과 this 바인딩

- 슈퍼클래스의 `constructor` 내부 코드가 실행되기 이전에 **암묵적으로 빈 객체를 생성**한다.
  - 이 빈 객체가 클래스가 생성한 인스턴스다.
  - 그리고 이 인스턴스가 `this`에 바인딩된다.
  - 따라서 슈퍼클래스의 `constructor` 내부의 `this`는 생성된 인스턴스를 가리킨다.
- 이때 **인스턴스는 `new.target`이 가리키는 서브클래스가 생성한 것으로 처리**된다.
  - `new.target`은 `new` 연산자와 함께 호출된 **서브클래스**를 가리킨다.
  - 따라서 생성된 인스턴스의 프로토타입은 **슈퍼클래스의 `prototype`이 아니라 서브클래스의 `prototype`**이다.
  - ```javascript
    class Rectangle {
      constructor(width, height) {
        // 암묵적으로 빈 객체(인스턴스)가 생성되고 this에 바인딩된다
        console.log(this); // ColorRectangle {}
        // new.target은 서브클래스를 가리킨다
        console.log(new.target); // ColorRectangle

        // 인스턴스는 new.target이 가리키는 서브클래스의 prototype을 상속받는다
        console.log(Object.getPrototypeOf(this) === ColorRectangle.prototype); // true
        console.log(this instanceof ColorRectangle); // true
        console.log(this instanceof Rectangle); // true
        // ...
      }
    }
    ```

##### 3. 슈퍼클래스의 인스턴스 초기화

- 슈퍼클래스의 `constructor`가 실행되어 **`this`에 바인딩되어 있는 인스턴스를 초기화**한다.
  - 즉 `this`에 바인딩되어 있는 인스턴스에 프로퍼티를 추가하고 `constructor`가 인수로 전달받은 초기값으로 프로퍼티 값을 초기화한다.

##### 4. 서브클래스 constructor로의 복귀와 this 바인딩

- `super`의 호출이 종료되고 **제어권이 서브클래스 `constructor`로 돌아온다**.
  - 이때 **`super`가 반환한 인스턴스가 `this`에 바인딩**된다.
  - 서브클래스는 별도의 인스턴스를 생성하지 않고 `super`가 반환한 인스턴스를 `this`에 바인딩하여 그대로 사용한다.
  - ```javascript
    class ColorRectangle extends Rectangle {
      constructor(width, height, color) {
        super(width, height);

        // super가 반환한 인스턴스가 this에 바인딩된다
        console.log(this); // ColorRectangle {width: 2, height: 4}
        // ...
      }
    }
    ```
- 이처럼 **`super`가 호출되지 않으면 인스턴스가 생성되지 않으며 `this` 바인딩도 할 수 없다**.
  - 따라서 **서브클래스의 `constructor`에서 `super`를 호출하기 전에는 `this`를 참조할 수 없다**.

##### 5. 서브클래스의 인스턴스 초기화

- `super` 호출 이후 서브클래스의 `constructor`에 기술되어 있는 **인스턴스 초기화가 실행**된다.
  - 즉 `this`에 바인딩되어 있는 인스턴스에 프로퍼티를 추가하고 `constructor`가 인수로 전달받은 초기값으로 인스턴스 프로퍼티를 초기화한다.

##### 6. 인스턴스 반환

- 클래스의 모든 처리가 끝나면 **완성된 인스턴스가 바인딩된 `this`가 암묵적으로 반환**된다.

    ```mermaid
    flowchart TB
        NEW["new ColorRectangle(2, 4, 'red')"]
        S1["① 서브클래스 constructor 시작<br/>super(width, height) 호출<br/>(인스턴스 생성을 슈퍼클래스에게 위임)"]
        S2["② 슈퍼클래스 constructor<br/>빈 객체 생성 → this 바인딩<br/>(프로토타입은 new.target = ColorRectangle)"]
        S3["③ 슈퍼클래스 인스턴스 초기화<br/>width, height 추가"]
        S4["④ 서브클래스 constructor로 복귀<br/>super가 반환한 인스턴스를 this에 바인딩"]
        S5["⑤ 서브클래스 인스턴스 초기화<br/>color 추가"]
        S6["⑥ this 암묵적 반환"]

        NEW ==> S1 ==> S2 ==> S3 ==> S4 ==> S5 ==> S6
    ```

#### 표준 빌트인 생성자 함수 확장

- `extends` 키워드 다음에는 **`[[Construct]]` 내부 메서드를 갖는 함수 객체로 평가될 수 있는 모든 표현식**을 사용할 수 있다.
  - `String`, `Number`, `Array` 같은 **표준 빌트인 객체도 `[[Construct]]`를 가지므로** 상속받아 확장할 수 있다. ([21장](../../week08/윤홍비/21.빌트인_객체.md))
  - ```javascript
    // Array 생성자 함수를 상속받아 확장한 MyArray
    class MyArray extends Array {
      // 중복된 배열 요소를 제거하고 반환한다
      uniq() {
        return this.filter((v, i, self) => self.indexOf(v) === i);
      }

      // 모든 배열 요소의 평균을 구한다
      average() {
        return this.reduce((pre, cur) => pre + cur, 0) / this.length;
      }
    }

    const myArray = new MyArray(1, 1, 2, 3);
    console.log(myArray); // MyArray(4) [1, 1, 2, 3]

    // MyArray.prototype.uniq 호출
    console.log(myArray.uniq()); // MyArray(3) [1, 2, 3]

    // MyArray.prototype.average 호출
    console.log(myArray.average()); // 1.75
    ```
- 주의할 점은 `Array.prototype`의 메서드 중 **새로운 배열을 반환하는 메서드(`filter`, `map` 등)는 `MyArray` 클래스의 인스턴스를 반환**한다는 것이다.
  - ```javascript
    console.log(myArray.filter((v) => v % 2) instanceof MyArray); // true
    ```
  - 그래서 **`uniq`의 반환값에서도 `uniq`나 `average`를 이어서 호출**할 수 있다.
  - ```javascript
    console.log(myArray.filter((v) => v % 2).uniq().average()); // 2
    ```
- 만약 `filter`, `map` 같은 메서드가 **`MyArray`가 아닌 `Array` 인스턴스를 반환하게 하려면** `Symbol.species`를 사용한다.
  - ```javascript
    class MyArray extends Array {
      // 모든 메서드가 Array 인스턴스를 반환하도록 한다
      static get [Symbol.species]() {
        return Array;
      }
    }
    ```

### 정리

| 개념                  | 설명                                                                         |
| --------------------- | ---------------------------------------------------------------------------- |
| 클래스                | 생성자 함수와 비슷하지만 **더 엄격하고 더 많은 기능**을 제공하는 객체 생성 메커니즘 |
| `constructor`         | 인스턴스를 **생성하고 초기화**하는 특수한 메서드 (사실은 클래스 자신)        |
| 프로토타입 메서드     | 클래스 몸체에서 정의한 메서드 (인스턴스로 호출한다)                          |
| 정적 메서드           | `static`으로 정의한 메서드 (클래스로 호출한다)                               |
| 클래스 필드           | 클래스 몸체에서 직접 정의하는 인스턴스 프로퍼티 (ES2022)                     |
| private 필드          | `#` 접두사로 정의하며 **클래스 내부에서만 참조**할 수 있다 (ES2022)          |
| `extends`             | 수퍼클래스와 서브클래스의 **상속 관계를 설정**한다 (프로토타입 체인 2개)     |
| `super`               | 호출하면 **슈퍼클래스 `constructor`**, 참조하면 **슈퍼클래스 메서드**를 가리킨다 |

- 클래스는 **프로토타입 기반 객체 생성 메커니즘** 위에 구현되어 있다.
  - 하지만 `new` 없이 호출할 수 없고, 암묵적으로 strict mode가 적용되며, 메서드가 열거되지 않는 등 **생성자 함수보다 엄격하다**.
  - 클래스 선언문도 호이스팅되지만 **TDZ**에 의해 선언 이전에 참조할 수 없다.
- 클래스의 인스턴스 생성은 **빈 객체 생성 → `this` 바인딩 → 초기화 → `this` 반환** 순서로 진행된다.
  - 서브클래스는 **직접 인스턴스를 생성하지 않고 `super`를 통해 슈퍼클래스에게 위임**한다.
  - 그래서 `super` 호출 전에는 `this`를 참조할 수 없다.
- 클래스 필드와 private 필드(`#`)는 24장에서 클로저로 구현했던 **정보 은닉을 언어 차원에서 지원**한다.
  - 인스턴스별로 독립적인 private 상태를 가지므로 **클로저 방식의 상태 공유 문제가 없다**.
- 상속은 **인스턴스 체인과 정적 체인** 두 가지 프로토타입 체인으로 구현된다.
  - `extends`는 클래스뿐 아니라 `[[Construct]]`를 갖는 모든 함수로 확장할 수 있어 **동적 상속**과 **표준 빌트인 확장**이 가능하다.
- 다음 장에서 다루는 화살표 함수는 **클래스 필드와 함께** 메서드의 `this`를 고정하는 데 자주 사용된다. (26장)
