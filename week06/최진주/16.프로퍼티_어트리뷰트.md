# 16장. 프로퍼티 어트리뷰트

- 프로퍼티는 "키: 값"만이 아니라 값 + 상태 정보(어트리뷰트) 묶음으로 관리됨
- 어트리뷰트를 조회·정의하는 방법과 객체 변경을 막는 방법이 핵심

---

## 내부 슬롯과 내부 메서드

- `[[ ]]` 이중 대괄호로 표기하는 엔진 내부 구현용 의사 프로퍼티·메서드
- ECMAScript 스펙 설명용, 개발자가 직접 접근 불가
- 일부는 간접 접근 가능
  - `[[Prototype]]` → `__proto__`, `Object.getPrototypeOf()`로 확인

```js
const obj = {};
obj.[[Prototype]];          // SyntaxError
Object.getPrototypeOf(obj); // Object.prototype
```

---

## 프로퍼티 어트리뷰트

- 프로퍼티 생성 시 엔진이 어트리뷰트를 기본값으로 자동 정의
- 어트리뷰트도 내부 슬롯이므로 직접 접근 불가, 디스크립터 객체로 간접 확인

| 어트리뷰트 | 의미 |
|---|---|
| `[[Value]]` | 프로퍼티 값 |
| `[[Writable]]` | 값 변경 가능 여부 |
| `[[Enumerable]]` | `for...in`, `Object.keys` 열거 대상 여부 |
| `[[Configurable]]` | 삭제, 어트리뷰트 재정의 가능 여부 |

```js
const product = { name: '키보드', price: 10000 };

Object.getOwnPropertyDescriptor(product, 'price');
// { value: 10000, writable: true, enumerable: true, configurable: true }

Object.getOwnPropertyDescriptors(product); // 모든 프로퍼티의 디스크립터 반환 (ES8)
```

## 데이터 프로퍼티와 접근자 프로퍼티

| 구분 | 데이터 프로퍼티 | 접근자 프로퍼티 |
|---|---|---|
| 역할 | 값을 직접 저장 | 값 없음, 읽기·쓰기 시 함수 호출 |
| 어트리뷰트 | value, writable, enumerable, configurable | get, set, enumerable, configurable |
| 구분 기준 | 디스크립터에 `value` 존재 | 디스크립터에 `get`/`set` 존재 |

- getter: 프로퍼티를 읽을 때 호출, 다른 값에서 계산되는 값 표현에 적합
- setter: 프로퍼티에 값을 할당할 때 호출, 값 검증에 활용

```js
const payment = {
  _amount: 0,
  get amount() {
    return this._amount;
  },
  set amount(value) {
    if (value < 0) throw new RangeError('결제 금액은 0 이상');
    this._amount = value;
  },
};

payment.amount = 5000; // setter 호출
payment.amount;        // 5000 (getter 호출)
payment.amount = -1;   // RangeError
```

## Object.defineProperty

- 어트리뷰트를 명시적으로 지정해 프로퍼티 정의·재정의
- 여러 개 정의 시 `Object.defineProperties` 사용
- 생략한 어트리뷰트 기본값 주의

| 생성 방식 | writable / enumerable / configurable 기본값 |
|---|---|
| 객체 리터럴, 할당 | `true` |
| `defineProperty`에서 생략 | `false` (value는 `undefined`) |

```js
const order = {};
Object.defineProperty(order, 'id', { value: 'A1' });

Object.keys(order); // []   (enumerable: false)
order.id = 'B2';    // 무시됨, strict mode에서는 TypeError
order.id;           // 'A1' (writable: false)
delete order.id;    // false (configurable: false)
```

- `configurable: false`가 되면 삭제와 어트리뷰트 재정의 불가, 되돌릴 수 없음

## 객체 변경 방지

| 메서드 | 추가 | 삭제 | 값 읽기 | 값 쓰기 | 어트리뷰트 재정의 | 확인 메서드 |
|---|---|---|---|---|---|---|
| `Object.preventExtensions` | X | O | O | O | O | `Object.isExtensible` |
| `Object.seal` | X | X | O | O | X | `Object.isSealed` |
| `Object.freeze` | X | X | O | X | X | `Object.isFrozen` |

- 금지된 동작은 non-strict mode에서 무시, strict mode에서 에러
- 아래로 갈수록 제한 범위가 넓어짐

### 얕은 동결

- 세 메서드 모두 직속 프로퍼티만 제한, 중첩 객체는 영향 없음

```js
const config = Object.freeze({ fee: { rate: 0.03 } });

config.fee = null;
config.fee;      // { rate: 0.03 } (변경 안 됨)

config.fee.rate = 0.05;
config.fee.rate; // 0.05 (중첩 객체는 변경됨)
```

### 깊은 동결

- 중첩 객체까지 재귀적으로 freeze 필요

```js
function deepFreeze(target) {
  if (target && typeof target === 'object' && !Object.isFrozen(target)) {
    Object.freeze(target);
    Object.values(target).forEach(deepFreeze);
  }
  return target;
}

const config = deepFreeze({ fee: { rate: 0.03 } });
config.fee.rate = 0.05;
config.fee.rate; // 0.03
```

## const와 Object.freeze 비교

| 구분 | `const` | `Object.freeze` |
|---|---|---|
| 막는 대상 | 변수 재할당 | 객체 프로퍼티 추가·삭제·수정 |
| 객체 내부 변경 | 가능 | 불가 (1단계만) |

```js
const user = { name: 'A' };
user.name = 'B'; // 가능
user = {};       // TypeError
```
