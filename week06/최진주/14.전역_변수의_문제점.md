# 14장. 전역 변수의 문제점

- 변수의 생명 주기는 스코프의 생명 주기와 연결됨
- 전역 변수는 범위가 가장 넓고 수명이 가장 길어 여러 문제의 원인이 됨
- 전역 변수를 줄이는 방법은 IIFE(이피) → 네임스페이스 객체 → 모듈 패턴 → ES6 모듈 순으로 발전

---

## 변수의 생명 주기

| 구분 | 생성 시점 | 소멸 시점 |
|---|---|---|
| 지역 변수 | 함수 호출 시 | 스코프를 참조하는 곳이 없어질 때 |
| var 전역 변수 | 전역 코드 실행 시 | 전역 객체가 사라질 때 (브라우저 탭 종료) |

- 지역 변수는 보통 함수 종료와 함께 소멸
- 단, 스코프를 참조하는 함수(클로저)가 남아 있으면 계속 유지, 참조가 사라지면 가비지 컬렉터가 회수
- var로 선언한 전역 변수는 전역 객체(window)의 프로퍼티가 됨

### 호이스팅은 스코프 단위로 동작

```js
var x = 'global';

function foo() {
  console.log(x); // undefined
  var x = 'local';
}
foo();
```

- 함수 내부의 var x가 함수 스코프 선두로 호이스팅됨
- var는 선언과 동시에 undefined로 초기화, 할당은 해당 줄 실행 시점에 일어남
- 따라서 전역 x가 아닌 아직 할당 전인 지역 x를 참조

---

## 전역 변수의 문제점

| 문제 | 내용 |
|---|---|
| 암묵적 결합 | 모든 코드가 참조·변경 가능, 변경 지점 추적 어려움 |
| 긴 생명 주기 | 메모리를 오래 점유, 의도치 않은 변경 가능성 증가 |
| 스코프 체인의 종점 | 식별자 검색 시 가장 마지막에 탐색되어 상대적으로 느림 (실무 영향 작음) |
| 네임스페이스 오염 | 파일이 분리되어도 전역 스코프는 하나, 이름 충돌 발생 |

```js
// cart.js
var total = 0;
// coupon.js
var total = 5000;

console.log(total); // 5000
```

- var는 중복 선언을 허용하므로 에러 없이 값이 덮어써짐
- CSS 전역 클래스명 충돌과 같은 구조의 문제, BEM · CSS Modules와 같은 문제의식
  - BEM: 유지보수가 쉽고 명확한 CSS 클래스 이름을 짓기 위한 방법론 (block__element--modifier)

## 프로퍼티 접근과 식별자 검색

| 구분 | 예시 | 찾는 방식 | 못 찾을 때 |
|---|---|---|---|
| 프로퍼티 접근 | `window.a` | 객체에서 키 탐색 | `undefined` |
| 식별자 검색 | `a` | 스코프 체인을 따라 선언 탐색 | `ReferenceError` |

```html
<script type="module">
  var a = 1; // 모듈 스코프에만 존재, window 프로퍼티 아님
</script>

<script>
  console.log(window.a); // undefined
  console.log(a);        // ReferenceError: a is not defined
</script>
```

- a는 모듈 스코프에 존재하지만 일반 스크립트의 스코프 체인에서는 닿을 수 없음
- 같은 이름이라도 `window.a`인지 `a`인지에 따라 결과가 달라짐

## 전역 변수를 줄이는 방법

### 즉시 실행 함수 (IIFE)

```js
(function () {
  var total = 0;
})();

console.log(typeof total); // 'undefined'
```

- 함수로 감싸 변수를 지역 스코프에 가둠

### 네임스페이스 객체

```js
var MYAPP = {};
MYAPP.cart = { total: 0 };

MYAPP.cart.total = -100;
console.log(MYAPP.cart.total); // -100
```

- 전역 식별자를 객체 하나로 줄여 이름 충돌 감소
- 객체 자체는 여전히 전역, 내부 프로퍼티는 모두 공개라 외부에서 수정 가능

### 모듈 패턴

```js
var Cart = (function () {
  var total = 0; // 클로저로 은닉

  return {
    add(price) { total += price; },
    getTotal() { return total; },
  };
})();

Cart.add(3000);
Cart.total = 500;              // 반환 객체에 새 프로퍼티만 추가됨
console.log(Cart.getTotal());  // 3000
```

- IIFE + 클로저로 private 변수 구현, 공개할 메서드만 반환
- 정보 은닉과 캡슐화 가능
- 반환 객체를 var로 받으면 그 식별자 하나는 전역에 남음

### ES6 모듈

```js
// cart.js
let total = 0; // export하지 않음 → 외부 접근 불가

export function add(price) { total += price; }
export function getTotal() { return total; }
```

```js
// main.js
import { add, getTotal } from './cart.js';

add(3000);
console.log(getTotal()); // 3000
```

- 파일 자체가 독립된 모듈 스코프
- 모듈 최상위의 var도 window 프로퍼티가 되지 않음
- 기본적으로 모든 값이 비공개, export한 것만 다른 모듈에서 import 가능
- 브라우저에서는 `<script type="module">`로 사용, 현재 React 프로젝트의 import/export가 이 방식

### 모듈 패턴과 ES6 모듈 비교

| 구분 | 모듈 패턴 | ES6 모듈 |
|---|---|---|
| 스코프 생성 | 함수(IIFE)로 감싸서 생성 | 파일 자체가 스코프 |
| 공개 방법 | 객체로 return | export |
| 비공개 방법 | 클로저 내부 변수 | export하지 않은 값 |
| 전역 흔적 | 반환 객체를 받은 식별자 남음 | 없음 |
| 사용 방법 | 문법 없이 패턴으로 구현 | import / export 문법 |
