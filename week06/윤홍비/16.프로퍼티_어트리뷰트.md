### 내부 슬롯과 내부 메서드

- 자바스크립트 엔진의 구현 알고리즘을 설명하기 위해 ECMAScript 사양에서 사용하는 의사(pseudo-) 프로퍼티와 의사 메서드다.
  - 이중 대괄호`[[...]]`로 감싼 이름들이 내부 슬롯과 내부 메서드다.
- 자바스크립트 엔진의 내부 로직이므로 원칙적으로 직접 접근하거나 호출할 수 없다.
  - 단 일부 내부 슬롯과 내부 메서드에 한하여 간접적으로 접근할 수 있는 수단을 제공한다.
  - ```javascript
    const o = {};

    o.[[Prototype]]; // SyntaxError (직접 접근 불가)
    o.__proto__; // Object.prototype (간접 접근 가능)
    ```

### 프로퍼티 어트리뷰트와 프로퍼티 디스크립터 객체

- 자바스크립트 엔진은 프로퍼티를 생성할 때 프로퍼티의 상태를 나타내는 프로퍼티 어트리뷰트를 기본값으로 자동 정의한다.
  - 프로퍼티의 상태란 값, 값의 갱신 가능 여부, 열거 가능 여부, 재정의 가능 여부를 말한다.
- 프로퍼티 어트리뷰트는 내부 슬롯 `[[Value]]`, `[[Writable]]`, `[[Enumerable]]`, `[[Configurable]]`이다.
  - 직접 접근할 수 없지만 Object.getOwnPropertyDescriptor 메서드로 간접 확인할 수 있다.
  - ```javascript
    const person = { name: "Lee" };

    Object.getOwnPropertyDescriptor(person, "name");
    // { value: 'Lee', writable: true, enumerable: true, configurable: true }
    ```

- 존재하지 않는 프로퍼티나 상속받은 프로퍼티에 대한 디스크립터(프로퍼티 어트리뷰트를 담아 보여주는 일반 객체)를 요구하면 undefined가 반환된다.
- ES8에서 도입된 Object.getOwnPropertyDescriptors는 모든 프로퍼티의 디스크립터를 반환한다.

### 데이터 프로퍼티와 접근자 프로퍼티

- 프로퍼티는 데이터 프로퍼티와 접근자 프로퍼티로 구분할 수 있다.
  - 데이터 프로퍼티 : 키와 값으로 구성된 일반적인 프로퍼티
  - 접근자 프로퍼티 : 자체적으로는 값을 갖지 않고 다른 데이터 프로퍼티의 값을 읽거나 저장할 때 호출되는 접근자 함수로 구성된 프로퍼티(ex: get, set)

#### 데이터 프로퍼티

| 어트리뷰트         | 디스크립터 프로퍼티 | 설명                                                            |
| ------------------ | ------------------- | --------------------------------------------------------------- |
| `[[Value]]`        | value               | 프로퍼티 키로 프로퍼티 값에 접근하면 반환되는 값                |
| `[[Writable]]`     | writable            | 값의 변경 가능 여부. false면 읽기 전용이 된다                   |
| `[[Enumerable]]`   | enumerable          | 열거 가능 여부. false면 for...in, Object.keys에 열거되지 않는다 |
| `[[Configurable]]` | configurable        | 재정의 가능 여부. false면 삭제와 어트리뷰트 변경이 금지된다     |

- 프로퍼티가 생성될 때 `[[Value]]`는 값으로 초기화되고 나머지는 모두 true로 초기화된다.
  - 프로퍼티를 동적으로 추가해도 마찬가지다.

#### 접근자 프로퍼티

| 어트리뷰트         | 디스크립터 프로퍼티 | 설명                                |
| ------------------ | ------------------- | ----------------------------------- |
| `[[Get]]`          | get                 | 값을 읽을 때 호출되는 접근자 함수   |
| `[[Set]]`          | set                 | 값을 저장할 때 호출되는 접근자 함수 |
| `[[Enumerable]]`   | enumerable          | 데이터 프로퍼티와 같다              |
| `[[Configurable]]` | configurable        | 데이터 프로퍼티와 같다              |

- 접근자 함수는 getter/setter 함수라고도 부른다.
  - 둘 중 하나만 정의할 수도 있다.
  - ```javascript
    const person = {
      firstName: "Ung-mo", // 데이터 프로퍼티
      lastName: "Lee", // 데이터 프로퍼티

      // fullName은 접근자 프로퍼티
      get fullName() {
        return `${this.firstName} ${this.lastName}`;
      },
      set fullName(name) {
        [this.firstName, this.lastName] = name.split(" ");
      },
    };

    person.fullName = "Heegun Lee"; // setter 호출
    console.log(person.fullName); // 'Heegun Lee' (getter 호출)

    Object.getOwnPropertyDescriptor(person, "fullName");
    // { get: f, set: f, enumerable: true, configurable: true }
    ```

- 접근자 함수는 함수인데도 호출할 때 괄호를 붙이지 않는다.
  - get, set 키워드로 정의하면 함수 호출을 엔진이 대신 수행하기 때문이다.
    - 프로퍼티를 읽으면 `[[Get]]`이, 값을 할당하면 `[[Set]]`이 내부적으로 호출된다.
  - 따라서 겉보기에는 데이터 프로퍼티와 완전히 똑같이 동작한다.
  - ```javascript
    person.fullName; // getter 실행 결과인 'Heegun Lee'
    person.fullName(); // TypeError (문자열을 호출한 셈이 된다)
    ```
  - 즉 괄호를 붙이면 getter의 반환값을 호출하는 것이 되므로 에러가 발생한다.
- 사용하는 쪽에서는 데이터 프로퍼티인지 접근자 프로퍼티인지 구분할 필요가 없다.
  - 따라서 나중에 데이터 프로퍼티를 접근자 프로퍼티로 바꿔도 사용하는 코드를 고치지 않아도 된다.

- 접근자 프로퍼티는 자체적으로 값을 갖지 않으며 데이터 프로퍼티의 값을 읽거나 저장할 때 관여한다.
  - 따라서 디스크립터에 value와 writable이 없다.
- 접근자 프로퍼티는 내부 슬롯 `[[Get]]`, `[[Set]]`을 호출해 값을 반환하거나 저장한다.
  - 프로토타입도 접근자 프로퍼티일 수 있다.
  - `__proto__`는 Object.prototype의 접근자 프로퍼티다. ([18장](../../week05/윤홍비/18.함수와_일급_객체.md#__proto__-접근자-프로퍼티))

- 접근자 프로퍼티는 **읽을 때마다 getter 함수가 실행된다**는 점을 유의해야 한다.
  - 겉보기가 프로퍼티이므로 호출 비용이 드러나지 않아 무거운 연산을 넣기 쉽다.
  - ```javascript
    const data = {
      items: [3, 1, 2],

      get sorted() {
        return this.items.sort((a, b) => a - b); // 읽을 때마다 정렬한다
      },
    };

    for (let i = 0; i < 1000; i++) {
      data.sorted[0]; // 정렬이 1000번 수행된다
    }
    ```
  - 위 예제의 sort는 원본 배열을 직접 변경하므로 읽기만 해도 상태가 바뀌는 문제도 있다.
- 따라서 getter는 **비용이 적고 부작용이 없어야 한다**.
  - 비싼 연산은 메서드로 정의해 호출 비용이 드러나게 하는 것이 좋다.

### 프로퍼티 정의

- 새로운 프로퍼티를 추가하면서 어트리뷰트를 명시적으로 정의하거나,
  - 기존 프로퍼티의 어트리뷰트를 재정의하는 것을 말한다.
- Object.defineProperty 메서드를 사용한다.
  - ```javascript
    const person = {};

    Object.defineProperty(person, "firstName", {
      value: "Ungmo",
      writable: true,
      enumerable: true,
      configurable: true,
    });
    ```

- 디스크립터 객체에서 생략한 어트리뷰트는 기본값이 적용된다.
  - value, get, set : undefined
  - writable, enumerable, configurable : **false**
  - ```javascript
    const obj = {};
    Object.defineProperty(obj, "a", { value: 1 });

    Object.getOwnPropertyDescriptor(obj, "a");
    // { value: 1, writable: false, enumerable: false, configurable: false }
    ```

  - 즉 객체 리터럴로 생성할 때와 달리 생략하면 제한적인 프로퍼티가 된다.

- 어트리뷰트에 따른 동작
  - writable이 false면 값을 변경할 수 없다. 이때 에러 없이 무시된다.(strict mode에서는 에러)
  - enumerable이 false면 for...in, Object.keys 등으로 열거할 수 없다.
  - configurable이 false면 delete로 삭제할 수 없고 재정의도 할 수 없다.
- Object.defineProperties를 사용하면 여러 개의 프로퍼티를 한번에 정의할 수 있다.

### 객체 변경 방지

- 객체는 변경 가능한 값이므로 재할당 없이 직접 변경할 수 있다.
  - 자바스크립트는 객체의 변경을 방지하는 다양한 메서드를 제공하며 금지 강도가 다르다.

#### const와 Object.freeze는 다른 층위다

- const는 **변수 바인딩**에 걸리고 Object.freeze는 **객체 자체**에 걸린다.
  - 따라서 둘은 서로를 대체할 수 없고 막는 대상이 정반대다.

| 구분            | 막는 것       | 막지 못하는 것 |
| --------------- | ------------- | -------------- |
| `const`         | 변수 재할당   | 객체 내용 변경 |
| `Object.freeze` | 객체 내용 변경 | 변수 재할당    |

- ```javascript
  const obj = { a: 1 };
  obj.a = 2; // 가능하다 (const는 재할당만 금지한다)
  obj = {}; // TypeError

  const frozen = Object.freeze({ a: 1 });
  frozen.a = 2; // 무시된다 (freeze는 값 변경을 금지한다)

  let f = frozen;
  f = {}; // 가능하다 (freeze는 재할당을 막지 못한다)
  ```

- 즉 완전히 변경을 막으려면 const로 선언한 변수에 동결한 객체를 할당해야 한다. ([15장](./15.let,const키워드와_블록레벨스코프.md#const-키워드와-객체))

| 구분           | 메서드                     | 프로퍼티 추가 | 삭제 | 값 읽기 | 값 쓰기 | 어트리뷰트 재정의 |
| -------------- | -------------------------- | ------------- | ---- | ------- | ------- | ----------------- |
| 객체 확장 금지 | `Object.preventExtensions` | ❌            | ⭕   | ⭕      | ⭕      | ⭕                |
| 객체 밀봉      | `Object.seal`              | ❌            | ❌   | ⭕      | ⭕      | ❌                |
| 객체 동결      | `Object.freeze`            | ❌            | ❌   | ⭕      | ❌      | ❌                |

#### 객체 확장 금지

- Object.preventExtensions는 프로퍼티 추가를 금지한다.
  - 프로퍼티 동적 추가와 Object.defineProperty 모두 금지된다.
  - 확장 가능 여부는 Object.isExtensible로 확인한다.

#### 객체 밀봉

- Object.seal은 읽기와 쓰기만 가능하게 한다.
  - 즉 추가, 삭제, 어트리뷰트 재정의가 금지된다.
  - 밀봉 여부는 Object.isSealed로 확인한다.
- 밀봉된 객체는 configurable이 false가 된다.

#### 객체 동결

- Object.freeze는 읽기만 가능하게 한다.
  - 즉 추가, 삭제, 값 쓰기, 어트리뷰트 재정의가 모두 금지된다.
  - 동결 여부는 Object.isFrozen으로 확인한다.
- 동결된 객체는 writable과 configurable이 모두 false가 된다.

#### 불변 객체

- 위 변경 방지 메서드들은 **얕은 변경 방지**로 직속 프로퍼티만 변경이 방지된다.
  - 따라서 중첩 객체까지는 영향을 주지 못한다.
  - ```javascript
    const person = { name: "Lee", address: { city: "Seoul" } };

    Object.freeze(person);

    Object.isFrozen(person); // true
    Object.isFrozen(person.address); // false (중첩 객체는 동결되지 않는다)

    person.address.city = "Busan"; // 변경된다
    ```

- 중첩 객체까지 동결하여 완전한 불변 객체를 구현하려면
  - 모든 프로퍼티에 대해 재귀적으로 Object.freeze를 호출해야 한다.
  - ```javascript
    function deepFreeze(target) {
      if (target && typeof target === "object" && !Object.isFrozen(target)) {
        Object.freeze(target);
        Object.keys(target).forEach((key) => deepFreeze(target[key]));
      }
      return target;
    }
    ```
