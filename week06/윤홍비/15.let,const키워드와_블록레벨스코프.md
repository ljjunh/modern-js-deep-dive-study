### var 키워드로 선언한 변수의 문제점

#### 변수 중복 선언 허용

- var 키워드로 선언한 변수는 중복 선언이 가능하다.
  - 초기화문이 있는 변수 선언문은 자바스크립트 엔진에 의해 var 키워드가 없는 것처럼 동작한다.
  - 초기화문이 없는 변수 선언문은 무시된다.
  - ```javascript
    var x = 1;
    var y = 1;

    var x = 100; // 초기화문이 있으면 재할당된 것처럼 동작한다.
    var y; // 초기화문이 없으면 무시된다.

    console.log(x); // 100
    console.log(y); // 1
    ```
- 의도치 않게 먼저 선언된 변수 값이 변경되는 부작용이 발생한다.

#### 함수 레벨 스코프

- var 키워드로 선언한 변수는 오로지 함수의 코드 블록만을 지역 스코프로 인정한다.
  - 따라서 함수 외부에서 var 키워드로 선언한 변수는 코드 블록 내에서 선언해도 모두 전역 변수가 된다.
  - ```javascript
    var i = 10;

    for (var i = 0; i < 5; i++) {
      console.log(i); // 0 1 2 3 4
    }

    console.log(i); // 5 (의도치 않게 전역 변수가 변경되었다)
    ```
  - 반면 함수로 감싸면 함수는 스코프를 만들므로 전역 변수가 변경되지 않는다.
    - ```javascript
      var i = 10;

      function foo() {
        for (var i = 0; i < 5; i++) {}
        console.log(i); // 5 (블록은 벗어나도 함수 안에서는 유효하다)
      }

      foo();

      console.log(i); // 10 (함수를 벗어나지 못하므로 전역은 그대로다)
      ```
    - 즉 var는 블록은 벗어나지만 함수는 벗어나지 못한다.
- 함수 레벨 스코프는 전역 변수를 남발할 가능성을 높인다.

#### 변수 호이스팅

- var 키워드로 선언한 변수는 변수 호이스팅에 의해 변수 선언문 이전에 참조할 수 있다.
  - 단 할당문 이전에 참조하면 undefined를 반환한다.
  - ```javascript
    console.log(foo); // undefined

    var foo;
    foo = 123;

    console.log(foo); // 123
    ```
- 에러를 발생시키지는 않지만 프로그램의 흐름상 맞지 않으며 가독성을 떨어뜨리고 오류를 발생시킬 여지를 남긴다.

### let 키워드

#### 변수 중복 선언 금지

- 같은 스코프 내에서 중복 선언하면 문법 에러가 발생한다.
  - ```javascript
    let bar = 123;
    let bar = 456; // SyntaxError: Identifier 'bar' has already been declared
    ```

#### 블록 레벨 스코프

- let 키워드로 선언한 변수는 모든 코드 블록(함수, if, for, while, try/catch 등)을 지역 스코프로 인정한다.
  - ```javascript
    let foo = 1;

    {
      let foo = 2;
      let bar = 3;
    }

    console.log(foo); // 1
    console.log(bar); // ReferenceError
    ```
- 함수도 코드 블록이므로 스코프를 만든다.
  - 이때 함수 내의 코드 블록은 함수 레벨 스코프에 중첩된다.
- for 문에서 let을 사용하면 **반복마다 새로운 스코프가 생성**된다.
  - 즉 반복마다 별도의 렉시컬 환경이 만들어지고 변수 값이 복사된다.
  - 따라서 비동기 콜백이 각각 다른 값을 기억한다.
  - ```javascript
    // var는 반복문 전체에서 변수가 하나뿐이다.
    for (var i = 0; i < 3; i++) {
      setTimeout(() => console.log(i), 0);
    }
    // 3 3 3 (콜백 실행 시점에는 이미 i가 3이다)

    // let은 반복마다 새로운 바인딩이 생성된다.
    for (let j = 0; j < 3; j++) {
      setTimeout(() => console.log(j), 0);
    }
    // 0 1 2
    ```
  - var를 사용하면 콜백이 모두 같은 변수를 참조하므로 반복이 끝난 뒤의 값만 출력된다.
- 즉 블록 레벨 스코프는 전역 오염 방지뿐 아니라 비동기 코드의 정확성과도 직결된다.
  - 이벤트 핸들러 등록이나 setTimeout을 반복문에서 사용할 때 자주 마주치는 문제다.

#### 변수 호이스팅

- let 키워드로 선언한 변수는 변수 호이스팅이 발생하지 않는 것처럼 동작한다.
  - 선언문 이전에 참조하면 ReferenceError가 발생한다.
  - ```javascript
    console.log(foo); // ReferenceError
    let foo;
    ```
- var 키워드로 선언한 변수는 선언 단계와 초기화 단계가 한번에 진행된다.
  - 즉 선언 단계에서 스코프에 등록되고 동시에 undefined로 초기화된다.
  - 따라서 선언문 이전에 참조해도 undefined를 반환한다.
- 하지만 let 키워드로 선언한 변수는 **선언 단계와 초기화 단계가 분리되어 진행**된다.
  - 선언 단계는 런타임 이전에 실행되지만 초기화 단계는 선언문에 도달했을 때 실행된다.
  - 초기화 단계 실행 이전에 접근하려 하면 ReferenceError가 발생한다.
- 스코프의 시작 지점부터 초기화 시작 지점까지 변수를 참조할 수 없는 구간을
  - 일시적 사각지대(TDZ, Temporal Dead Zone)라 한다.
  - ```javascript
    // 런타임 이전에 선언 단계가 실행된다. 아직 변수는 초기화되지 않았다.
    // 이 구간이 TDZ다.
    console.log(foo); // ReferenceError

    let foo = 1; // 변수 초기화
    console.log(foo); // 1
    ```
- let 키워드로 선언한 변수는 호이스팅이 발생하지 않는 것처럼 보이지만 실제로는 호이스팅이 발생한다.
  - ```javascript
    let foo = 1; // 전역 변수

    {
      console.log(foo); // ReferenceError
      let foo = 2; // 지역 변수
    }
    ```
  - 호이스팅이 발생하지 않는다면 전역 변수 foo의 값인 1이 출력되어야 한다.
  - 하지만 호이스팅이 발생하여 지역 변수 foo를 참조했기에 에러가 발생한다.
- 그렇다면 선언 단계에서 메모리에는 무엇이 들어갈까?
  - 선언 단계에서는 실행 컨텍스트의 렉시컬 환경(선언적 환경 레코드)에 **식별자(이름)만 등록**된다.
  - 즉 변수를 위한 슬롯(공간)은 이미 만들어져 있지만, 그 안에 값 대신 "아직 초기화되지 않음" 상태가 표시되어 있다.
    - 명세에서는 이를 empty로 표현하고, V8 엔진은 the_hole이라는 특수한 내부 값을 그 슬롯에 넣어둔다.
  - ```
    [선언적 환경 레코드]
      foo(var) → undefined          // 읽기 가능
      bar(let) → <uninitialized>    // 읽으면 ReferenceError
    ```
  - 따라서 TDZ에서 참조하면 "그런 이름이 없다"가 아니라 "이름은 찾았는데 슬롯이 비어 있다"는 이유로 ReferenceError가 발생한다.
  - 정리하면 다음과 같다.
    - var 호이스팅: 선언 + undefined 초기화가 함께 끌어올려짐 → 메모리에 undefined가 들어감
    - let 호이스팅: 선언(이름 등록)만 끌어올려짐, 초기화는 실제 코드 위치에서 → 메모리 슬롯은 있지만 \<uninitialized\> 상태
    - 즉 let, const는 호이스팅이 "안 되는" 것이 아니라 선언 단계와 초기화 단계가 분리되어 그 사이에 TDZ 구간이 생기는 것이다.

#### 전역 객체와 let

- let 키워드로 선언한 전역 변수는 전역 객체의 프로퍼티가 아니다.
  - 즉 window.foo와 같이 접근할 수 없다.
  - ```javascript
    var x = 1;
    let y = 2;

    console.log(window.x); // 1
    console.log(window.y); // undefined
    ```
- let 전역 변수는 보이지 않는 개념적인 블록(전역 렉시컬 환경의 선언적 환경 레코드) 내에 존재한다.
- 단 저장소가 분리되어 있을 뿐 **같은 전역 스코프이므로 var와 이름이 충돌한다**.
  - 선언 순서를 바꿔도 마찬가지로 문법 에러가 발생한다.
  - ```javascript
    var x = 1;
    let x = 2; // SyntaxError: Identifier 'x' has already been declared

    let y = 1;
    var y = 2; // SyntaxError
    ```
  - 즉 저장소가 둘로 나뉜 것이 완전히 독립적이라는 뜻은 아니다.
  - 여러 스크립트를 병합하거나 번들링할 때 마주칠 수 있는 문제다.

### const 키워드

- const 키워드는 상수를 선언하기 위해 사용한다.
  - 하지만 반드시 상수만을 위해 사용하지는 않는다.
- const 키워드의 특징은 let 키워드와 대부분 동일하다.

#### 선언과 초기화

- const 키워드로 선언한 변수는 **반드시 선언과 동시에 초기화**해야 한다.
  - ```javascript
    const foo = 1;
    const bar; // SyntaxError: Missing initializer in const declaration
    ```
- let 키워드와 마찬가지로 블록 레벨 스코프를 가지며 호이스팅이 발생하지 않는 것처럼 동작한다.

#### 재할당 금지

- const 키워드로 선언한 변수는 재할당이 금지된다.
  - ```javascript
    const foo = 1;
    foo = 2; // TypeError: Assignment to constant variable.
    ```

#### 반복문과 const

- 일반 for 문에는 const를 사용할 수 없지만 for...of와 for...in에는 사용할 수 있다.
  - ```javascript
    for (const i = 0; i < 3; i++) {} // TypeError: Assignment to constant variable.
    for (let i = 0; i < 3; i++) {} // 가능하다.

    for (const x of [1, 2, 3]) {
      console.log(x); // 1 2 3 (가능하다)
    }
    ```
- 같은 const인데 결과가 다른 이유는 변수를 다루는 방식이 다르기 때문이다.
  - 일반 for 문은 `i++`로 **같은 변수를 재할당**하므로 const를 사용할 수 없다.
  - for...of는 반복마다 **새로운 변수를 선언**하므로 재할당이 아니다.
- 따라서 for...of와 for...in에는 const를 기본으로 사용하는 것이 좋다.
  - 반복 변수를 재할당할 일이 없기 때문이다.

#### 상수

- 상수는 재할당이 금지된 변수를 말한다.
  - const 키워드로 선언한 변수에 원시 값을 할당한 경우 변수 값을 변경할 수 없다.
  - 원시 값은 변경 불가능한 값이고 const 키워드에 의해 재할당이 금지되기 때문이다.
- 상수는 상태 유지와 가독성, 유지보수의 편의를 위해 적극적으로 사용해야 한다.
  - 일반적으로 상수의 이름은 대문자로 선언해 상수임을 명확히 나타낸다.
  - 여러 단어로 이뤄진 경우 스네이크 케이스로 표현한다.
  - ```javascript
    const TAX_RATE = 0.1;
    ```

#### const 키워드와 객체

- const 키워드로 선언된 변수에 객체를 할당한 경우 값을 변경할 수 있다.
  - 객체는 변경 가능한 값이므로 재할당 없이도 직접 변경이 가능하다.
  - ```javascript
    const person = { name: "Lee" };

    person.name = "Kim"; // 가능하다.
    console.log(person); // { name: 'Kim' }
    ```
- const 키워드는 **재할당을 금지할 뿐 불변을 의미하지는 않는다**.
  - 새로운 값을 재할당하는 것은 불가능하지만 프로퍼티 동적 생성, 삭제, 값 변경은 가능하다.
  - 이때 객체가 변경되더라도 변수에 할당된 참조 값은 변경되지 않는다.
  - 불변 객체로 만들려면 Object.freeze를 사용해야 한다. (12장)

### var vs let vs const

|                  | var                 | let                 | const               |
| ---------------- | ------------------- | ------------------- | ------------------- |
| 중복 선언        | 허용                | 금지                | 금지                |
| 스코프           | 함수 레벨           | 블록 레벨           | 블록 레벨           |
| 선언 전 참조     | undefined           | ReferenceError(TDZ) | ReferenceError(TDZ) |
| 재할당           | 가능                | 가능                | 불가능              |
| 선언 시 초기화   | 생략 가능           | 생략 가능           | **필수**            |
| 전역 객체 프로퍼티 | 된다              | 안 된다             | 안 된다             |

- ES6를 사용한다면 var 키워드는 사용하지 않는다.
- 재할당이 필요한 경우에 한정해 let 키워드를 사용한다.
  - 이때 변수의 스코프는 최대한 좁게 만든다.
- 변경이 발생하지 않고 읽기 전용으로 사용하는 원시 값과 객체에는 const 키워드를 사용한다.
  - const 키워드는 재할당을 금지하므로 var, let보다 안전하다.
- 즉 일단 const로 선언하고, 재할당이 필요하면 그때 let으로 변경하는 것이 좋다.
