# 8장. 제어문

## 1. 제어문이란

- 위에서 아래로 순차 실행되는 코드 흐름을 인위적으로 바꾸는 문법
- 조건에 따라 실행 여부 결정(조건문), 반복 실행(반복문), 중간 탈출(break, continue)
- 흐름을 머릿속으로 따라가야 해서 가독성 저하 원인이 되기 쉬움

| 분류 | 문법 |
|---|---|
| 블록문 | `{ }` |
| 조건문 | `if...else`, `switch` |
| 반복문 | `for`, `while`, `do...while` |
| 흐름 탈출 | `break`, `continue` |

---

## 2. 블록문

- 여러 문을 중괄호로 묶은 단위, 엔진은 하나의 문으로 취급
- 끝에 세미콜론 붙이지 않음
- `let`, `const`는 블록 단위로 스코프 생성

---

## 3. 조건문

### if...else

- 조건식을 불리언으로 평가해 실행할 블록 결정
- 불리언이 아닌 값은 암묵적으로 불리언 변환 (truthy / falsy)
- 값을 결정하는 단순 분기는 삼항 연산자로 대체 가능
    - 삼항 연산자는 표현식이라 변수에 바로 할당 가능, if는 문이라 불가

```js
// if문
let label;
if (isPaid) label = '결제완료';
else label = '결제대기';

// 삼항 연산자
const label = isPaid ? '결제완료' : '결제대기';
```

### switch

- 표현식을 한 번 평가한 뒤 일치하는 case로 이동
- 비교 방식은 일치 비교(`===`), 타입 변환 없음
- break 없으면 다음 case까지 계속 실행 (폴스루)
- 일치하는 case 없으면 default 실행

```js
// 흔한 실수 1: break 누락
switch (method) {
  case 'card':
    console.log('카드 결제');
  case 'point':
    console.log('포인트 결제'); // card일 때도 실행됨
}

// 흔한 실수 2: 타입 불일치
const step = '2'; // input.value, URL 파라미터는 항상 문자열
switch (step) {
  case 2: console.log('2단계'); break; // 실행 안 됨, '2' !== 2
}
// 개선: switch (Number(step))
```

| | if...else | switch |
|---|---|---|
| 적합한 상황 | 범위 비교, 복합 조건 | 하나의 값을 여러 상수와 비교 |
| 비교 방식 | 조건식 자유 | `===` 고정 |
| 주의점 | 중첩 시 가독성 저하 | break 누락 시 폴스루 |

## 4. 반복문

| 문법 | 조건 검사 시점 | 최소 실행 횟수 | 적합한 상황 |
|---|---|---|---|
| `for` | 실행 전 | 0회 | 반복 횟수가 명확할 때 |
| `while` | 실행 전 | 0회 | 횟수 모르고 조건만 있을 때 |
| `do...while` | 실행 후 | 1회 | 최소 한 번은 실행해야 할 때 |

- while은 조건이 참인 동안 반복 (조건을 만족할 때까지가 아님)
- `for(;;)`처럼 모든 부분 생략 시 무한 루프

```js
// 결제 승인 상태를 최소 1회 조회, 대기 중이면 재조회
let status;
do {
  status = checkPaymentStatus();
} while (status === 'PENDING');
```

## 5. break와 continue

- break 탈출 대상은 반복문, switch, 레이블 문 세 가지뿐
- if는 break 탈출 대상 아님
    - 반복문 밖 if 안에서 break 사용 시 SyntaxError
    - 반복문 안 if 안에서 break 사용 시 if가 아니라 반복문 전체 탈출
- continue는 현재 반복의 나머지를 건너뛰고 다음 반복으로 이동
- 레이블 문으로 중첩 반복문 한 번에 탈출 가능, 가독성 문제로 비권장

```js
if (true) {
  break; // SyntaxError
}

for (let i = 0; i < 5; i++) {
  if (i === 2) break; // for 전체 탈출
  console.log(i);     // 0, 1
}
```

```js
// 중첩 if
for (const item of cart) {
  if (item.inStock) {
    if (!item.isGift) {
      total += item.price;
    }
  }
}

// 개선: continue로 제외 조건 먼저 처리 (가드 패턴)
for (const item of cart) {
  if (!item.inStock || item.isGift) continue;
  total += item.price;
}
```

## 6. 고차 함수

### 개념

- 함수를 인자로 받거나 함수를 반환하는 함수
- 인자로 넘기는 함수를 콜백 함수라고 부름
- 배열의 대표 고차 함수: `forEach`, `map`, `filter`, `reduce`, `find`, `some`, `every`
- 반복 처리 방식(어떻게)은 고차 함수가 담당, 개발자는 할 일(무엇을)만 콜백으로 전달

```js
const prices = [1000, 2000, 3000];

// for: 인덱스 관리, 빈 배열 준비, push까지 직접 작성
const discounted = [];
for (let i = 0; i < prices.length; i++) {
  discounted.push(prices[i] * 0.9);
}

// map: 각 요소를 어떻게 바꿀지만 작성
const discounted = prices.map((price) => price * 0.9);
// [900, 1800, 2700]
```

### 자주 쓰는 고차 함수

| 메서드 | 역할 | 반환값 | 중간 중단 |
|---|---|---|---|
| `forEach` | 각 요소에 작업 실행 | undefined | 불가 |
| `map` | 각 요소 변환 | 새 배열 | 불가 |
| `filter` | 조건 맞는 요소만 추출 | 새 배열 | 불가 |
| `reduce` | 요소를 하나의 값으로 누적 | 누적 결과 | 불가 |
| `find` | 조건 맞는 첫 요소 탐색 | 요소 또는 undefined | 찾으면 중단 |
| `some` | 조건 맞는 요소 존재 여부 | 불리언 | 찾으면 중단 |
| `every` | 모든 요소가 조건 만족 여부 | 불리언 | 불만족 시 중단 |

### 제어문 대신 고차 함수를 권장하는 이유

- 선언적 코드: 인덱스, 증감 같은 절차 대신 의도만 드러남
- 부수 효과 감소: `map`, `filter`는 원본 변경 없이 새 배열 반환
    - React state 불변성 유지에 유리
- 조합 용이: `filter → map → reduce` 체이닝 가능

```js
// 재고 있는 상품의 결제 금액 합계
const total = cart
  .filter((item) => item.inStock)
  .map((item) => item.price * item.quantity)
  .reduce((sum, price) => sum + price, 0);
```

### 트레이드오프

- 성능은 고차 함수가 더 좋지 않음
    - 요소마다 콜백 호출 비용 발생, for문이 같거나 약간 유리
    - 일반적인 UI 코드에서는 체감 차이 미미
- 중간 중단 필요 시 for 계열이 더 명확

### forEach 중단 관련 주의점

- forEach는 break 사용 불가
- forEach 콜백 안의 return은 현재 콜백만 종료, 반복은 계속 진행

```js
[1, 2, 3].forEach((n) => {
  if (n === 2) return; // 2만 건너뜀, 중단 아님
  console.log(n);      // 1, 3
});
```

| 목적 | 대안 |
|---|---|
| 조건 맞는 요소 찾기 | `find` |
| 존재 여부만 확인 | `some` |
| 중단 후 추가 작업 필요 | `for...of` + `break` |
